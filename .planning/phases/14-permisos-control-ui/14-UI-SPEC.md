## Spacing Scale

MUI theme uses `spacing: (factor) => ${0.25 * factor}rem` — meaning `theme.spacing(1) = 4px`. All spacing values below map to this scale.

| Token | Value | MUI spacing() | Usage |
|-------|-------|---------------|-------|
| xs | 4px | spacing(1) | Icon gaps, inline checkbox padding |
| sm | 8px | spacing(2) | Compact element spacing, gap between icon + label |
| md | 16px | spacing(4) | Default element spacing, card inner padding |
| lg | 24px | spacing(6) | Section padding, drawer inner padding (p: 3) |
| xl | 32px | spacing(8) | Layout gaps between cards |
| 2xl | 48px | spacing(12) | Major section breaks |
| 3xl | 64px | spacing(16) | Page-level top/bottom spacing |

Exceptions:
- Drawer width: 600px (matches existing RolePermissionsDrawer and UserPermissionsDrawer — do not change)
- Drawer header padding: `p: 3, pb: 2` (matches existing pattern)
- Touch targets for CRUD action checkboxes: minimum 40px height per row
- Avatar in drawer header: 56×56px (existing pattern, do not change)

## Layout & Interaction Patterns

### Permissions Management Page (`/usuarios` → Roles tab)

**Pattern:** Existing `RoleCards` grid (3-column MUI Grid) remains. Each card gains:
- Bottom summary strip: `{N} funciones — {full_count} completos / {partial_count} parciales`
- Icon button `tabler:shield-lock` opens `RolePermissionsDrawer` (existing trigger, no change)

### RolePermissionsDrawer — Extended CRUD Mode

**Width:** 600px (unchanged)
**Header:** unchanged gradient pattern
**Body change:** For each Function row, replace single `Checkbox` with `CrudActionRow`:

```
[ App Card — left border color ]
  [ Module TreeItem ]
    [ Function row ]
      [ fn name ]  [ C ][ R ][ U ][ D ]
```

- `CrudActionRow` chips: use `Chip size="small"` with `variant="filled"` when action enabled, `variant="outlined"` when disabled
- Clicking a chip toggles that specific action for that function
- Module-level checkbox: checks/unchecks all 4 actions for all functions in module
- App-level checkbox: checks/unchecks all 4 actions for all functions in app
- Indeterminate state: shown when some but not all actions are checked

### UserPermissionsDrawer — Override Indicators

Same CRUD toggle pattern as role drawer, plus:
- Each `CrudActionRow` chip shows tooltip: "Hereda del rol [RoleName]" if same as role default
- If user override differs from role: chip border changes to `warning.main` (#FF9F43) with tooltip "Sobreescrito manualmente"
- Inherited (no override): normal chip appearance
- Reset button per Function: `tabler:refresh` icon button restores function to role defaults

### UnauthorizedPage

Full page centered layout:
- Icon: `tabler:shield-off` at 64px, color `error.main`
- Heading: `h4` variant, "Sin Autorización"
- Body: `body1`, "No tenés permiso para acceder a esta sección."
- CTA Button: `variant="contained" color="primary"` — "Volver al inicio" → navigates to `/`
- Positioned at: registered as `src/pages/401.tsx`

### Menu Hiding (Navigation)

- Nav items gate: `CanViewNavLink` / `CanViewNavGroup` already exist — wire to new granular CASL ability
- Hidden items: not rendered (not visible, not `display: none`) — prevents DOM leaking
- Gerente scope: only sees items within their branch's permitted functions

## Destructive Actions

| Action | Trigger | Confirmation Pattern |
|--------|---------|---------------------|
| Reset user overrides to role defaults | "Restablecer" icon button in UserPermissionsDrawer footer | `ConfirmDialog` (existing component): heading "Restablecer Permisos", body copy above, confirm="Sí, restablecer" (color="error"), cancel="Cancelar" |
| Remove all permissions from a role | Only via superadmin — uncheck all at app level | No separate confirm dialog — the drawer's existing "Guardar" flow covers this. The indeterminate/unchecked state is visually explicit before save. |

No inline delete actions. No hard-delete of permissions data — only updates to boolean flags.

## Accessibility

- All `Checkbox` components retain MUI default ARIA attributes
- `CrudActionRow` chips: `aria-label="Acción {CREATE|READ|UPDATE|DELETE} — {habilitado|deshabilitado}"` on each chip
- `UnauthorizedPage`: `role="alert"` on the container
- Drawer: `aria-label="Permisos de {roleName/userName}"` on the Drawer root
- TreeView items: existing `nodeId` scheme retained (`app-{id}`, `mod-{id}`, `fn-{id}`)
- Focus management: when Drawer opens, first focusable element is the close (X) button
