`api-ventago/scripts/diagnose-image-names.js` 를 새로 만든다. **읽기 전용**이다 —
`putObject` · `removeObject` · `UPDATE` · `INSERT` 를 쓰지 않는다.

입력: stdin 으로 `id<TAB>image_url` 줄들을 받는다(DB 접근을 스크립트 밖으로 뺀다 —
운영/로컬 어느 쪽에서 뽑았는지가 호출부에 드러나야 한다).

동작: 각 `image_url` 에 대해 **세 가지 키 후보**를 MinIO 에 `statObject` 로 물어본다.

```js
const raw  = name;                                          // DB 에 있는 그대로
const fix  = Buffer.from(name, 'latin1').toString('utf8');   // 모지바케를 되돌린 형태
const brk  = Buffer.from(name, 'utf8').toString('latin1');   // 반대 방향(혹시 DB 가 멀쩡한 경우)
```

각 상품을 정확히 하나의 버킷으로 분류한다:

| 분류 | 조건 | 무엇을 뜻하는가 |
|---|---|---|
| `ascii_ok`   | `/^[\x20-\x7E]*$/.test(raw)` 이고 raw 존재 | 정상 (대조군) |
| `raw_hit`    | raw 가 비ASCII 인데 raw 키가 **존재** | ⓑ 업로드가 깨진 이름 그대로 저장했다 → 404 의 원인은 **조립/전송 인코딩**(경로 4/5) |
| `fix_hit`    | raw 는 없는데 `fix` 키가 **존재** | ⓒ **DB 문자열만 깨졌다** → 데이터 정정으로 해결 가능 |
| `brk_hit`    | raw 는 없는데 `brk` 키가 **존재** | 반대 방향으로 깨졌다 |
| `missing`    | 셋 다 없음 | ⓐ **객체 자체가 없다** → 이름 고쳐도 사진은 안 돌아온다 |

출력(마지막에 요약 한 블록, JSON 아님 — 사람이 읽는다):
```
총 N건 / ascii_ok A / raw_hit B / fix_hit C / brk_hit D / missing E
판정: <A|B|C 중 하나>
```
그리고 각 분류의 **예시 3건씩**(id + 세 후보 키)을 출력한다 — 숫자만으로는 반증할 수 없다.

★ 대조군을 반드시 출력한다: `ascii_ok` 중 3건도 `statObject` 를 실제로 거쳐 「존재」로
  찍혀야 한다. **ascii_ok 가 전부 「없음」으로 나오면 스크립트가 버킷을 못 보고 있는 것**이지
  데이터 문제가 아니다 — 그 경우 종료코드 2 로 죽고 「버킷 연결 실패」라고 말한다.
  (대조군 없는 검사는 검사가 아니다.)

★ `statObject` 는 순차로 부르되 동시 8개로 제한한다(운영 MinIO 에 부담을 주지 않는다).

스크립트 맨 위에 주석으로 **무엇을 세는가 / 왜 세 후보인가 / 이것이 고치는 스크립트가
아니라는 것**을 적는다.
