**`prices` 현재 스키마 (로컬 5432 `information_schema` 실측):**
```
id           integer          NOT NULL
product_id   integer          NULL      ← ★ nullable
price_type_id integer         NULL      ← ★ nullable
amount       double precision NULL
currency     varchar          NULL
created_at   timestamptz      NOT NULL
updated_at   timestamptz      NOT NULL
```
**현재 인덱스:** `prices_pkey` · `idx_prices_price_type_id` ·
`idx_prices_product_price_type` — 뒤의 것 정의:
```sql
CREATE INDEX idx_prices_product_price_type ON public.prices USING btree (product_id, price_type_id)
```
★ **non-unique** 다. 이것이 `upsertPrices` 주석이 말하는 그것이다.
★ 두 컬럼이 **nullable** 이라 기본 UNIQUE 는 NULL 을 서로 다른 값으로 본다 →
  `NULLS NOT DISTINCT`(PG15+, 로컬·운영 모두 **PG18**)가 필요하다.

**고칠 주석 — `productsPrice.service.ts:149-158` (현재 원문):**
```typescript
/**
 * prices 배치 업서트 — (a) 기존 행 1회 조회 → (b) 쓰기 2회.
 *
 * ★ `updateOnDuplicate` 의 ON CONFLICT 대상은 prices 의 PK(id) 다.
 *   (product_id, price_type_id) 에는 UNIQUE 제약이 없어(idx_prices_product_price_type
 *   는 non-unique) conflict target 이 될 수 없다. 따라서 기존 행은 **id 를 실어**
 *   보내 갱신하고, 신규 행만 따로 INSERT 한다. id 없이 updateOnDuplicate 를 쓰면
 *   충돌이 아예 안 나 중복 행이 쌓인다.
 */
```
★ 이 주석을 **반드시 함께 고친다.** 안 고치면 거짓이 되어 다음 사람을 속인다.

**현재 구현 (`:159-216`):** `findAll` 로 기존 id 를 모으고 → `toUpdate`(id 포함,
`updateOnDuplicate: ['amount','updatedAt']`) + `toInsert` 두 번 `bulkCreate`.
호출부는 `bulkUpdateBaseAndTypes`(:275) 와 `bulkUpdateExplicit` 이며 **둘 다
트랜잭션 안**에서 `transaction` 을 넘긴다.

**마이그레이션 규약 spec** (`migration-conventions.spec.ts`, 컷오프 2026-08-21):
- 기존 테이블 인덱스는 **`CONCURRENTLY` 필수** — `prices` 는 기존 테이블이다
- 기존 테이블 `ALTER` 가 있는 파일은 `lock_timeout` 필요 (이 파일엔 ALTER 가 없다)
- ★ `CONCURRENTLY` 는 **트랜잭션 안에서 못 쓴다** → `BEGIN/COMMIT` 를 넣지 않고,
  적용할 때 `--single-transaction` 을 **붙이지 않는다**

**Sequelize `ON CONFLICT` 문법:** `bulkCreate(rows, { updateOnDuplicate, conflictAttributes })`
— `conflictAttributes` 가 conflict target 을 PK 대신 지정한다. **먼저 설치된
sequelize 버전에서 이 옵션이 지원되는지 확인할 것**(`node -e "console.log(require('sequelize/package.json').version)"`).
지원하지 않으면 `this.sequelize.query()` 로 `INSERT ... ON CONFLICT (product_id, price_type_id) DO UPDATE SET amount = EXCLUDED.amount, updated_at = now()` 를 직접 쓴다
(같은 `transaction` 을 반드시 넘긴다 — 빠뜨리면 별도 커넥션에서 커밋돼 부분 저장이 된다).
