# Plan 10-02: AFIP Relay Client + 발행 서비스 (afip-connector 포팅)

**Phase:** 10-facturacion-electronica
**Status:** Not started
**Depends on:** Plan 10-01
**Estimate:** 2일

## Goal

기존 Java `afip-connector` 의 핵심 로직(CoolsistemaConnector + AfipService.processInvoice)을 NestJS 로 포팅해 Sale → CAE 발행 파이프라인을 구현한다.

## Scope (In)

### 상수/DTO 포팅 (Java → TypeScript)
- `api-ventago/src/app/facturacion/constants/afip.constants.ts`:
  - `InvoiceType` enum (A=1, B=6, C=11, M=51, E=19, NCA=3, NCB=8, NCC=13)
  - `IVA` enum (NATIONAL=5 @21%, EXEMPT, CLIENT_EXTERIOR)
  - `DocumentType` enum (CUIT=80, DNI=96, CF=99)
  - `ProductType` enum (PRODUCT=1, SERVICE=2, BOTH=3)
  - `Currency` enum (PES, DOL)
- `api-ventago/src/app/facturacion/dto/afip-voucher-request.dto.ts`:
  - `AfipVoucherRequestDto` (point, type, productType, documentType, dni, amount, iva, ivaType, creditNote, asoc)
  - `AfipCaeResponseDto` (cae, caeVencimiento, afipNumber, error)
  - `AssociatedVoucherDto`

### AFIP Relay Client
- `api-ventago/src/app/facturacion/relay/afip-relay.service.ts`:
  - Axios 인스턴스 (timeout 10s, keep-alive agent 공유)
  - `createVoucher(request, {prod, clientId, cuit})` → `POST /api/invoice?prod=&client=&cuit=`
  - `getStatus()` → `GET /api/afip/status` (헬스체크, 관리자 화면용)
  - `getLastVoucher(pto, invoiceType)` → `GET /api/afip/last/{pto}/{type}` (마지막 번호 조회)
  - **retry 로직**: 3회 지수백오프 (500ms, 1s, 2s), 네트워크 에러만 재시도
  - 응답 파싱 + 에러 매핑 → `AfipRelayException`
- URL 상수는 환경변수 (`AFIP_RELAY_BASE_URL=https://invoice.coolsistema.com/api`)

### 발행 서비스 (핵심 로직)
- `api-ventago/src/app/facturacion/facturacion.service.ts`:
  - `emitInvoiceFromSale(saleId, options)`:
    1. Sale 조회 + Store.fiscalConfig + SaleItems eager load
    2. 중복 발행 차단 — `sale.invoiceId IS NULL` 어드바이저리 락
    3. 판매 → `AfipVoucherRequest` 매핑 (아래 규칙)
    4. `Invoice` row 생성 (status='PENDIENTE')
    5. `afipRelayService.createVoucher()` 호출
    6. 응답 CAE → Invoice 업데이트 (status='OK', cae, caeVencimiento, numero)
    7. Sale.invoiceId + Sale.status='FACTURADO' 업데이트
    8. 단일 트랜잭션 + rollback 안전
  - `emitManualInvoice(dto)`: Sale 없이 수동 발행 (debug/수정용)
  - `cancelInvoice(invoiceId)`: status='CANCELADO' (실제 AFIP 취소는 Nota de Crédito 발행, 별도 함수)
  - `emitCreditNote(originalInvoiceId, reason)`: NC 발행 (type=original+3, asoc 세팅)

### Sale → AfipVoucherRequest 매핑 규칙 (Java AfipService.processInvoice 에서 포팅)
```typescript
// resiva 대신 Ventago의 StoreClient.condIva 사용
let iva: IVA;
if (client.condIva === 'EXENTO') iva = IVA.EXEMPT;
else if (client.condIva === 'EXTERIOR') iva = IVA.CLIENT_EXTERIOR;
else iva = IVA.NATIONAL;

// 발행자 condIva + 상대 condIva 로 InvoiceType 결정
let invoiceType: InvoiceType;
if (store.fiscalConfig.condIva === 'RI') {
  if (client.condIva === 'RI') invoiceType = InvoiceType.INVOICE_A;
  else if (client.condIva === 'EXTERIOR') invoiceType = InvoiceType.INVOICE_E;
  else if (client.condIva === 'EXENTO') invoiceType = InvoiceType.INVOICE_A;
  else invoiceType = InvoiceType.INVOICE_B;
  // M 전환: store.fiscalConfig.invoiceTypeDefault === 'M'
  if (invoiceType === InvoiceType.INVOICE_A && store.fiscalConfig.invoiceTypeDefault === 'M') {
    invoiceType = InvoiceType.INVOICE_M;
  }
} else if (store.fiscalConfig.condIva === 'MONOTRIBUTO') {
  invoiceType = InvoiceType.INVOICE_C;
}

// 금액 계산 (Decimal.js 필수)
const total = new Decimal(sale.total);
const neto = total.div(iva.base);          // iva.base = 1.21 for NATIONAL
const impuesto = total.minus(neto).toDP(2, Decimal.ROUND_DOWN);

// DocumentType 결정
let docType: DocumentType;
if (client.condIva === 'RI' || client.condIva === 'MONOTRIBUTO') docType = DocumentType.CUIT;
else if (client.cuit || client.dni) docType = DocumentType.DNI;
else docType = DocumentType.CF;  // Consumidor final sin identificar
```

## Risks

- **릴레이 인증**: client/cuit 파라미터 외 추가 헤더 인증 필요한지 확인 필요 (원본 코드에서는 없음)
- **타임존**: AR 시간 vs store timezone 불일치 → AFIP은 fecha 필수
- **동시 발행 경합**: 같은 sale 에 대한 동시 두 요청 → DB unique + 락
- **Decimal 정밀도**: JS Number 금지, decimal.js 도입
- **쿠폰/할인**: sale.total 에 할인 포함 여부 확인 → AFIP에는 최종 금액만 전달
