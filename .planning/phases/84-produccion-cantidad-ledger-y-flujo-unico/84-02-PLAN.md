<objective>
로트의 상태를 **셋으로 가른다**. 지금은 `status` 한 칸에 세 생명주기가 들어 있어
"3공정 다 끝났는데 IN_PROGRESS" 같은 모순이 계속 생긴다.
</objective>

<constraints>
- ★ **"마지막 공정 완료 = 로트 COMPLETED" 로 바로 바꾸면 안 된다** (CODEX). 그러면 재고 PENDING 을
  숨긴다. 생산이 끝난 것과 재고에 들어간 것은 **다른 사실**이다.
- 기존 `status` 컬럼을 제거하지 않는다 — 읽는 화면이 여럿이다. 파생으로 유지하거나 병기한다.
- 상태는 **계산**한다. 저장하더라도 원천은 하위 사실(route step 종료 / posted / 불일치 0)이다.
</constraints>

<tasks>
1. 마이그레이션: `production_status` · `inventory_status` · `reconciliation_status` 추가.
2. 판정:
   - 모든 route step 종료 → `production_status = COMPLETED`
   - 최종 실적 격자 게시 성공 → `inventory_status = POSTED`
   - 설명되지 않은 수량 차이 0 → `reconciliation_status = BALANCED`
   ★ `CANCELLED` 만 있는 로트를 COMPLETED 로 판정하지 않는다(기존 결함 D3).
3. 화면 문구는 셋을 합쳐 **다음 행동**으로 보여준다: "생산 완료 · 재고 입고 필요".
4. 기존 `status` 와의 대응표를 코드 주석 한 곳에 명시(두 곳이 들고 있으면 갈라진다).
</tasks>
