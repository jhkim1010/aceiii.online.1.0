<objective>
Phase 12의 인프라 Wave. 보고서 셸의 레이아웃 시스템을 통일된 Cockpit 패턴으로 재구성한다.

**구현 항목:**

1. **56px 단일 Topbar 통합** (`ReportsTopbar.tsx`)
   - 좌측: 제목 블록(breadcrumb + title, 세로 구분선)
   - 중앙: filterSchema 기반 자동 렌더 필드 (Sucursal select / Search input / RangeDate chip 2개)
   - 우측: 액션 그룹 (★ Favorito / 📊 Excel / 📄 PDF / ▶ Ejecutar)
   - 모든 필드 36px 높이, gap 8px, 회색 배경 outlined
   - 참조: `reports-topbar-mockup.html`

2. **filterSchema 시스템** (`registry.ts` + `ReportsFilterFields.tsx`)
   - `ReportEntry`에 `filterSchema?: FilterField[]` 추가
   - `FilterField = 'sucursal' | 'search' | 'rangeDate' | 'category' | 'paymentMethod'`
   - `<ReportsFilterFields slug={slug} />`가 schema를 읽고 자동으로 필드 렌더
   - 필드 값은 Redux `reportsV2.currentParams`에 단일화

3. **CockpitLayout 컴포넌트** (`CockpitLayout.tsx`)
   - props: `kpis`, `primary`, `detail`, `drawer`, `primaryHeight?`
   - 구조: KPI Strip (80px) → Primary Area (resizable) → resize handle → Detail Area (flex:1)
   - Drawer는 fixed right, slide 애니메이션, 380px
   - resize는 localStorage에 비율 저장
   - 모든 보고서 Body가 이 컴포넌트를 사용하도록 표준화

4. **Redux currentParams 슬라이스 확장** (`store/apps/reports-v2/index.ts`)
   - `currentParams: Record<string, any>` 추가
   - `setCurrentParams(slug, params)` action
   - 보고서 변경 시 해당 slug의 defaultParams로 reset

**Wave 1 범위:** 인프라만. 실제 보고서 본문 구현은 Wave 2부터.

**참조 목업:**
- `reports-topbar-mockup.html` (56px Topbar)
- `vendor-cockpit-mockup.html` (CockpitLayout 전체 구조 — Wave 2에서 사용)

**Pool 영향:** 없음 (프론트엔드만). 단, 향후 Wave 8의 통합 API를 위한 params 단일화가 이 Wave의 부수 효과.
