<objective>
Phase 12의 마지막 Wave. Pool과 성능을 측정·최적화하고 회귀를 검증한다.

**구현 항목:**

1. **API 최종 통합 검증**
   - 16개 보고서 service에 `getXxxCockpit(params)` 메소드가 모두 존재하는지 점검
   - 각 메소드가 단일 sequelize.query 호출만 하는지 확인 (N+1 검사)
   - 누락된 곳은 raw SQL CTE로 통합

2. **프론트 캐시 훅** (`useCockpitCache.ts`)
   - key: `slug + JSON.stringify(params)`
   - TTL 5분
   - Map 기반 in-memory cache (LRU 64 entries)
   - 모든 useXxxReport 훅이 이 캐시를 통해 fetch하도록 wrapping
   - 동일 보고서·동일 필터 재방문 시 API 호출 0

3. **Pool 사용량 측정 (운영 안전 우선)**
   - 측정 스크립트: `scripts/measure-cockpit-pool.sh`
     - `pg_stat_activity`에서 ventago DB 연결 수를 1초마다 30회 샘플링
     - 50개 동시 cockpit 호출 시뮬레이션 (artillery 또는 hey)
     - peak/avg/min을 콘솔 출력
   - 기준: peak ≤ 기존 (Phase 8) 측정값
   - 초과 시 raw SQL 인덱스 검토 + EXPLAIN ANALYZE

4. **운영 배포 안전 절차**
   - 마지막 Jenkins 빌드 로그 (`#NNN.txt`) 확인
   - 빌드 그린 확인 후 staging 배포
   - 24시간 모니터링 후 prod 배포
   - 롤백 플랜: Phase 8 셸은 그대로 유지하므로 `/reportes-v2`만 비활성화하면 즉시 롤백 가능

5. **문서화**
   - `docs/superpowers/specs/2026-04-XX-cockpit-pattern.md` 작성
   - 향후 신규 보고서 추가 시 따를 표준 패턴 설명
   - "단일 통합 엔드포인트" 원칙 명시

**완료 기준:**
