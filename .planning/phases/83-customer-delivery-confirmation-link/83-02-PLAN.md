<objective>
고객 확인 페이지와 통지 흐름을 만든다.
</objective>

<constraints>
- ★ **직원 확인을 고객 OK 에 걸지 않는다.** 직원이 누르면 그 자리에서 종결된다.
  고객에게는 *"등록했습니다. 아니면 알려주세요"* 만 보낸다 — 침묵 = 동의.
- 공개 페이지는 **모바일 우선**, 로그인 없음, 탭 한 번. 개인정보는 최소로.
- WhatsApp 발송은 기존 흐름을 재사용한다(`PartialInvoiceModal` 에 이미 있다).
- 분쟁은 **조용히 쌓이면 안 된다** — Despacho 보드 상단과 Phase 82 보고서 양쪽에 뜬다.
</constraints>

<tasks>
1. `/entrega/[token]` 공개 페이지 — 주문번호·발송일·운송사 표시,
   버튼 2개: **`Sí, lo recibí`** / **`No lo recibí`**(사유 선택). 확인 후 감사 화면.
2. 발송 시 고객에게 링크 발송(WhatsApp). 문구에 **추적 코드**도 함께.
3. 직원 확인 시 통지 발송(선택) — *"Registramos la entrega el DD/MM. Si no lo recibiste, avisanos."*
4. `En disputa` 를 Despacho 보드에 별도 열/배지로.
</tasks>

<verification>
- 모바일에서 링크 → 탭 1회로 확인 완료
- 직원 확인 후에도 주문이 즉시 종결된다(고객 응답 대기 없음)
- 분쟁 등록 시 보드와 보고서 양쪽에 나타난다
</verification>

<success-criteria>
- 확인율이 오른다(고객 확인 비중이 측정된다)
- 대행이 막다른 골목이 되지 않는다
</success-criteria>
