<objective>
배달 확인의 **출처와 시점**을 기록할 수 있게 만든다.

Purpose: 지금은 `delivered_at` 하나에 "도착했다고 보는 날" 과 "누가 누른 시각" 이 뭉쳐 있다.
직원이 5일 늦게 누르면 그 늦음이 그대로 배송 지연으로 기록된다.
</objective>

<constraints>
- ★ **`delivered_at` 의 기존 의미를 바꾸지 않는다** — 리포트·화면이 이미 읽는다.
  새 컬럼을 더하고, 기존 값은 그대로 둔다(소급 수정 금지).
- 토큰은 **추측 불가능**해야 한다(주문번호·id 기반 금지). 만료를 둔다.
- 공개 엔드포인트는 **인증 없이** 열린다 → 토큰 하나로 **그 주문만** 보이게. 열거 공격 방어(레이트 리밋).
- ★ **자동 확인을 만들지 않는다** — 레거시 폴백 경로가 매출·외상을 만든다(FINDINGS).
</constraints>

<tasks>
1. 마이그레이션(운영·로컬 양쪽):
   - `online_orders.delivered_confirmed_by` varchar(16) NULL — 'customer' | 'staff'
   - `online_orders.delivered_confirmed_at` timestamptz NULL — 클릭 시각
   - `online_orders.delivery_dispute_at` timestamptz NULL + `delivery_dispute_note` varchar(500)
   - `online_orders.confirm_token` varchar(64) NULL + `confirm_token_expires_at` timestamptz
   - 부분 UNIQUE 인덱스(`confirm_token` NOT NULL)
2. `deliverOrder(..., { deliveredOn?, confirmedBy })` — 도착일 지정 허용(미래·발송 이전 거부),
   `delivered_confirmed_by/at` 기록.
3. 토큰 발급(발송 시) + 공개 확인 엔드포인트:
   - `GET /public/entrega/:token` — 주문 요약(최소 정보: 번호·날짜·상태). **금액·고객 개인정보 최소화**
   - `POST /public/entrega/:token/confirmar` — 고객 확인
   - `POST /public/entrega/:token/no-recibido` — 분쟁 등록
   레이트 리밋 + 만료 + 이미 확정된 주문 재확인 무시(멱등).
4. 분쟁 상태를 Despacho 보드·Phase 82 보고서가 읽을 수 있게 노출.
</tasks>

<verification>
- 직원이 도착일을 3일 전으로 지정 → `delivered_at`=3일 전, `delivered_confirmed_at`=지금
- 잘못된/만료 토큰 → 404(존재 여부를 흘리지 않는다)
- 같은 토큰으로 두 번 확인 → 원장·상태 변화 없음(멱등)
- 자동 확인 경로가 **없다**(코드 검색으로 확인)
</verification>

- 확인의 출처가 남는다
