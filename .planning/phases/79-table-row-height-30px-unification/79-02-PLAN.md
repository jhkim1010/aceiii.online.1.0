<objective>
MUI `<Table>` 계열(96개 파일)의 행 높이를 **테마 override 한 곳**에서 30px 로 맞춘다.

Purpose: 이 계열에는 `FullTable` 같은 래퍼가 없다. 파일 96개를 개별 수정하면 다음 밀도 변경 요청 때
**같은 작업을 다시 96번** 하게 된다. 테마가 유일한 지렛대다(79-FINDINGS F1).
</objective>

<constraints>
- **`sizeSmall` / `paddingCheckbox` / `paddingNone` 셀은 현재 규칙에서 제외돼 있다**(F4).
  이미 dense 로 쓰는 표가 있다는 뜻이다 — 그 셀렉터를 건드려 **그쪽이 더 작아지게 만들지 않는다.**
- 헤더(`MuiTableHead`) 패딩은 건드리지 않는다 — 이번 범위는 본문 행이다.
- `MuiTableRow` 의 좌우 패딩(`paddingLeft/Right: spacing(6)`)은 **가로** 여백이라 무관하다. 손대지 않는다.
- 폰트 크기는 줄이지 않는다(ROADMAP 범위 밖). 높이는 **패딩으로만** 만든다.
</constraints>

<tasks>
1. `src/@core/theme/overrides/table.ts` 의 `MuiTableBody` → `.MuiTableCell-body` 패딩을 줄인다.
   현재 `theme.spacing(3.5)`(= 14px, `spacing = 4px × factor`) → **`theme.spacing(1.25)`(5px)**.
   계산: 5 + 5 + 본문 20px + 경계선 1px ≈ **31px**. 실측이 31px 로 나오면 `spacing(1)`(4px, 29px)과
   비교해 **30 에 더 가까운 쪽**을 택하고, 고른 이유를 주석 한 줄로 남긴다.

2. 목표값이 AG Grid 계열과 갈라지지 않도록 `table-density.ts` 의 `TABLE_ROW_HEIGHT` 를
   **주석으로 참조**한다(테마에서 px 를 직접 계산해 쓰더라도, 어떤 목표에서 나온 값인지 남긴다).
   ★ 두 계열이 서로 다른 숫자로 조용히 갈라지는 것이 이 phase 가 없애려는 상태 그 자체다.

3. 실제 렌더 높이를 브라우저 개발자도구로 잰다 — 계산이 아니라 **측정값**으로 확정한다.
   `<tr>` 의 offsetHeight 가 30±1px 인지 확인.

4. dense 로 이미 쓰던 표(있다면)의 높이가 **변하지 않았는지** 확인한다.
   `grep -rn "size=\"small\"" ventago-app/src --include=*.tsx | grep -i table` 로 후보를 찾는다.
</tasks>

<verification>
