    - No user value ever appears: the functions only embed the placeholder strings they receive (spec passes sentinel placeholders and asserts nothing else variable is embedded).
    - itemsAggCte pre-aggregates sale_items per sale (fan-out guard): units=SUM(quantity), items_total=SUM(subtotal), costo=SUM(quantity*unit_cost) FILTER (unit_cost IS NOT NULL), venta_con_costo=SUM(subtotal) FILTER (unit_cost IS NOT NULL), restricted to sale_id IN (SELECT sale_id FROM venta).
    - devolucionesLocalCte selects activity_type='devuelto' rows of the same store with ACCOUNTING_SALE_STATUSES, local day (same COALESCE as venta), branch = COALESCE(origin_branch_id, branch_id), monto = Ganancia/devolucionesFilasSql formula with store bound, unidades = SUM(sale_items.quantity), costo_devuelto = SUM(quantity*unit_cost) FILTER unit_cost not null.
    - Union of sources: no predicate on `source` anywhere (D-28); spec asserts the string 'source =' / "source IN" does not appear in the WHERE.
    - Local day itest: sale_date = 2026-09-11T02:30Z with store tz America/Argentina/Buenos_Aires → dia 2026-09-10 (BA); a row with sale_day_local NULL is still found on its BA day.
    - Exclusion itest: movido, devuelto, fallado rows (status 'Pagado', quantity > 0) contribute 0 rows to `venta`.
    - dpago itest: a sale with credit_payment_id set is excluded.
    - Reversal itest: 'Anulado' (+1000, day 1) and 'Anulación' (−1000, day 2) → both present, each on its own day with its own sgn.
    - Legacy itest: one source='legacy' and one source='pos' sale on the same day → both rows present; fuentesSql returns {legacy:1, pos:1}.
    - Tenant itest: two dummy stores with identical sales; running the CTE bound to store A returns only A's sale ids. Mutation control (documented in the spec header and executed once): removing the `s.store_id =` predicate makes the itest fail.
    - Duplicate monitor itest: a planted pair (legacy + pos, same store, same total, 60 s apart, identical item multiset) → monitor returns exactly 1 pair; control store without such pair → 0; a pair with same total but different items → 0.
