    - Injection control: strings like `'; DROP TABLE sales;--` in any id/preset/sort/dir field → rejected (DIMENSION_DESCONOCIDA / METRICA_DESCONOCIDA / TIPO_INVALIDO / ORDEN_INVALIDO); the normalized output never contains a raw user string that is not a catalog id (spec deep-scans output)

    Availability (D-19): groupBy or filter on a dimension with disponibilidad[d].disponible=false → DIMENSION_NO_DISPONIBLE with that motivoEs

    - groupBy dia with > diaMaxDias days → PERIODO_DIA_MUY_LARGO with fixes [«Ver por semana» patch groupBy semana, «Últimos 90 días» patch preset]; any other case > agregadoMaxDias → PERIODO_MUY_LARGO
    - producto without top → PRODUCTO_REQUIERE_TOP (fix top 20); producto×dia with > productoDiaMaxDias days → PRODUCTO_DIA_LIMITE; top outside 1..topMax → TOP_FUERA_DE_RANGO
    - compare 'anio_anterior' with > compararAnioMaxDias → COMPARAR_ANIO_LIMITE
    Combos and grain (D-10/D-30):
    - item-grain dim or filter together with medio_pago dim or mediosPago filter → COMBINACION_PROHIBIDA (no safe join)
    - metric bloqueadaCon matching the resolved grain/dimensions → METRICA_BLOQUEADA with motivoEs and a fix removing the metric: tickets/ticket_promedio × medio_pago; ticket_promedio × item grain; unidades/aur × pago; devoluciones with any dim outside soloConDimensiones or any filter other than sucursales
    - grano = 'pago' if medio_pago dim/filter, else 'item' if any item dim/filter, else 'cabecera'
    - devolucionesAtribuibles = grano 'cabecera' AND dims ⊂ {sucursal, time dims} AND filters ⊂ {sucursales}
    - sort.by must be a selected metric or dimension id, dir asc|desc → else ORDEN_INVALIDO

    - compare non-null → metricasEfectivas adds unidades, tickets, aur where not blocked for the grain; blocked ones go to omitidas with motivo; alineacion = alineacionComparacion(period, groupBy); comparacion = periodoComparacion(desde, hasta, compare, alineacion); normalized output carries hoy and alineacion — D-31/D-31a rules live only in period.ts; spec asserts with hoy 2026-10-17: ultimos_30_dias grouped by dia + periodo_anterior → 2026-08-14..2026-09-12; este_mes with no time dim → 2026-09-01..2026-09-17; este_mes grouped by dia → 2026-09-01..2026-09-17 (period type wins); ultimos_12_meses grouped by mes → 2024-10-18..2025-10-17
