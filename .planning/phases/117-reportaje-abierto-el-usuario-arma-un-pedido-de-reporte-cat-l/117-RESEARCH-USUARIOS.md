# Phase 117 — 매장 주인·관리자는 어떤 보고서를 원하나 (조사 종합, 2026-10-17)

원자료: `research/externo.md`(웹·경쟁 제품, 출처 URL 포함) · `research/interno.md`(운영 DB·로그·Pedidos, 읽기 전용, 개인정보 없음).
상태: **제안** — 아래 P-항목은 사용자 결정 후 CONTEXT 에 반영한다.

## 1. 한 줄 결론
기능 방향(지표+차원+비교+Top N+저장, 템플릿에서 시작)은 업계 표준(Shopify·Lightspeed·Odoo)과 같다. 그러나 **우리 매장들이 이 기능을 요청한 증거는 약하고**, 데이터가 비어 있는 차원(카테고리·시즌·색·원가)이 많아 **매장마다 쓸 수 있는 조합이 다르다.** 그래서 「작게, 매장 데이터에 맞춰, 템플릿 중심」으로 가야 한다.

## 2. 근거 요약

### 외부
- 의류 표준 지표: sell-through · weeks of supply · GMROI · markdown · AUR(평균 판매가) · 반품률 — 스타일·색·사이즈·주 단위로.
- POS 판매만으로 되는 것: 매출·수량·티켓·ticket promedio·UPT·결제수단·판매원·지점·talle/color 분포. 재고 필요: sell-through·품절 사이즈·재고 커버·재고 연령. 원가 필요: 마진·GMROI.
- Shopify 사용자 정의 보고서 = 우리 설계와 거의 동일(지표+차원+필터 기본 30일+비교+Top N+저장). 주 진입 경로 = **기본 보고서를 열어 고친 뒤 저장**.
- 반복되는 불편: 두 차원을 한 표로 못 봄(Square 품목×결제수단 등).
- 아르헨티나: CAME 는 실질(불변가격)·수량으로 발표. → **pesos 옆에 수량·티켓을 항상** 보이고 AUR 로 가격/수량 효과를 분리. IPC 보정은 2단계.
- Gastos/Facturación 은 판매와 **다른 원장** — 나란히 놓을 수는 있어도 같은 행에 섞을 수 없다. 모노트리부토 12개월 누적 vs 한도, Libro IVA Ventas, NC 내역, 발급 비율이 점주·회계사 관심사.

### 내부 (운영 실측)
- **Pedidos 42건 중 보고서 요청 0건.** Trello 카드 제목에 「Reportes de ventas: por período, sucursal, vendedor y producto」「Exportar a Excel」 정도.
- AI 채팅 16건 중 데이터 질문 1건.
- 14일 보고서 호출의 **77%가 Stock**. 판매 분석 화면은 화면당 사용자 1–6명. 엑셀 내보내기는 한 곳(판매 내보내기, Shaple 매일)만 쓰인다.
- **원가 입력률 0%**(Shaple·NOIX·Charo·ohmydenim·ACE) · Cache 0.4% · coolsistema 7.1% · Cielo 41.5% → 마진은 대부분 매장에서 의미 없음.
- 카테고리는 Shaple·Cache·Charo·ohmydenim 에서 전부 `NONE`, 색은 「Color Único」. 매장별로 쓸모 있는 차원이 다르다(NOIX=카테고리, Shaple=사이즈 35종, Cache=시즌, Cielo=색). **전 매장 공통으로 쓸 수 있는 것: 시간·상품·판매자·결제수단.**
- 판매자는 `sales.seller_id` 로(대부분 1–2 계정으로 판매 등록 → `user_id` 무의미). 결제수단 없는 티켓 4.7%(Shaple) → 「sin medio」 행 필요. 분할결제 ≤7.5%.
- 다지점 매장 4곳뿐. 최대 매장 하루 262티켓 → 계획한 한도는 넉넉하다.
- ⚠ **최근 30일 판매 중 레거시 임포트 4,657건 vs Ventago POS 1,028건.** Cache 는 같은 날 양쪽이 있다(중복 여부 미확인). 「판매」 공용 정의를 쓰기 전에 반드시 정해야 한다.
- Gastos: 6개 매장 기록(NOIX·Shaple 활발), 분류가 자유 입력이라 품질 낮음(「c」「e」). Facturación: Ventago 발급 30일 12건, 실제 발급 대부분은 레거시 `legacy_facturas`. 기존 화면엔 유형별(A/B/C/NC)·발급 비율·순액/IVA 없음(`afip_vouchers` 엔 컬럼 있음).

## 3. 제안 (사용자 결정 필요)

| # | 제안 | 이유 |
|---|---|---|
| **P1** | 「판매」 정의에 **레거시 임포트 판매를 포함**(중복 판정 규칙 먼저 실측) | 안 넣으면 대부분 매장의 최근 판매 80%가 빠진다 |
| **P2** | 카탈로그에 **보고서 유형 축**(Ventas · Gastos · Facturación)을 처음부터 두고, 1단계는 **Ventas**, 다음 **Gastos**, Facturación 은 레거시 발급 포함 후 | 원장이 달라 섞을 수 없다. Facturación 은 지금 넣으면 대부분 「0% 발급」 |
| **P3** | **매장 데이터에 맞춘 차원 잠금**: 값이 1개뿐이거나 전부 NONE 인 차원은 회색 + 이유(「이 매장은 카테고리가 입력되지 않았습니다」) | 매장마다 쓸모 있는 차원이 다르다 |
| **P4** | 마진은 admin 지표로 두되 **기본 템플릿에서 제외**, 원가 입력률을 항상 표시 | 원가 0% 매장이 대부분 |
| **P5** | 비교를 켜면 **수량·티켓·AUR 를 항상 함께** | 인플레이션 왜곡 |
| **P6** | 「sin vendedor」「sin medio de pago」 행, 결제수단 이름은 표시용으로 정리 | 실데이터 |
| **P7** | 1단계 템플릿 6~8개(아래) | 전 매장 공통 차원 중심 |
| **P8** | 무거운 구축 전에 **2~3개 매장(Shaple·NOIX·Cache·Cielo 중) 주인에게 목업을 보여 확인** | 요청 증거가 약하다 — 만들고 안 쓰이는 위험 |

### P7 템플릿 후보 (우선순위)
1. 일/월별 판매 + 전기 대비(수량·티켓 병기)
2. 이번 주/30일 베스트셀러(마드레 기준, 전체 합 대비 %)
3. 판매자별 판매(「sin vendedor」 포함)
4. 결제수단별 입금(금액만, 티켓 잠금)
5. 사이즈 × 색(데이터 있는 매장만, 사이즈 숫자순 — PEDIDO 40)
6. 지점 비교(다지점 매장만 노출)
7. 요일·시간대별 판매
8. 반품 내역 / 워스트셀러(판매 0 상품은 재고 필요 → 갭)

### 1단계 밖으로 확인된 갭
sell-through · 품절 사이즈 · 재고 커버/연령 · GMROI(재고·원가 필요) · 외상 잔액 · 예약 발송(메일) · 자연어 보고서 · IPC 실질화 · MercadoPago 정산 대사.
