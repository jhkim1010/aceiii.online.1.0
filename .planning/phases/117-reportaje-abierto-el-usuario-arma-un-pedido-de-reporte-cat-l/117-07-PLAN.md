  <files>api-ventago/src/app/reporte-medida/compiler.ts, api-ventago/src/app/reporte-medida/compiler.spec.ts</files>
  <behavior>
    Universe and binding:
    - every statement (principal/totales/fuentes/comparación) contains ventaHeaderCte with placeholders '$1::int','$2::text','$3::date','$4::date'; bind[0] === storeId, bind[1] === tz
    - filters compile to `= ANY($n::int[])` with bind arrays; branch filter on venta.branch_id; vendedores on seller_id; mediosPago on spm.payment_method_id; categorias/temporadas on the COALESCE key; colores/talles on leaf ids
    - injection control: compiling a normalized order whose numeric filter arrays contain values never inlines them (sql contains no digits from filter values beyond placeholders); ids/labels never come from the order
    Header grain (sucursal/tiempo/vendedor or none):
    - FROM venta LEFT JOIN items_agg (pre-aggregated) — spec asserts no `JOIN sale_items` at header grain outside itemsAggCte and no `JOIN sale_payment_methods`
    - venta_neta = SUM(total_amount) minus attributable devoluciones.monto when devolucionesAtribuibles (joined by the same group keys: branch_id / time bucket); otherwise no subtraction
    - tickets = SUM(sgn); ticket_promedio = SUM(venta)/NULLIF(SUM(sgn),0) computed in the final SELECT (never averaging averages); unidades = SUM(items_agg.units); aur = SUM(items_agg.items_total)/NULLIF(SUM(items_agg.units),0)
    - devoluciones metric = SUM(devoluciones.monto) by the same keys (header only)
    - margen = (SUM(venta_con_costo) − SUM(costo)) [− reintegros + costo_devuelto when devolucionesAtribuibles, Ganancia formula D-30]; margen_pct = margen/NULLIF(SUM(venta_con_costo),0); cobertura_costo = SUM(venta_con_costo)/NULLIF(SUM(items_total),0)
    Item grain (categoria/temporada/color/talle/producto as dim or filter):
    - venta JOIN sale_items si ON si.sale_id = venta.sale_id LEFT JOIN products p ON p.id = si.product_id AND p.store_id = $1::int LEFT JOIN products m ON m.id = p.parent_id AND m.store_id = $1::int
    - categoria key = CASE WHEN upper(trim(c.name)) IN ('NONE','GENERAL') THEN NULL ELSE c.id END with c joined on COALESCE(p.category_id, m.category_id) AND c.store_id = $1::int; same for temporada/seasons; color = p.color_id → colors (store-bound); talle = p.size_id → sizes (store-bound); producto key = COALESCE(p.parent_id, p.id), label = madre sku + ' ' + name, NULL product → «Sin producto (ítem libre)»
    - venta_neta = SUM(si.subtotal) (no devoluciones; label notes it); unidades = SUM(si.quantity); tickets = signed distinct: COUNT(DISTINCT sale_id) FILTER (sgn=1) − COUNT(DISTINCT sale_id) FILTER (sgn=−1); aur = SUM(subtotal)/NULLIF(SUM(quantity),0); margen line-level over unit_cost IS NOT NULL
    Payment grain (medio_pago dim or filter):
    - venta LEFT JOIN sale_payment_methods spm ON spm.sale_id = venta.sale_id; revenue = SUM(COALESCE(spm.amount, venta.total_amount)); key spm.payment_method_id (NULL → «Sin medio de pago»); label columns from payment_methods (pm.store_id = $1::int OR pm.store_id IS NULL): emit `medio_pago_label` = pm.title and `medio_pago_slug` = pm.slug raw; display normalization (D-22) is done in 117-09 post-process by `normalizarMedioPago`, NOT in SQL
    Dimensions:
    - D-31 support: semana_key and mes_key are the bucket START date as 'YYYY-MM-DD' text (to_char of the truncated date) so 117-09 can decide bucket completeness; comparison statements reuse the same SQL with pedido.comparacion dates in $3/$4 — the compiler never decides alignment (weekday vs calendar is chosen in period.ts per D-31a); spec: for a mes-grain order with calendar comparison the comparison bind holds exactly pedido.comparacion.desde/hasta and the SQL text is byte-identical to the principal
    - sucursal: venta.branch_id → branches (store-bound) label; dia: venta.dia; semana: date_trunc('week', venta.dia)::date; mes: date_trunc('month', venta.dia)::date; dia_semana: EXTRACT(ISODOW FROM venta.dia)::int with labels Lunes..Domingo; hora: venta.hora with label 'HH:00'; vendedor: venta.seller_id → "Sellers" (store-bound) name || ' ' || last_name, NULL → «Sin vendedor»
    Ordering/limit:
    - ORDER BY the sort alias (catalog id) + deterministic tie-break on the group keys; LIMIT (top ?? limite) + 1 where limite = LIMITES.pantallaMaxFilas or csvMaxFilas by modo (truncation detection)
    Totals/fuentes:
    - totales = same FROM/WHERE without GROUP BY/LIMIT, same metric expressions (non-additive correct)
    - fuentes = fuentesSql over the same universe (counts by source)
    Snapshots: one inline snapshot per grain × representative dimension (sucursal+mes, producto top 20, medio_pago) — accepted only together with 117-09 behavioural itests
  </behavior>

Spanish comments citing D-IDs and the fan-out rule.</implementation>
