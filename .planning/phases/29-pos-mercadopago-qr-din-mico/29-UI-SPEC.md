# Phase 29 — UI Design Contract

> Visual and interaction contract for Mercadopago QR Dinámico integration. Generated by gsd-ui-researcher from CONTEXT.md (D-A1..D-A4 LOCKED), RESEARCH.md, sketch-findings-ace-online skill (6 references LOCKED), and verified mockup `.planning/sketches/001-phase-29-mp-qr-suite/index.html`.

> **Scope:** 5 surfaces — (1) `configuracion/mercadopago` NEW page · (2) `PaymentSummaryModal` extension + QR side panel · (3) `nueva-venta` sandbox banner · (4) `control-de-caja` Caja MP row + transfer/detail modals · (5) `SalesDetailView` refund failure UX.

> **Stack reality:** Next.js 13 (Pages Router) + React 18 + MUI 5 (`@mui/material@5.12.2`) + Redux Toolkit + SWR + axios `apiConnector` + Spanish (Argentine) UI. shadcn NOT applicable — project uses MUI 5 exclusively. `qrcode.react@^4.2.0` is the ONE new frontend dep (verify Next 13 SSR compat in Wave 0).

## Typography

| Role | Size | Weight | Line Height | Font Family | Usage |
|------|------|--------|-------------|-------------|-------|
| Body | 15px (0.9375rem) | 400 | 1.5 | Roboto | Default body, alert text, table cells |
| Label / caption | 12px (0.75rem) | 500 | 1.4 | Roboto | Form labels, branch meta, history rows, chip text |
| Mono numeric | 15px (0.9375rem) | 600 | 1.4 | JetBrains Mono | Currency amounts, payment_id, timestamps, account ID — **ALL monetary numerics use mono** |

**Rules:**
- 4 sizes, 2 weights (400 + 600/700) — within design-quality budget
- Mono font is the SECOND font; reserved exclusively for: monetary amounts, payment_id, timestamps (`HH:mm:ss` countdown + history), account IDs, MP error codes inside `<code>` blocks
- Antialiased (`-webkit-font-smoothing: antialiased`) — matches print-agent / zebra-agent
- NO uppercase text-transform on body copy. Uppercase ONLY on chips ("VIRTUAL", "PRODUCCIÓN", "SANDBOX MERCADOPAGO ACTIVO") with `letterSpacing: 0.04em`

## Interaction Contract

### Surface 2 — PaymentSummaryModal QR flow (state machine)

```
idle → user picks "Mercadopago QR" → enters amount
        ↓
generating (POST /api/mercadopago/qr; show "Generando QR…")
        ↓ success
waiting (QR rendered + countdown 3:00 → 0:00, polling every 5s, listening to socket)
        ├── countdown < 30s → countdown text turns red (`error.main`)
        ├── socket event `mercadopago:approved` → approved
        ├── SWR poll sees status='approved' → approved
        ├── countdown reaches 0 → expired
        └── user clicks "Cancelar QR" → confirm → expired
        ↓
approved (✓ check icon, fade-in success state, "Generando venta…")
        ↓ ~600ms delay (lets user see confirmation)
auto-trigger handleSubmit("INVOICED", paymentMethods) → modal closes
        ↓
expired (red ✗, "QR expirado", "Generar nuevo QR" CTA returns to idle for that row)
```

**Idempotency guard:** `processedIntentRef` ref guard MUST be set before calling `handleSubmit`. If both webhook AND polling fire, only the first wins.

**Keyboard:**
- `Esc` while QR modal open → triggers Cancel QR confirm (existing modal behavior preserved)
- `F2` → Generar Venta (existing) — disabled while QR pending; only callable when MP status='approved' OR no MP row

### Surface 3 — Sandbox banner mount/unmount

- Mounted at top of `pages/nueva-venta/...` page when `useMpAccountForCurrentScope()` returns environment='sandbox'
- Re-evaluates on `BranchContext` change (switching branch can flip sandbox/production)
- Re-evaluates on MP account reconnect/disconnect events (Socket.io or SWR mutate)
- Banner is sticky-non-sticky — scrolls with page (NOT `position: sticky`) per existing nueva-venta layout
- Click "Cambiar a producción" → `next/router push('/configuracion/mercadopago')`

### Surface 4 — Caja MP row interactions

- Row hover: bg `rgba(0, 177, 234, 0.18)` (deeper tint than resting)
- "Transferir →" click → opens transfer modal (admin/gerente only — disabled with tooltip for vendedor)
- "Detalle" click → opens detail modal with mp_movements (time descending)
- Detail modal "Transferir saldo" footer CTA → close detail + open transfer (chained)
- Transfer quick-fill buttons (25/50/100%) → calculate from current `mp_wallets.balance`, write to amount field
- Transfer amount input: mono font, right-aligned, currency mask (existing AR `cleave.js` pattern)
- Transfer submit → optimistic UI: row balance decremented immediately, rolled back on failure

### Surface 5 — Refund failure flow

- On `nullifySale` API response, if `mpRefundFailed: true`:
  1. SWR cache for `/api/sales/{id}` mutates with new `refundStatus: 'failed'` + `refundAttempts[]`
  2. Inline `<Alert severity="error">` mounts in nullify-result area
  3. Global `toast.error()` fires (3.5s auto-dismiss)
  4. Sale summary chip changes to `⚠ Devolución parcial` (or `MP fallida`)
- "Reintentar devolución" click → POST `/api/mercadopago/refunds/{saleId}/retry`
  - Button → `⏳ Procesando…` disabled
  - On success: SWR mutate, success toast, alert unmounts, attempt history appends success row
  - On failure: error toast `Reintento #{N+1} falló…`, attempt history appends failed row, alert remains
- "Abrir MP Dashboard" → `target="_blank" rel="noopener"` external link
- "Ver historial ({N} intentos)" → smooth-scrolls to `#refund-attempts` anchor
- Attempt history is ALWAYS visible if `attempts.length > 0` (never collapsed) — operator must be able to debug

### Loading states (all surfaces)

- API in-flight: button shows `⏳ Procesando…` + `disabled`. NO spinner overlays. Buttons indicate their own state.
- SWR initial fetch on `configuracion/mercadopago`: 3 skeleton cards (`<Skeleton variant="rectangular" height={120} />`) replaced with content on data
- SWR error: inline `<Alert severity="error">` with retry button
- Optimistic updates: transfer/disconnect mutate cache immediately, revert on rejection

## Accessibility

| Concern | Decision |
|---------|----------|
| Color contrast (text on bg) | `#f4f4f8` on `#1a1a2e` = 14.5:1 (AAA). `#9999b3` on `#1a1a2e` = 6.1:1 (AA). Mono numerics on surface-2 `#232342` = 12.8:1 (AAA). |
| Color contrast (chip text) | Cyan `#00b1ea` chip uses dark text `#1a1a2e` (contrast 8.4:1). Gold `#f5a623` chip uses dark text `#1a1a2e` (contrast 9.1:1). |
| Color-only signaling | All semantic states pair color with icon/text: success has ✓, error has ⚠️, sandbox has 🧪, environment chip has 🌐 / 🧪. NEVER rely on color alone. |
| Keyboard navigation | All buttons reachable via Tab. QR modal: Esc → Cancel confirm. F2 → Generar Venta (existing). Tab order: payment rows → MP amount input → Cancel QR → Cancelar (modal) → Generar Venta. |
| Screen readers | `<Alert>` uses MUI's built-in `role="alert"` + `aria-live`. Toast also `role="status" aria-live="polite"`. Countdown announced via `aria-live="off"` (would be too chatty) — operator gets visual signal only. |
| Touch targets | All buttons ≥ 36px height (MUI `size="small"` default). Switch toggles ≥ 38px hit area. |
| Focus rings | MUI default `outline` preserved on all interactive elements. Focus shadow `0 0 0 3px var(--color-primary-soft)` (gold halo) on primary CTAs. |
| QR scannability | White background `#fff` wrapper around QR (`p: 1.5` = 12px margin) — required for camera contrast against dark theme. `level="M"` error correction (15% data recovery — handles minor camera blur). |
| Disabled state contrast | Disabled buttons use MUI `opacity: 0.38` (matches MUI dark theme spec, AA-compliant for non-critical interactive). |
| Toast dismissal | 3500ms auto-dismiss + manual close button (X icon top-right) for screen reader users who need more time. |
