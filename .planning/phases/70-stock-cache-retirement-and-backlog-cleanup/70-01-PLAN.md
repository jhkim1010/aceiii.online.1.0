<objective>
재고 수량을 **읽는** 경로를 `products.stock` 캐시에서 `stock_balances` / 인터페이스 뷰로 옮긴다.

`products.stock` 은 상품당 숫자 하나라 **지점 차원이 없다.** 다지점 매장에서 "이 지점에 몇 개 있나" 를 물으면 원래 답할 수 없었고, 코드가 그걸 지점별 재고인 것처럼 쓰던 자리가 남아 있다. `stock_balances` 는 `ProductBranch` 단위라 이 질문에 정확히 답한다.

Purpose: 70-06 에서 트리거를 걷어내려면 **읽는 쪽이 먼저 옮겨져 있어야** 한다. 순서를 뒤집으면 재고가 0으로 보이는 사고가 난다.
Output: `products.stock` 을 읽지 않는 재고 조회·검증 경로.
</objective>

### T2 — 판매 재고 검증 전환 (가장 중요)
`sales-create.service.ts:1276`

```ts
if (!product.isGeneric && !allowSaleWithoutStock && product.stock <= 0) { ... }
```

`product.stock`(전 지점 합) → **판매가 일어나는 지점의 `stock_balances.available`** 로 교체한다.

- 조회는 판매 트랜잭션 안에서, `product_branch_id` 기준
- **`allowSaleWithoutStock` 이 true 면 지금처럼 통과** — 음수 재고는 그 매장에서 의도된 동작이다. 차단을 새로 넣으면 회귀다
- `isGeneric` 예외 유지
- 여러 품목을 검증할 때 N+1 금지 — `product_branch_id IN (:ids)` 로 한 번에

### T3 — 나머지 읽기 경로 전환
`cantidad` 같은 응답 필드는 **의미를 확인하고** 옮긴다. 전 지점 합이 맞는 자리면 `v_stock_total_variante.available`, 지점별이면 `stock_balances.available`. 판단 근거를 주석에 남긴다.

### T4 — 회귀 테스트
`sales-stock-guard.spec.ts` 에 케이스 추가:
- `allowSaleWithoutStock=false` + available 0 → 차단
- `allowSaleWithoutStock=true` + available 음수 → **통과** (정책)
- 지점 A 재고 0 / 지점 B 재고 10 → 지점 A 판매는 차단, 지점 B 는 통과 (`products.stock` 합계로는 구분 못 하던 케이스)
