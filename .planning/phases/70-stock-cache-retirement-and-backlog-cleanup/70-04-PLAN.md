<objective>
Trello [Pasar a pdf](https://trello.com/c/30zWO5C8) — *"en el formato de notebook o 110% u 90% no aparece la opcion para traspasar a pdf... solo si esta en 70%"*.

**신고는 레이아웃 문제로 들리지만 원인이 둘이다.**

1. **레이아웃**: `ReportsTopbar.tsx` 는 `height:56` 단일 flex row 에 `flexWrap` 이 없다. 좌측 제목과 우측 액션군은 `flexShrink:0`, 중앙 필터 슬롯은 `flex:1, minWidth:0` 인데 **자식 필드가 `minWidth:120`/`100` 으로 고정**(`ReportsFilterFields.tsx:27,157`)이라 줄어들지 않는다. 폭이 좁아지면 필터가 슬롯 밖으로 넘쳐 우측 액션군을 덮는다. 70% 로 축소하면 다시 보이는 동작과 정확히 일치한다.

2. **★ 더 중요**: 그 PDF 버튼은 **동작하지 않는 placeholder** 다.

```ts
// ReportsTopbar.tsx:26-29
const handlePdf = () => { alert('PDF export — próximamente') }
```

보이게만 만들면 경고창만 뜬다. 즉 이 카드는 레이아웃 버그이자 **미구현 기능 요청**이다.

Purpose: 둘 다 고친다. 레이아웃만 고치면 사용자는 "이제 보이는데 안 된다" 를 다시 신고한다.
Output: 실제로 PDF 를 내려주는 버튼 + 좁은 화면에서 안 가려지는 상단바.
</objective>

### T1 — 레이아웃 수정
`ReportsTopbar.tsx`:
- 우측 액션군을 **우선 배치**하고 중앙 필터 슬롯에 `overflow: hidden` 적용 → 넘쳐도 액션을 덮지 않는다
- 또는 `flexWrap: 'wrap'` + 높이 auto 로 필터를 아래 줄로 내린다 (둘 중 시각적으로 나은 쪽 선택, 근거를 SUMMARY 에)
- 확인 폭: 브라우저 확대 100% / 110% / 125%, 노트북 1366px

### T2 — PDF 생성 (서버)
Excel 이 이미 서버 생성 방식이다(`ExcelService.generateExcelReport` + `apiConnector.downloadFile`). **같은 구조**로 PDF 를 만든다.

- `reportsPdf.service.ts` 신규 — 리포트 공통 PDF 생성기
- **`pypdf` 사용 금지** (프로젝트 규약). 이미 저장소에 있는 PDF 생성 수단을 먼저 찾아 쓴다 — `print-agent`/매뉴얼 빌드에 puppeteer 전례가 있으니 그 경로를 우선 검토
- 내용: 리포트 제목 · 적용된 필터 요약 · 생성 시각 · 매장/지점 · 데이터 표
- **필터·정렬이 화면과 동일**해야 한다 — Excel export 가 params 를 받는 방식을 그대로 따른다
- 행 수 상한을 두고(예: 5,000행) 초과 시 안내. 무제한 생성은 메모리·pool 위험

### T3 — PDF 버튼 배선
`ReportActionsContext` 에 `downloadPdf` 를 추가하고 `alert` placeholder 를 제거한다. Excel 과 동일하게 Body 가 등록 → Topbar 가 호출.
`downloadPdf` 를 등록하지 않은 리포트는 버튼이 **비활성**이어야 한다 (`hasExcel` 패턴 그대로).
