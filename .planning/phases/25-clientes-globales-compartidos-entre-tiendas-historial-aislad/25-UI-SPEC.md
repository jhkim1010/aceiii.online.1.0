# Phase 25 — UI Design Contract

> Visual and interaction contract for Phase 25 (Clientes globales compartidos + Importación masiva). Generated by gsd-ui-researcher on 2026-04-23, verified downstream by gsd-ui-checker.

This spec **extends** the existing Ventago MUI 5 design system. No new component library is introduced. Every new surface reuses established MUI primitives (`Chip`, `Stepper`, `Dialog`, `Alert`, `DataGrid`/`FullTable`, `CardHeader`) and the `themeConfig` palette found at `ventago-app/src/@core/theme/palette/index.ts`.

## Spacing Scale

All new UI uses the MUI theme spacing unit (`theme.spacing(n)` = `8 × n` px). Concrete pixel values are multiples of 4 per the GSD rule. The `sx` shorthand numbers below map directly to this unit.

| Token | Value | MUI `sx` | Usage in Phase 25 |
|-------|-------|----------|-------------------|
| xs  | 4 px | `0.5` | Chip icon-to-label gap; adjacent radios inside a row; inline form adornments |
| sm  | 8 px | `1` | Chip-to-chip gap (filter bar); `DialogTitle` gap between avatar and title (matches existing pattern) |
| md  | 16 px | `2` | Default `TextField` vertical rhythm; `Alert` → next block; button-group horizontal gap |
| lg  | 24 px | `3` | `Grid container spacing` for stat-card rows (matches ClienteVistaView); `DialogContent` padding |
| xl  | 32 px | `4` | Drop-zone padding (`Stepper` step 0 upload box); page-level section break above `Stepper` |
| 2xl | 48 px | `6` | Empty-state vertical padding (`py: 6` matches existing); between commit-result hero card and failure-row list |
| 3xl | 64 px | `8` | Not used in this phase (single-column page layout) |

**Dialog sizing rules (merge + promotion):**
- `maxWidth="md"` + `fullWidth` for `PromoteMergeDialog` (matches ClienteVista edit dialog)
- `maxWidth="sm"` + `fullWidth` for the promotion-trigger confirmation step
- Inner `Grid container spacing={2}` for field-pair rows (16 px between adjacent field blocks)
- 16 px (`sx={{ p: 2 }}`) padding between field-pair radio columns

**Exceptions:**
- Upload drop-zone `border: '2px dashed'` matches existing CargaMasiva pattern — not re-specified.
- Chip `size="small"` keeps 24 px height; touch targets for Action chips/buttons remain ≥ 32 px via MUI default `Button size="medium"`.

Uses the project's existing MUI type scale (`ventago-app/src/@core/theme/typography/index.ts`). No new roles introduced. Phase 25 only asserts which existing variants are valid for each new surface.

| Role | MUI variant | Size | Weight | Line Height | Phase 25 Usage |

## Color

Phase 25 adheres to the existing palette at `ventago-app/src/@core/theme/palette/index.ts`. The 60/30/10 split is expressed below in MUI theme tokens; raw hex values are only listed for chips and row-tints where MUI's automatic `color` prop cannot express the intended subtle tint.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`background.paper`) | Card surfaces, dialog body, preview table cells |
| Secondary (30%) | page background `#F4F5FA` (default MUI `background.default`) + sidebar navy `#1a1a2e` (layout-wide) | Page scaffolding; unchanged by this phase |
| Accent (10%) | `primary.main` = `#05a7cf` (teal) | Primary CTAs only: "Importación masiva" button, Stepper's active step, "Confirmar importación", row-override dropdown selected state, merge-dialog "Aplicar cambios" button |
| Destructive | `error.main` = `#EA5455` | "Skip" chip, error-row background tint, failure-row list item, merge-dialog "Cancelar promoción" destructive-secondary action |

**Accent (`#05a7cf`) is reserved for — explicit list:**
1. Primary CTA buttons introduced by this phase
2. Active Stepper step indicator (MUI default)
3. Selected row-override dropdown option
4. `[Global]` chip background (see below)
5. Hovered upload drop-zone border (existing `primary.dark` from `'&:hover'`)

Accent must **NOT** be used for: generic body icons, row borders, info banners, secondary buttons, filter chips (filter chips use MUI `color` prop based on state only).

### Chip semantic tokens

Chips are central to this phase (row-bucket visualization). Exact MUI mapping:

| Chip label | MUI `color` | Variant | Exact resolved hex | Rationale |
|-----------|-------------|---------|---------------------|-----------|
| `Global` | `primary` | `filled` | `#05a7cf` bg / `#fff` label | Matches accent; signals promotion destination |
| `Local` | `default` | `filled` | MUI grey[300] `#E0E0E0` bg / rgba(0,0,0,0.87) label | Neutral; signals "stays where it is" |
| `Skip` | `error` | `outlined` | `#EA5455` border + label / transparent bg | Outlined (not filled) to visually de-emphasize excluded rows while remaining identifiable |
| `Link to current tienda` | `info` | `outlined` | `#00CFE8` border + label | Used as row-override indicator when user chose "link only" for an existing-global-hit |
| `Update basic info` | `warning` | `outlined` | `#FF9F43` border + label | Used as row-override indicator when user chose to overwrite fields on an existing global record |

### Row-tint (DataGrid error highlight)

Rows with validation errors (regardless of bucket) get a subtle red tint:

```tsx
sx={{
  '& .row-error': { backgroundColor: 'rgba(234, 84, 85, 0.08)' },
  '& .row-error:hover': { backgroundColor: 'rgba(234, 84, 85, 0.14)' },
}}
// applied via getRowClassName on DataGrid
```

Rationale: MUI's `theme.palette.error.main` at 8% alpha is the standard "subtle error wash" used in the theme overrides directory (`src/@core/theme/overrides/dataGrid.ts` pattern for selected/hovered states).

### Promotion status indicator (GlobalClientesView)

Binary dot next to the cliente name: `success.main` (`#28C76F`) = promoted/verified, `warning.main` (`#FF9F43`) = pending merge decision. Size: 8 px circle. Not a chip — visual weight is lower because this is a read-only list.

### S6 — PromoteMergeDialog (NEW file)

**Path:** `ventago-app/src/views/cliente-vista/PromoteMergeDialog.tsx`

**Props:**
```ts
type PromoteMergeDialogProps = {
  open: boolean
  onClose: () => void
  mode: 'promote-confirm' | 'merge-resolve'
  localClient: {
    id: number
    fullname: string
    document: string
    email?: string
    phone?: string
    address?: string
    provincia?: string
    localidad?: string
    fechaNacimiento?: string
    notas?: string
  }
  existingGlobalClient?: typeof localClient & {
```

**Layout:**

`mode === 'promote-confirm'` (no duplicate found in ownerGroup):

- `DialogTitle`: `[icon mdi:account-arrow-up-outline]` + `"Promover a cliente global"`
- `DialogContent`: Single `Alert severity="info"` + summary card of `localClient` fields + explanatory body paragraph
- `DialogActions`: `[Cancelar]` (outlined) + `[Promover]` (contained primary)

`mode === 'merge-resolve'` (duplicate found):

- `DialogTitle`: `[icon mdi:call-merge]` + `"Cliente ya existe en otra tienda del grupo"`
- `DialogContent`:
  - `Alert severity="warning"`: `"Se encontró un cliente global con el mismo {DNI|CUIT}. Elige qué valor conservar para cada campo."`
  - Metadata header: `Global actual está vinculado a {linkedStoreCount} tienda(s) del grupo.`
  - **Field-pair grid** — one `Grid container` per field, 4 fields per row on `sm` breakpoint:

```tsx
<Grid item xs={12} md={6}>
  <FormControl component="fieldset" fullWidth sx={{ border: 1, borderColor: 'divider', borderRadius: 1, p: 2 }}>
    <FormLabel component="legend" sx={{ px: 1 }}>{fieldLabel}</FormLabel>
    <RadioGroup value={fieldPicks[field]} onChange={(e) => setFieldPicks(prev => ({ ...prev, [field]: e.target.value }))}>
      <FormControlLabel
        value="global"
        control={<Radio size="small" />}
        label={<><Chip label="Global" color="primary" size="small" variant="outlined" sx={{ mr: 1 }} /> {existingGlobalClient[field] || <em>{t('common_empty', '(vacío)')}</em>}</>}
      />
      <FormControlLabel
        value="local"
        control={<Radio size="small" />}
        label={<><Chip label="Local" size="small" variant="outlined" sx={{ mr: 1 }} /> {localClient[field] || <em>(vacío)</em>}</>}
      />
    </RadioGroup>
  </FormControl>

```

- Fields in scope (order): `fullname`, `document` (display only — radio disabled, "por coincidencia obligatoria"), `phone`, `email`, `address`, `provincia`, `localidad`, `fechaNacimiento`, `notas` → **9 fields, 5 rows on md** (each pair = 2 columns).

- `DialogActions`: `[Cancelar]` (outlined) + `[Combinar y promover]` (contained primary, disabled until every field has a pick)

- Loading (confirm in-flight): action buttons disabled, `[Combinar y promover]` → `<CircularProgress size={16} />` + `Procesando...` label
- Error (API 4xx/5xx): `Alert severity="error"` at top of content; retry enabled; the current fieldPicks are preserved
- Success: dialog auto-closes via `onConfirm` resolving; parent shows `Snackbar severity="success"` `"Cliente promovido correctamente"`

**Keyboard:** ESC closes (MUI default). ENTER inside the dialog submits only when focus is on the action button (MUI default). No custom shortcut.

**Accessibility:** All field-pair `FormControl` has `<FormLabel>` acting as `legend`; each radio has an auto-generated unique id via MUI's `RadioGroup`. Screen readers will announce "Nombre completo — Global: Juan Pérez — Local: Juan A Perez".

### S7 — POS/ClienteView promotion trigger

**Rule:** In `ClienteVistaView.tsx` `handleSave`, after a successful `PUT /clients/:id` where the payload contains a **newly added** document (`prevDocument === '' && newDocument !== ''`), the response body includes `needsPromotion: true` and optionally `mergeConflict: { existingGlobalClient }`.

**Flow:**
1. Save succeeds → close edit dialog → open `PromoteMergeDialog`:
   - `mode: 'promote-confirm'` if `mergeConflict === null`
   - `mode: 'merge-resolve'` if `mergeConflict` populated
2. User confirms → calls `POST /clients/:id/promote` or `POST /clients/merge` per mode
3. Success → `Snackbar` (`react-toastify` — existing toast library per `themeConfig.toastPosition='top-right'`) + refresh table
4. User cancels → local client remains; next save (without further DNI changes) **does not** re-prompt (stateful `skipPromotionFor: Set<clientId>` in component state; resets on component unmount)

**"Always confirm" vs "silent promote" decision (Claude's Discretion):** Chosen **always-confirm** per CONTEXT.md hint, because:
- Merge scenario requires explicit field picks (unavoidable)
- Promote-only scenario: confirmation is quick (one button) and matches cashier's mental model of "I just changed important data"
- No silent side-effects — user sees the new global status in the result snackbar

### Copywriting contract (summary for checker)

| Element | Copy (ES primary) |
|---------|-------------------|
| Primary CTA (phase entry) | **Importación masiva** |
| Primary CTA (commit) | **Confirmar importación** |
| Primary CTA (merge) | **Combinar y promover** |
| Empty state heading | **Sin filas en este filtro.** |
| Empty state body | **No hay filas para importar. Revisa la configuración.** |
| Error state (single row) | **DNI inválido (se esperan 7-8 dígitos).** / **CUIT inválido (fallo checksum mod-11).** / **Formato de email inválido.** |
| Error state (page-level) | **La importación falló. Ninguna fila fue procesada. Descarga el CSV de errores y corrige antes de reintentar.** |
| Destructive confirmation | **Cancelar promoción** (with dialog copy: "Se conservará como cliente local. Los datos aún no son visibles en otras tiendas.") |
| 403 global client | **No tienes permiso para acceder a este cliente (distinto grupo propietario).** |

Destructive actions in this phase:
- **Cancel mid-flow merge** — treat as non-destructive for data (no persistence changes); copy: `Cancelar`.
- **Cancelar promoción** (from merge dialog) — user says "no, do not promote this local client now". Local record is untouched; DNI/CUIT field is **reverted** on the edit form. Confirmation: inline, no second modal (single click cancels).
- **Fusionar grupos** (superadmin) — truly destructive (groups become one, cannot split back). Two-step confirm: first the Select dialog, then a `<Dialog>` typing the target group name (`"Escribe el nombre del grupo destino para confirmar"`).
