# Plan 09-01: DB 마이그레이션 + 백필 (Store Lifecycle 컬럼 도입)

**Phase:** 09-store-lifecycle
**Status:** Not started
**Depends on:** Nothing (v1.0 운영 DB 기준)
**Estimate:** 0.5일

## Goal

운영 무중단으로 `stores` 테이블에 lifecycle 컬럼을 추가하고 기존 데이터를 백필한다.

## Scope (In)

- `api-ventago/src/migrations/` 에 마이그레이션 파일 추가 (Sequelize-cli 또는 raw SQL 스크립트)
- 신규 컬럼: `lifecycle_state`, `trial_ends_at`, `activated_at`, `suspended_at`, `archived_at`, `lifecycle_reason`
- 인덱스: `idx_stores_lifecycle`, `idx_stores_trial_ends` (partial)
- `Users.status` + `Users.trialEndsAt` 기반 백필 쿼리
- 운영 배포 전 dev DB 검증 SQL

## Scope (Out)

- 모델/서비스 코드 변경 (Plan 09-02)
- 기존 `status`/`isActive` 컬럼 제거 (다음 사이클)

## Success Criteria

1. 신규 컬럼이 모두 생성되고 인덱스가 잡힘
2. 기존 매장 전부 `lifecycle_state` 값 채워짐 (NULL 없음)
3. `trial_ends_at` 이 매장별로 유저 중 `MAX(trial_ends_at)` 로 설정됨
4. 롤백 스크립트 존재 (`DROP COLUMN ... IF EXISTS`)
5. 운영 DB 적용 시 락 시간 1초 미만

## Steps

1. 마이그레이션 파일 작성 (`20260407-store-lifecycle.sql`)
2. dev DB에서 실행 → 샘플 데이터로 백필 결과 검증
3. Staging DB에 적용 → `/store` API 동작 확인 (기존 코드는 신규 컬럼 무시)
4. 운영 DB 적용 (짧은 배치 락)
5. Rollback 스크립트 준비

## Risks

- 백필 쿼리가 users 테이블 대량 스캔 → 인덱스 사전 확인 필요
- `MAX(trial_ends_at)` 서브쿼리 성능 → 필요 시 CTE 사용
