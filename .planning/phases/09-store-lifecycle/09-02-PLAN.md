# Plan 09-02: 백엔드 Store Lifecycle 서비스 + Cron 재작성

**Phase:** 09-store-lifecycle
**Status:** Not started
**Depends on:** Plan 09-01
**Estimate:** 1.5일

## Goal

Store 상태 머신을 백엔드에 구현하고, 상태 전이 API를 제공하며, cron을 Store 레벨로 재작성한다.

## Scope (In)

### 모델
- `api-ventago/src/app/store/store.model.ts`:
  - `lifecycleState`, `trialEndsAt`, `activatedAt`, `suspendedAt`, `archivedAt`, `lifecycleReason` 컬럼 추가
  - VIRTUAL `lifecycleDetails` getter (UI용: id, name, color, description)
- `api-ventago/src/common/constants.ts`:
  - `LifecycleState` enum (`TRIAL|ACTIVE|SUSPENDED|ARCHIVED|DELETED`)
  - `LifecycleDetails` 매핑 (이름, 색상, 아이콘)
  - `LIFECYCLE_TRANSITIONS` 허용 전이 맵 (state machine guard)

### 서비스
- `store.service.ts`:
  - `createStore()` → 자동 `lifecycleState='TRIAL'` + `trialEndsAt = now + 30일`
  - `findAllQuerys()` → `state` 파라미터 지원, `status`/`isActive` 파라미터는 deprecated alias
  - `getLifecycleStats()` → 단일 GROUP BY 쿼리로 KPI 반환 `{trial, active, suspended, archived, expiringSoon}`
  - `transitionLifecycle(storeId, toState, reason, actorUserId)` → 상태 전이 단일 메서드
    - 허용 전이 검증 (`LIFECYCLE_TRANSITIONS`)
    - 타임스탬프 업데이트 (`activatedAt`, `suspendedAt`, `archivedAt`)
    - `lifecycleReason` 기록 (감사)
    - `Users.status` cascade 업데이트 (동기화)
    - SUSPENDED/ARCHIVED 전이 시 해당 store의 `active_sessions` 즉시 삭제
  - `extendTrial(storeId, newTrialEndsAt)` → 기존 메서드 재활용, 단일 값으로 갱신
- `store.controller.ts` 엔드포인트 추가:
  - `GET /store?state=TRIAL,ACTIVE` (기존 status 호환 유지)
  - `GET /store/lifecycle-stats`
  - `PUT /store/:id/activate` body `{reason?}`
  - `PUT /store/:id/suspend` body `{reason}`
  - `PUT /store/:id/archive` body `{reason}`
  - `PUT /store/:id/restore` body `{reason}`
  - `PUT /store/:id/extend-trial` (기존 유지)
- `/store/with-admin` 엔드포인트: 내부적으로 `findAllQuerys({include:'admin'})` 위임, 신규 코드에서는 deprecated

### Cron 재작성
- `store.cron.ts` `suspendExpiredStores()` 재작성:
  ```typescript
  // 1단계: 배치 UPDATE Store
  UPDATE stores
  SET lifecycle_state='SUSPENDED',
      suspended_at=NOW(),
      lifecycle_reason='Trial expired + grace period'
  WHERE lifecycle_state='TRIAL'
    AND trial_ends_at + interval '{gracePeriodDays} days' < NOW()
  RETURNING id;

  // 2단계: 배치 UPDATE Users (위 returning된 store_ids로)
  UPDATE users SET status='suspended'
  WHERE store_id IN (...) AND status IN ('trial','active');

  // 3단계: active_sessions 삭제
  DELETE FROM active_sessions WHERE store_id IN (...);

  // 4단계: 알림 (비동기)
  ```
- **단일 트랜잭션** 내 3개 쿼리만 실행 (for-loop 금지, pool 1 connection)
- 추가 cron: trial 만료 7일/3일/1일 전 경고 알림

### Session Guard
- `guards/session.guard.ts`:
  - JWT 검증 후 `Store.lifecycleState IN ('SUSPENDED','ARCHIVED','DELETED')` 체크
  - 해당 시 401 `STORE_SUSPENDED` 응답
  - Store 조회는 sessionToken validation 쿼리에 JOIN으로 포함 (추가 쿼리 없음)

## Scope (Out)

- 프론트엔드 변경 (Plan 09-03)
- 기존 `status`/`isActive` 컬럼 삭제 (다음 사이클)

## Success Criteria

1. 매장 신규 생성 시 lifecycle_state='TRIAL', trial_ends_at=+30d 자동 설정됨
2. `PUT /store/:id/activate` 호출 시 상태 전이 + 타임스탬프 기록 + Users cascade 업데이트
3. 허용되지 않은 전이(예: DELETED→ACTIVE) 시 400 에러
4. Cron이 단일 트랜잭션 3쿼리로 expired trial 일괄 처리
5. SUSPENDED 매장의 기존 세션이 즉시 무효화 (401 반환)
6. `/store/lifecycle-stats` 가 단일 쿼리로 5개 count 반환
7. `/store?state=TRIAL,ACTIVE` 필터링 정상 동작
8. 기존 `/store?status=0,1` 요청도 backward-compat로 동작

## Steps

1. `constants.ts` enum/transitions 맵 추가
2. `store.model.ts` 컬럼 매핑 + VIRTUAL getter
3. `store.service.ts`: `transitionLifecycle()` + `getLifecycleStats()` 구현
4. `store.service.ts`: `findAllQuerys()` state 파라미터 지원
5. `store.controller.ts`: 신규 엔드포인트 4개 + stats
6. `store.cron.ts`: 배치 쿼리로 재작성
7. `session.guard.ts`: lifecycle 체크 추가
8. 기존 `createStore` 에 trial 자동 설정 로직 추가
9. `extendAdminTrial` → Store 레벨 `extendTrial`로 일부 이관
10. 단위 테스트: 전이 규칙 + cron 배치

## Risks

- **Users.status 동기화 경합**: 여러 admin 유저가 있는 경우 cascade 업데이트 시 트랜잭션 격리 필요
- **기존 코드 호환성**: `findAllQuerys`에 `status` 쓰는 다른 호출자 확인 필요 (grep)
- **Session guard의 추가 쿼리**: Store join이 매 요청 오버헤드 → `active_sessions` 테이블에 `lifecycle_state_cache` 컬럼 고려
- **Cron 배치 락**: SUSPENDED 전환 시 users 테이블 대량 UPDATE → 운영 시간대 피하기 (00:00 유지)
