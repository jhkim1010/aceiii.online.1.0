**B. `tick()` 재작성** — 조회+갱신을 하나로:
```typescript
// [Phase 64 W5] 만료 lease 회수 — 워커가 죽어 processing 으로 갇힌 작업을 되살린다.
// 별도 cron 을 만들지 않는다(워커 복귀 시 중복 스케줄 위험). tick 시작 시 1회면 충분하다.
private async reclaimExpiredLeases(): Promise<number> {
  const [, meta] = await this.sequelize.query(
    `UPDATE sync_outbox
        SET status = 'pending', locked_by = NULL, lease_expires_at = NULL,
            last_error = COALESCE(last_error, 'lease expired — reclaimed')
      WHERE status = 'processing' AND lease_expires_at < NOW()`,
  );

  return (meta as any)?.rowCount ?? 0;
}

// [Phase 64 W5] 원자적 claim.
// 종전에는 SELECT 로 고르고 별도 UPDATE 로 표시해서, 두 워커가 같은 작업을 집을 수 있었다.
// SKIP LOCKED 는 다른 워커가 잠근 행을 대기 없이 건너뛴다 — 워커가 늘어도 서로 막지 않는다.
private async claimBatch(limit: number): Promise<SyncOutbox[]> {
  const [rows] = await this.sequelize.query(
    `UPDATE sync_outbox o
        SET status = 'processing',
            attempts = o.attempts + 1,
            locked_by = $1,
            lease_expires_at = NOW() + INTERVAL '5 minutes'
       FROM (
         SELECT id FROM sync_outbox
          WHERE status = 'pending' AND next_retry_at <= NOW()
          ORDER BY next_retry_at
          LIMIT $2
          FOR UPDATE SKIP LOCKED
       ) s
      WHERE o.id = s.id
    RETURNING o.*`,
    { bind: [this.workerId, limit] },
  );

  return rows as SyncOutbox[];
}
```
- `workerId` = `${process.env.pm_id ?? 'w'}-${process.pid}` 형태(짧고 식별 가능하게).
- `tick()` 본문은 `reclaimExpiredLeases()` → `claimBatch(BATCH_SIZE)` → 순차 처리(기존 `for` 루프 유지, `job.update({status:'processing'})` 호출은 제거 — claim 이 이미 했다).
- `running` 플래그는 유지하되 주석 추가: **정확성의 근거가 아니라 같은 프로세스 내 중복 tick 방지용일 뿐이며, 정확성은 SKIP LOCKED + lease 가 담당한다.**
- 성공 시 `status='done'`, 실패 시 `markRetryOrFail` — 둘 다 `locked_by`/`lease_expires_at` 을 NULL 로 되돌린다.
- `attempts` 증가 위치가 claim 으로 이동했으므로 `markRetryOrFail` 의 `job.attempts >= job.maxAttempts` 비교가 여전히 맞는지 확인한다(중복 증가 금지).
