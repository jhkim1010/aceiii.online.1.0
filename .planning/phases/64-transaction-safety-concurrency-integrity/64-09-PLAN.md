  });

**1. `sale-idempotency.conc-spec.ts`** (R1)
- 같은 `Idempotency-Key` 로 동시 2요청 → `SELECT count(*) FROM sales WHERE ...` == 1
- 두 응답 body 의 `id` 가 같다
- 완료 후 같은 키 재요청 → 신규 판매 0, 저장된 응답 재생
- 다른 body + 같은 키 → 422

**2. `nullify-double.conc-spec.ts`** (R2)
- 동일 saleId 동시 취소 2요청 → `count(*) WHERE nullified_sale_id = $id` == 1
- 성공 1 / 400 1
- `products.stock` 복원량 == 원본 판매 수량 (2배 아님)

**3. `suspended-atomicity.conc-spec.ts`** (R3)
- update 중 실패 주입(존재하지 않는 productId 등) → 구 아이템 개수 불변
- 동시 update+remove → 하나만 성공, 예약 원장 합 정확히 1회분

**4. `work-order-complete.conc-spec.ts`** (R4)
- 동시 완료 2요청 → `production_results` 1건, work order COMPLETED 1회
- 원장 합 == `products.stock` 변화량
- 원장 행에 `product_branch_id` 존재(`product_id` 컬럼 조회는 오류가 나야 정상)

**5. `outbox-claim.conc-spec.ts`** (R6)
- 동일 큐에 job 20건 적재 후 tick 2개 동시 실행 → processor 호출 총합 == 20 (중복 0)
- `processing` + 만료 lease job → tick 후 pending 복귀
- 판매 롤백 시 outbox 행 0 (R5)

**6. `offline-push-idem.conc-spec.ts`** (R7)
- 동일 uuid 동시 2배치 → 500 발생 0, `applied` 1 + `duplicate` 1, sales 1건
- `received` 상태 op 재전송 → 판매 1건 생성 + `applied` 전이
