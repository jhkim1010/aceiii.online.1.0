세부 규칙:
1. `for` 루프 안의 모든 `create`/`increment`/`findOne`/`update` 에 `{ transaction: t }` 를 빠짐없이 전달한다 — **하나라도 누락되면 그 문장만 별도 커넥션에서 실행돼 원자성이 깨진다**(이번 결함의 원인 그 자체).
2. `ProductBranch.findOne/create`(`:772`–`:780`)도 `transaction: t`.
3. 재고 복원 순서는 반드시 `productId` 오름차순. 부모 변형(`parentId`) increment 도 같은 루프 안에서 처리하되, 부모/자식 혼재 시에도 정렬 기준은 `productId` 하나로 통일한다.
4. `resolveSaleBranchId` 는 트랜잭션 진입 전에 1회 호출(현행과 동일 값, 커넥션 추가 점유 없음).
5. MP 환불(`mpRefundService.refundForSale`)은 **커밋 후**. 실패 시 기존처럼 `mpRefundFailed`/`mpRefundError` 를 응답에 첨부한다(동작 불변).
6. promo 감사 로그(`promo_refund_attempt`)는 커밋 후로 이동 — 실제로 취소가 확정된 뒤에만 남는다.
7. `Transaction` 은 `sequelize` 에서 import (파일 상단에 이미 존재하는지 확인 후 추가).
