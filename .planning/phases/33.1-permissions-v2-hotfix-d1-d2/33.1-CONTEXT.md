## Implementation Decisions

### D1 — ensureRoleFunctions 자동복구 제거

**LOCKED:** [api-ventago/src/app/auth/services/user-structure.service.ts:113-204](../../../api-ventago/src/app/auth/services/user-structure.service.ts#L113) `ensureRoleFunctions(user, roleId)` 의 **두 auto-fill 경로 모두 제거**.

근거: 단일 호출처는 line 361 (`/me` 응답 구성 중 사용자 본인 role 해석). 이 함수는 "사용자가 보유한 RoleFunction 을 조회해 functionId 배열로 반환"하는 read-only 책임만 가져야 함. 현재 구현은 그 외에 두 가지 side-effect 를 수행:

- **Path A (line 122-179):** `roleFunctions.length === 0` 이면 `allFunctions` 전체에 대해 `RoleFunction.create({roleId, functionId, storeId})` 를 루프 — 149 row 자동 생성. **즉시 제거**.
- **Path B (line 180-209, else branch):** `backfillRoleFunctions(roleId, storeId)` 호출 — 기존 RoleFunction 이 있어도 신규 Function 등록 시 누락된 row 를 자동 채움. 이게 audit 의 "1 row → /me → 11 row" 재현의 직접 원인. **이 호출도 제거** (`/me` 는 read-only 여야 함).
- `backfillRoleFunctions(roleId, storeId)` 메서드 자체 ([line 80-110](../../../api-ventago/src/app/auth/services/user-structure.service.ts#L80)): 다른 호출처가 없음 (`grep -rn "backfillRoleFunctions" src/` 확인) → 메서드 자체도 **삭제** (dead code 가 되므로).

**최종 동작:** `ensureRoleFunctions` 는 단순히 `RoleFunction.findAll({where:{roleId, storeId}})` 결과의 `functionId` 만 반환. 결과가 0 건이면 빈 배열 반환 → `/me` 의 permissions = `{}` → UI 는 빈 사이드바 노출 → admin 이 명시적 토글 필요. 이게 "matrix UI 신뢰성 회복" 의 정확한 의미.

**예상 회귀:** Vendedor Store / Gerente Store role 을 신규 user 에게 배정하면 사이드바가 비어 보임. 이는 audit Scenario A 의 "🔴 role_functions = 0건 시드 누락" 결함이 별도 phase 로 처리되어야 함을 의미. **이 phase 의 책임 아님**. (out-of-scope.)

### D1-DEAD-CODE — user-registration.service.ts::ensureRoleFunctions 삭제

**LOCKED:** [api-ventago/src/app/auth/services/user-registration.service.ts:139-163](../../../api-ventago/src/app/auth/services/user-registration.service.ts#L139) `ensureRoleFunctions(adminRole, storeId)` **메서드 전체 삭제**.

### D2 — bulkUpdateRoleFunctionActions 에 cache invalidate 추가

**LOCKED:** [api-ventago/src/app/role/role-function/role-function.service.ts:73-103](../../../api-ventago/src/app/role/role-function/role-function.service.ts#L73) `bulkUpdateRoleFunctionActions(roleId, storeId, data)` 끝에 `permissionCacheService.invalidateRole(roleId)` 호출 추가.

**선행 작업:** `PermissionCacheService` 에 `invalidateRole(roleId: number)` 메서드 신규 추가.

위치: [api-ventago/src/app/permissions/permission-cache.service.ts](../../../api-ventago/src/app/permissions/permission-cache.service.ts) (현재 `invalidateUser`, `invalidateBranch`, `invalidateStore` 만 존재).

구현 패턴 (analog = `invalidateStore` line 134-157):
```typescript
async invalidateRole(roleId: number): Promise<number> {
  try {
    const sequelize = this.cacheModel.sequelize;
    if (!sequelize) throw new Error('Sequelize instance unavailable');
    const [, meta] = await sequelize.query(
      `DELETE FROM user_permission_cache
       WHERE user_id IN (SELECT user_id FROM user_roles WHERE role_id = :roleId)`,
      { replacements: { roleId } },
    );
    const deleted = (meta as { rowCount?: number })?.rowCount ?? 0;
    this.logger.debug(`invalidateRole(${roleId}) — ${deleted} rows 삭제`);
    return deleted;
  } catch (error) {
    this.logger.error(`invalidateRole(${roleId}) 실패:`, error);
    return 0;
  }
}
```

**DI 주입:** `RoleFunctionService` constructor 에 `PermissionCacheService` 주입. `RoleFunctionModule` 의 `imports` 에 `PermissionsModule` (또는 `PermissionCacheService` exporting 모듈) 추가. circular dependency 우려 시 `forwardRef` 사용.

**왜 invalidateRole 인가:**
- `invalidateUser(userId)`: role 단위 변경에 부적합 (한 role 에 N user → loop 필요).
- `invalidateStore(storeId)`: 너무 광범위 (다른 role 의 cache 도 함께 날아감).
- `invalidateRole(roleId)`: role_functions 변경의 정확한 scope. ✅
