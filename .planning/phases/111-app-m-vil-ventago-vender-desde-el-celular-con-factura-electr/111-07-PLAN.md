<objective>
Stock ingreso from the phone: one confirmed batch → one transaction of append-only ledger rows (type NULL, by product_branch_id) through the single safe writer, idempotent by a client key, gated by the stock permission, plus the read endpoints the scanner screen needs (current available per variant, destination branches).

Purpose: D-15 (scan → nothing saved until «Confirmar ingreso» → ledger movement in one tx), D-06 (permission). Research Q6, Pitfalls 8–9. Discretion recorded: idempotency = yes (client key, table mobile_stock_ingresos from Plan 01); permission = editar-stock-de-producto/update (prod grants measured read-only 2026-10-15: admin & gerente create/read/update/delete in 25 stores, inventory_clerk update in 10, vendedor/cashier none). Web ingreso routes have no function guard today; this is a new mobile capability so nobody loses an existing ability.
★ Existing contract of this slug (checker 2026-10-15): the web already guards `DELETE /products/stock-today/:parentId` with `@FunctionGuard('editar-stock-de-producto', 'delete')` (products.controller.ts:654 — deleting today's ingreso rows), so ACCIONES_EXIGIDAS_POR_GUARDS currently holds {delete} for it. Adding the mobile routes makes it {delete, update} and the roles screen shows the extra toggle. Decision: the mobile ingreso requires **update** (adding stock is not deleting history; requiring 'delete' would hand the ingreso to whoever may erase ingreso history and nothing else). Lock-out risk measured read-only on prod by the planner 2026-10-15 (5434, role_functions × role_function_actions for this slug): admin 25 stores {delete,update}, gerente 25 {delete,update}, inventory_clerk 10 {delete,update} + 15 none, accountant/cashier/viewer none; roles with delete-WITHOUT-update = **0**; user_function_actions overrides for the slug = 0 rows. So nobody who can delete today is locked out. The executor re-measures (Task 2 step 0) because grants can change before execution; no permission row is ever seeded by this plan (permission-table DML needs explicit user approval + a `-- perm-cache:` note — out of scope).
Output: ledger writer accepts explicit NULL type; PosStockModule.
