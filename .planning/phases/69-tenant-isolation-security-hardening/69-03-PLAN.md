<objective>
`PUT /products/:id/correct-today` (R2 / CR-02)는 지금 **URL 의 부모 상품만** 검증하고
body 의 `branchIds` 와 `items[].variantId` 는 검증 없이 그대로 서비스에 넘긴다.
서비스도 `parent.storeId` 를 이후 비교에 쓰지 않고
`ProductBranch.findAll({ where: { productId: IN variantIds, branchId: IN branchIds } })` 로 조회한다 — storeId JOIN 없음.

결과: 매장 A 사용자가 **자기 부모 상품 ID + 매장 B 의 variantId/branchId** 조합으로
**매장 B 의 재고 원장(`stocks`)에 조정 행을 만든다.** DB 교차 FK 트리거는 "B 상품 ↔ B 지점" 관계가
내부적으로 정합하므로 이를 차단하지 못한다.

Purpose: 원장 쓰기 경로에 소유권 게이트를 세우고, CLAUDE.md 「쓰기 경로 규약」대로 검증과 쓰기를 한 트랜잭션에 묶는다.
Output: 타 매장 조합에 403 을 던지고 `stocks` 행을 1개도 만들지 않는 `correctTodayStocks`.
</objective>

필수로 두는 이유는 CLAUDE.md 의 "헬퍼는 필수 인자로 받아 누락을 컴파일 타임에 막는다" 규약이다 — 기본값을 주지 않는다.

컨트롤러(`products.controller.ts:826`)는 `const { storeId, isSuperAdmin } = this.getScope(user)` 결과를
`{ storeId: storeId ?? null, isSuperAdmin }` 로 넘긴다. 기존 `assertProductInStore` 호출은 그대로 둔다(이중 방어).

서비스 본문 맨 앞(부모 조회 직후)에 아래 검증을 순서대로 넣는다. `scope.isSuperAdmin === true` 면 전부 skip 한다.

1. **부모 재검증**: `parent` 가 없으면 `NotFoundException`. `parent.storeId !== scope.storeId` 이면
   `ForbiddenException('El producto no pertenece a su tienda')`.
2. **branchIds 전량 검증**: `const uniqueBranchIds = [...new Set((branchIds || []).map(Number))]`.
   `Branch.findAll({ where: { id: { [Op.in]: uniqueBranchIds }, storeId: parent.storeId }, attributes: ['id'] })`
   결과 길이가 `uniqueBranchIds.length` 와 다르면 `ForbiddenException('Alguna sucursal no pertenece a su tienda')`.
   (`hasItems === false` 면 branchIds 가 비어 있을 수 있으므로 이 검증은 `hasItems` 일 때만 수행)
3. **variantId 전량 검증**: `const uniqueVariantIds = [...new Set(items.map(i => Number(i.variantId)))]`.
   `Product.findAll({ where: { id: { [Op.in]: uniqueVariantIds } }, attributes: ['id','parentId','storeId'] })`.
   - 길이 불일치(존재하지 않는 id) → `NotFoundException`
   - `storeId !== parent.storeId` 인 행이 하나라도 있으면 → `ForbiddenException`
   - `parentId !== parentId(인자)` 인 행이 하나라도 있으면 → `ForbiddenException('La variante no pertenece a este código madre')`
     ※ 이 조건이 "자기 부모 ID + 남의 변형" 공격을 정확히 막는 지점이다.
4. **ProductBranch 조회에 양쪽 소유권 강제**: 기존 `ProductBranch.findAll` 의 `where` 는 유지하되
   `include: [{ association: 'product', required: true, attributes: [], where: { storeId: parent.storeId } },
              { association: 'branch',  required: true, attributes: [], where: { storeId: parent.storeId } }]`
   를 추가한다. `attributes: []` 로 컬럼을 늘리지 않는다(GROUP BY 안전).
   ★ `required: true` 가 아니면 조건이 ON 절로 내려가 필터가 무력화된다 (Phase 68 Sager 사고와 동일 함정).

`priceUpdates` 는 `parentId` 기준이라 1번 검증으로 커버되지만, `priceTypeId` 는 검증 대상이 아니므로
`Price` 쓰기 경로는 그대로 둔다 (Phase 67 훅 + `trg_tenant_prices_store` 가 담당).

에러 메시지는 스페인어(사용자 노출 문자열)로 유지하고 주석은 한국어로 쓴다.
