<objective>
`jwt-global.guard.ts:53-82` 는 인증 후 `TenantContext.resolve(...)` 전체를 `try { … } catch {}` 로 감싸고,
주석으로 "컨텍스트 확정 실패가 인증 결과를 바꾸지 않는다 (격리는 미해석=no-op 로 폴백)" 이라고 못 박는다(R5 / WR-02).

결과: 예외가 나면 `resolved=false` 가 유지되고 **모든 Sequelize 격리 훅이 no-op 이 된 채 요청이 통과**한다.
보안 경계의 실패 정책이 명시적으로 fail-open 이다. 현재 `resolve` 가 대체로 throw 하지 않는다는 사실에
기대는 구조이며, 그 가정이 깨지는 순간 격리가 통째로 사라진다.

동일 계열의 두 번째 구멍도 함께 닫는다: `resolved=true` 이지만 `storeId === null` 이고 `isSuperAdmin === false`,
`system === false` 인 상태다. `tenant-hooks.ts:allowedStores()` 는 이 경우 `null` 을 돌려주므로 **격리가 전부 no-op** 이다.

Purpose: 격리 실패의 기본 동작을 fail-open 에서 fail-closed 로 뒤집는다.
Output: 미확정 인증 요청 403 + 보안 로그 + 회귀 테스트 + 영향 범위 실측 문서.
</objective>

`JwtGlobalGuard.canActivate` 를 다음으로 바꾼다.

1. `@Public` 분기와 `super.canActivate`, `resolveActAsStore` 위치는 그대로 둔다.
2. `try { … } catch { }` 의 **빈 catch 를 제거**한다. catch 에서:
   - `Logger('TenantGuard').error(...)` 로 라우트·userId·에러 메시지를 남긴다 (보안 로그)
   - `TENANT_CONTEXT_FAIL_MODE` 가 `observe` 가 아니면 `throw new ForbiddenException('No se pudo determinar el contexto de tienda')`
3. try 블록 **뒤에 사후 검사**를 추가한다 (이것이 핵심 — resolve 가 조용히 무시된 경우까지 잡는다):
   ```
   const ctx = TenantContext.get();
   ```
   - `ctx` 가 `undefined` (미들웨어 미적용 경로) → 보안 로그 + 정책 적용
   - `ctx.resolved !== true` → 보안 로그 + 정책 적용
   - `ctx.resolved === true && !ctx.system && !ctx.isSuperAdmin && typeof ctx.storeId !== 'number'`
     → Task 1 판정에 따라 403 또는 로그 전용
4. `TENANT_CONTEXT_FAIL_MODE` 헬퍼를 `tenant-context.ts` 에 추가한다:
   `export type ContextFailMode = 'enforce' | 'observe';`
   `export function resolveContextFailMode(): ContextFailMode` — 기본 `'enforce'`,
   `TENANT_CONTEXT_FAIL_MODE=observe` 면 observe. (`resolveGuardMode` 와 동일한 탈출구 패턴 — 재배포 없이 하향)
5. 보안 로그는 throttle 하지 **않는다** — 이 이벤트는 드물어야 정상이고, 폭주 자체가 신호다.
   로그 형식: `[tenant fail-closed] route=<method url> user=<id> reason=<unresolved|exception|null-store>`
6. 주석의 "컨텍스트 확정 실패가 인증 결과를 바꾸지 않는다" 를 삭제하고
   "확정 실패 = 격리 불가 → 요청 거부. 공개 경로는 @Public 로 명시한다" 로 교체한다.

**주의:** `@Public` 경로는 3번 검사에 도달하지 않는다(1번에서 return). 웹훅·공개몰·로그인 회귀가 없어야 한다.
크론/워커는 HTTP 가드를 타지 않으므로 무영향이다.
