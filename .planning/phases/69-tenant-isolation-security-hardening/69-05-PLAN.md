`VendorLoginDto` 에 선택 필드 `storeId?: number` 를 추가한다 (`@IsOptional() @IsInt() @Type(() => Number)`).

`vendorLogin(phone, pin, storeId?)` 를 다음 규약으로 재작성한다:

1. 후보 조회: `Vendor.findAll({ where: { phone, isActive: true, ...(storeId ? { storeId } : {}) }, include: [Store], order: [['id','ASC']], limit: VENDOR_LOGIN_MAX_CANDIDATES })`.
   `const VENDOR_LOGIN_MAX_CANDIDATES = 10` 을 모듈 상수로 둔다 — bcrypt 를 후보 수만큼 돌리므로 CPU DoS 상한이 필요하다.
2. 후보 0건 → `UnauthorizedException('Credenciales incorrectas')` (전화번호 열거 방지, 기존 메시지 유지).
3. **행마다 개별 검증**: `pinHash` 가 있는 후보에 대해서만 `await bcrypt.compare(pin, v.pinHash)` 를 돌려
   통과한 행들을 `matched` 에 모은다. 첫 행만 검증하는 현재 로직을 완전히 제거한다.
4. `matched.length === 0` → `UnauthorizedException('Credenciales incorrectas')`.
5. `matched.length === 1` → 토큰 발급.
   payload = `{ type: 'vendor', vendorId: m.id, storeId: m.storeId, vendorPhone: phone }`.
   응답 = `{ token, stores: [ { vendorId, storeId, storeName, logoUrl, aliasName } ] }` (기존 필드 형태 유지, 길이 1).
6. `matched.length > 1` (같은 PIN 을 여러 매장에서 쓰는 경우) → **토큰을 발급하지 않고**
   `{ requiresStoreSelection: true, stores: matched.map(...) }` 을 200 으로 반환한다.
   클라이언트는 `storeId` 를 실어 다시 호출한다. 이때도 PIN 재검증을 거치므로 매장 선택이 권한 상승 통로가 되지 않는다.

`getMe(...)` 는 phone 전체 조회를 버리고 `req.user` 의 `vendorId`/`storeId` 로 **정확히 1행**만 복원하도록 바꾼다.
컨트롤러의 `getMe(req.user.phone)` 호출은 `getMe(req.user.vendorId, req.user.storeId)` 로 교체한다.
반환 shape 은 `{ vendors: [v], stores: [ {...} ] }` 로 유지해 앱 파싱을 깨뜨리지 않는다.

로그에 `pin`, `pinHash` 를 남기지 않는다. 실패 사유는 로그에만 구분해 남기고 응답 메시지는 하나로 통일한다.

1. `payload.type !== 'vendor'` → 401 (기존 유지).
2. `typeof payload.vendorId !== 'number' || typeof payload.storeId !== 'number'` →
   `UnauthorizedException('TOKEN_LEGACY_REAUTH')`. **구 토큰(vendorIds 만 있는 토큰)은 통과시키지 않는다.**
   ※ 이것이 배포 직후 기존 로그인 세션을 무효화한다 — 벤더는 재로그인해야 한다. SUMMARY 에 명시할 것.
3. `const vendor = await Vendor.findOne({ where: { id: payload.vendorId, storeId: payload.storeId, isActive: true } })`.
   없으면 `UnauthorizedException('Vendedor inactivo')`.
4. 반환 `{ vendors: [vendor], vendorId: vendor.id, storeId: vendor.storeId, phone: payload.vendorPhone }`.
   `vendors` 를 길이 1 배열로 유지해 4개 컨트롤러의 `.map(v => v.id)` 줄을 무변경으로 살린다.

- `vendor-envios.controller.ts` / `vendor-settlements.controller.ts` / `vendor-notifications.controller.ts`:
  `@Query('storeId', ParseIntPipe) storeId` 를 받은 직후

- `vendor-recepciones.controller.ts`: `createRecepcion` 의 dto 에 storeId 가 없으면
  서비스 호출 전에 `req.user.storeId` 를 기준으로 대상 envío/recepción 이 그 매장 소속인지 확인하도록
