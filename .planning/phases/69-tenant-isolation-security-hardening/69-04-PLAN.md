<objective>
R3(CR-03) 수정은 벤더 토큰을 **단일 매장 scope** 로 좁힌다. 그 전에
"같은 전화번호로 여러 매장에 등록된 벤더가 실제로 몇 명이며, 그들의 PIN 이 매장별로 같은가 다른가"를
**먼저 측정**해야 한다. 되돌리기 어려운 결정(계정 병합/분리·매장 통지)이 여기에 달려 있기 때문이다.

- `pin_hash` 가 **동일**한 조합 → 수정 후에도 같은 PIN 으로 매장 선택만 추가되므로 UX 영향 미미
- `pin_hash` 가 **상이**한 조합 → 수정 후 각 매장 PIN 을 따로 입력해야 한다 → **매장 통지 필요**
- `pin_hash` 가 **NULL** 인 행 → 현재도 로그인 불가(첫 행이 NULL 이면 전체 차단) → 정리 대상 후보

Purpose: 조사 없이 인증 모델을 바꾸면 특정 벤더가 조용히 로그인 불가가 된다. 측정 → 승인 → 실행 순서를 강제한다.
Output: 실측 수치와 영향 벤더 목록이 담긴 `69-VENDOR-PIN-SURVEY.md` + 사용자 승인 기록.

**이 플랜은 읽기 전용이다. 코드·DB 를 변경하지 않는다.**

어떤 UPDATE/DELETE/DDL 도 실행하지 않는다.

Q1 — 다중 매장 phone 전수:
`SELECT phone, count(*) AS filas, count(DISTINCT store_id) AS tiendas, count(DISTINCT pin_hash) AS pins_distintos, bool_or(pin_hash IS NULL) AS tiene_pin_null FROM talleres_vendors WHERE phone IS NOT NULL AND phone <> '' GROUP BY phone HAVING count(DISTINCT store_id) > 1 ORDER BY tiendas DESC, filas DESC;`

Q2 — 그중 PIN 이 갈리는(영향 확정) 조합 상세:
`SELECT v.phone, v.id, v.store_id, v.name, v.is_active, (v.pin_hash IS NOT NULL) AS tiene_pin, v.pin_updated_at FROM talleres_vendors v WHERE v.phone IN (SELECT phone FROM talleres_vendors WHERE phone IS NOT NULL AND phone <> '' GROUP BY phone HAVING count(DISTINCT store_id) > 1) ORDER BY v.phone, v.store_id;`
※ `pin_hash` 원문은 **절대 문서에 옮기지 않는다** — 존재 여부(boolean)와 distinct 개수만 기록한다.

Q3 — 활성 기준 재집계(로그인 경로가 `is_active = true` 만 조회하므로 실질 영향 대상):
`SELECT phone, count(*) AS filas_activas, count(DISTINCT store_id) AS tiendas, count(DISTINCT pin_hash) AS pins_distintos FROM talleres_vendors WHERE is_active = true AND phone IS NOT NULL AND phone <> '' GROUP BY phone HAVING count(DISTINCT store_id) > 1;`

Q4 — 전체 규모 참고:
`SELECT count(*) AS total, count(*) FILTER (WHERE is_active) AS activos, count(*) FILTER (WHERE pin_hash IS NOT NULL) AS con_pin, count(DISTINCT store_id) AS tiendas FROM talleres_vendors;`
