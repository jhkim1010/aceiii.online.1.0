**STEP B — codigoMadreView=true 경로**:

isParentValue=true 경로의 SQL 도 동일하게 처리. 단, `si.product_id = p.id` 가 아닌 child product 기준이어야 함. parent product 로 표시되는 cockpit row 의 MOV 합은 그 parent 의 모든 child variants 의 합 → `si.product_id IN (SELECT id FROM products WHERE parent_id = p.id)` 사용.

isParent 분기 시 다음 형태로 sub-query 변경:
```sql
COALESCE((
  SELECT SUM(si.quantity)::int FROM sale_items si
  JOIN sales smv ON smv.id = si.sale_id
  WHERE smv.activity_type = 'movido'
    AND smv.target_branch_id = pb.branch_id
    AND (:storeId::int IS NULL OR smv.store_id = :storeId::int)
    AND ${isParentValue ? `si.product_id IN (SELECT id FROM products WHERE parent_id = p.id AND status != 'deactivated')` : `si.product_id = p.id`}
), 0)::int AS mov_in,
```
(다른 2 sub-query 동일 패턴.)

**주의**: 위 isParentValue 변수는 JavaScript 변수이므로 SQL 문자열 조립에 사용 — 기존 rowsJoin 변수가 isParentValue 분기 처리하는 패턴 따라가기 (라인 494).
