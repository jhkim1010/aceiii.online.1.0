## TASK-2 — `getOrLoad` 구현 (single-flight)

파일: `api-ventago/src/common/cache/memory-cache.service.ts`

```ts
// key → 진행 중인 loader Promise. TTL 경계에서 동시에 들어온 요청을 하나로 합친다.
private readonly inFlight = new Map<string, Promise<unknown>>();

async getOrLoad<T>(key: CacheKey, ttlMs: number, loader: () => Promise<T>): Promise<T>
```

동작 계약:

1. 유효한 캐시가 있으면 즉시 반환 (loader 미실행)
2. 없고 **같은 key 의 loader 가 이미 진행 중이면 그 Promise 를 공유** (loader 1회 실행)
3. 없고 진행 중도 아니면 loader 실행 → 성공 시 `set` → 반환
4. **loader 가 throw 하면 캐시에 쓰지 않고**, `inFlight` 에서 제거한 뒤 에러를 그대로 전파한다
   (실패를 캐시하면 60초간 장애가 고정된다)
5. 성공·실패 무관하게 `finally` 에서 `inFlight.delete(key)` — **누락하면 영구 누수다**

에러 핸들링은 항상 포함한다. `try/catch/finally` 필수.

## TASK-3 — `CacheKey` 타입으로 storeId 강제

파일 (신규): `api-ventago/src/common/cache/cache-key.ts`

문자열 키를 그대로 받으면 `storeId` 누락을 컴파일러가 못 잡는다. 브랜드 타입으로 막는다.

```ts
export type CacheKey = string & { readonly __cacheKey: unique symbol };

/** 매장 범위 키 — 기본형. prefix 는 도메인, storeId 는 필수. */
export function storeKey(prefix: string, storeId: number, ...parts: (string | number)[]): CacheKey;

/** 전역 키 — storeId 가 없는 것이 **의도임을 선언**해야 한다. 이유를 인자로 받는다. */
export function globalKey(prefix: string, reason: string, ...parts: (string | number)[]): CacheKey;
```

`getOrLoad` / `set` 은 `CacheKey` 만 받는다. 생 문자열은 타입 에러가 난다.
→ "모든 캐시 키에 store_id" 규약이 **문서가 아니라 타입**이 된다.
