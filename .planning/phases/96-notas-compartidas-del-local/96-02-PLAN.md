Design rule for these models: NO `@ForeignKey(() => Store)` / `@BelongsTo(() => Users)` to models
outside this folder. `storeId`/`senderId`/`userId` are plain INTEGER columns (FK constraints live in
the DB). Reason: the offline spec must be able to register only NOTA_MODELS; pulling Users/Store
drags their whole association graph (and the repo's documented model-cycle pitfall). Sender/user
names are loaded by the services with a separate `Users.findAll`.
Every `@Column` MUST have an explicit `type: DataType.X` (union/implicit types crash prod boot) and each `@Column({ ... })` decorator is written on ONE line so the grep check below works.
Global `underscored: true` maps camelCase → snake_case.
