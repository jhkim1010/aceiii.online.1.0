독립 SQL(spotcheck)의 원칙: 서비스의 상수·헬퍼를 쓰지 않고 **다른 형태로** 같은 정의를 쓴다 — 예: 지점은 `LEFT JOIN sales o ON o.id = s.nullified_sale_id AND o.store_id = s.store_id` 후 `COALESCE(o.branch_id, s.branch_id)`(서비스는 상관 서브쿼리), 건수는 `COUNT(*) FILTER (WHERE status <> 'Anulación') - COUNT(*) FILTER (WHERE status = 'Anulación')`(서비스는 SUM(CASE)), 결제수단 칸은 SQL CASE 로 slug 분류(서비스는 TS 함수). 같은 정의를 다른 길로 계산해야 대조가 의미를 갖는다.
웹 대조식(98-08, D-15 ② 의도된 차이): 워치 hoy.total(매장 전체) == getDailySummary(storeId, dia, dia).totalAmount − creditCashAdjustment (getDailySummary 는 sales.service.ts:1292, 지점 필터 없음).
Favor/Crédito 독립 계산(D-15 ①): spotcheck 는 서비스의 slug 분류·favor_auto CTE 를 쓰지 않는다. 결제행은 `SUM(spm.amount) FILTER (WHERE lower(trim(pm.slug)) IN ('favor','saldo-a-favor'))` 처럼 SQL 로 직접 나누고, 자동 상계는 **원장 쪽에서 출발해** `credit_ledger cl JOIN credit_ledger sc ON sc.id = cl.parent_ledger_id AND sc.movement_type = 'sale_credit' AND sc.sale_id = cl.sale_id` (parent 가 바로 그 판매의 sale_credit 인 것) `AND cl.payment_id IS NULL` 을 판매 쪽 `LEFT JOIN sales o ON o.id = s.nullified_sale_id` 의 `COALESCE(o.id, s.id) = cl.sale_id` 로 붙이고 부호는 `(1 - 2 * (s.status = 'Anulación')::int)` 로 준다 — 서비스(parent NOT NULL + CASE)와 다른 길로 같은 정의. favor = 명시 favor 결제행 + 자동 상계, credito = credito 결제행 − 자동 상계.
