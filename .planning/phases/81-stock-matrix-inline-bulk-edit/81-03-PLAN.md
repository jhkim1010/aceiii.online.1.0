<objective>
매트릭스에 **인라인 편집 모드**를 넣는다 — 사용자 요구의 본체.

Purpose: 지금은 셀 하나마다 선택→수정→확인이라 variation 이 많으면 그 횟수만큼 반복해야 한다.
</objective>

<constraints>
- ★ **미저장 입력을 조용히 버리지 않는다**(CODEX C9). 지금 구조는 지점·제품이 바뀌면 상태를
  즉시 초기화한다 — 편집값이 생기면 그게 곧 데이터 손실이다.
  → 변경값이 있으면 확인 후 폐기, 저장 중에는 지점/제품/`Editar` 비활성,
  **새 매트릭스 응답을 기존 입력에 자동 병합하지 않는다.**
- ★ **저장 후 remount 금지**(C11). 현재 `refreshKey` 가 Panel B·C 의 `key` 에 들어가 통째로
  다시 그려진다 — 오늘 없앤 깜빡임이 되살아나고 Panel B 의 페이지·정렬·선택을 잃는다.
  → 커밋 응답으로 Panel C 를 즉시 갱신하고, 재조회는 `key` 가 아니라 명시적 `reload()` 로.
  오늘 넣은 요청 시퀀스 방어를 유지한다.
- ★ **Panel D 를 제거하지 않는다**(C12). 편집 모드에서만 비활성/요약 전환. 제거 여부는
  사용 로그를 본 뒤 별도 단계에서 판단한다 — 지우는 것은 되돌리기 어렵다.
- 편집 불가 셀은 서버가 준 `adjustment.reason` 으로 이유를 표시한다(81-02).
- 행 높이는 Phase 79 규약(30px)을 지킨다 — 입력칸이 행을 밀지 않게 `size=small` + 컴팩트 패딩.
</constraints>

<tasks>
1. 지표 체크박스 줄 오른쪽에 **`Editar`** 체크박스. 지점 미선택이면 비활성 + 사유 툴팁.
2. 켜면 각 셀을 숫자 입력칸으로. 초기값 = 현재 스톡. 아래(또는 셀 안 작은 글씨)에 **Δ** 표시
   (0 이면 표시하지 않음 — 바뀐 것만 눈에 띄어야 한다).
3. 매트릭스 아래 오른쪽에 **`Confirmar`** — 변경된 셀만 모아 `adjust-batch` 로 전송.
   각 항목에 **`expectedStock`(로드 시점 값)** 을 함께 보낸다.
4. 저장 전 요약: 변경 셀 수 · `Σ|diff|` · 최대 단일 `|diff|`. 임계 초과 시 확인 다이얼로그에
   큰 변경 셀 목록과 "변경 전 → 후"(C10). 음수 입력은 항상 차단.
5. 409(기준값 불일치) 응답 처리 — 어느 셀이 왜 어긋났는지 표시하고 **그 값으로 갱신**한 뒤
   사용자가 다시 판단하게 한다. 조용히 재시도하지 않는다.
6. `Editar` 해제·지점 변경·제품 변경 시 폐기 확인.
</tasks>

</verification>
