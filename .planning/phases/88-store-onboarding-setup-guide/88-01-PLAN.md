# 88-01 · W1 — 셋업 가이드 계산기 (v2)

**목표:** 화면을 만들기 전에 **값이 맞는지부터 맞춘다.** 끝나면 `GET /auth/me` 가 요약을,
`GET /setup-guide` 가 상세를 정확히 돌려주고 브라우저 없이 curl 로 검증된다.

**v1 에서 바뀐 것 (전부 88-FINDINGS.md 근거):**
① 시각 비교(5분/1분) **전면 폐기** — 시드 상수 대조로.
② 모듈명 `onboarding` → **`setup-guide`**(기존 공개 가입 OTP 모듈과 충돌).
③ 「새 엔드포인트 금지」 **개정** — `/me` 는 요약, 갱신은 전용 엔드포인트.
④ 읽기 경로에서 **쓰지 않는다**.

## 1. 태스크

### TASK-1 — 마이그레이션 ★ 순서가 안전장치다 (H-1)

> **게이트: 운영 5434 적용을 확인하기 전에는 push 하지 않는다.**
> `Store` 모델에 `setupHiddenAt` 을 추가하는 순간 `me()` 의 `Store.findOne`(`auth.service.ts:947`)이
> 그 컬럼을 SELECT 한다. 컬럼이 없으면 **`/auth/me` 500 → 전 사용자 로그인 불가.**
> push = Jenkins = 배포는 자동이고 운영 마이그레이션은 수동 승인이라 **순서가 뒤집히기 쉽다.**

파일명은 실제 날짜로 — `/^\d{4}-\d{2}-\d{2}/` 를 만족해야 규약 테스트가 로드한다(M-4).
`api-ventago/migrations/2026-09-10-setup-guide.sql`

```sql
SET lock_timeout = '5s';

-- 1) 가이드 영구 닫기 (추가만·nullable)
ALTER TABLE stores ADD COLUMN IF NOT EXISTS setup_hidden_at timestamptz NULL;

-- 2) D-12: 기존 매장에는 보이지 않는다
UPDATE stores SET setup_hidden_at = now() WHERE setup_hidden_at IS NULL;

-- 3) 저장하는 것은 「의도」뿐 (SPEC D-2)
--    branch_id 는 NOT NULL DEFAULT 0 — 매장 단위 단계는 0. FK 를 걸지 않는다(0 은 지점이 아니다).
--    이유: COALESCE 표현식 UNIQUE 는 Sequelize upsert 의 ON CONFLICT 추론을 깨뜨린다(42P10, M-3).
CREATE TABLE IF NOT EXISTS store_setup_steps (
  id            serial PRIMARY KEY,
  store_id      integer NOT NULL,
  branch_id     integer NOT NULL DEFAULT 0,
  step_code     varchar(40) NOT NULL,
  dismissed_at  timestamptz NULL,
  snoozed_until timestamptz NULL,
  completed_at  timestamptz NULL,          -- 한 번 참이면 고정 (SPEC D-3)
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uq_store_setup_steps UNIQUE (store_id, branch_id, step_code)
);

-- 4) append-only 원장 — 계측 전용(TTFV·이탈 단계)
CREATE TABLE IF NOT EXISTS store_setup_events (
  id          bigserial PRIMARY KEY,
  store_id    integer NOT NULL,
  branch_id   integer NOT NULL DEFAULT 0,
  user_id     integer NULL,
  step_code   varchar(40) NOT NULL,
  event       varchar(20) NOT NULL,   -- viewed|started|completed|dismissed|undismissed|hidden|unhidden
  occurred_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS ix_store_setup_events_store_step
  ON store_setup_events (store_id, step_code, occurred_at DESC);
-- 완료 이벤트는 단계당 1건 — 4워커 동시 INSERT 중복 방지 (H-4)
CREATE UNIQUE INDEX IF NOT EXISTS uq_store_setup_events_completed
  ON store_setup_events (store_id, branch_id, step_code) WHERE event = 'completed';

-- 5) 운영 owner 이전 — 누락 시 앱(coolsistema)이 permission denied 500
DO $$
BEGIN
  IF EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'coolsistema') THEN
    ALTER TABLE store_setup_steps  OWNER TO coolsistema;
    ALTER TABLE store_setup_events OWNER TO coolsistema;
    ALTER SEQUENCE store_setup_steps_id_seq  OWNER TO coolsistema;
    ALTER SEQUENCE store_setup_events_id_seq OWNER TO coolsistema;
  END IF;
END $$;
```

- `w4-exempt` 주석을 **쓰지 않는다** — 새 테이블 문장은 `targetsNewTable()` 이 자동 면제하고,
  주석은 같은 파일의 `stores` ALTER·UPDATE 까지 **통째로 면제**시킨다(M-4).
- [ ] 실행 전 **`SELECT count(*) FROM stores;`** 로 `UPDATE` 영향 행 수를 제시하고 승인받는다
- [ ] 로컬 5432 — 사용자가 Mac 에서: `psql -p 5432 -d ventago -f api-ventago/migrations/2026-09-10-setup-guide.sql`
- [ ] 운영 5434 — 승인 후 SSH 실행 → **적용 확인 후에만 push**
- [ ] `./.planning/intel/db-schema.regen.sh` 갱신 커밋

### TASK-2 — `SetupGuideService.resolve()` — 술어는 **시드 상수 대조** (C-1·C-2)

```sql
-- $1 store_id, $2 branch_id(0=매장단위), $3 SaleActivityType.SALE
SELECT
  s.setup_hidden_at,
  CASE WHEN s.setup_hidden_at IS NOT NULL THEN NULL ELSE (       -- 숨긴 매장은 술어를 평가하지 않는다(H-3)
    EXISTS (SELECT 1 FROM products p
             WHERE p.store_id = s.id AND COALESCE(p.is_generic,false) = false)
  ) END AS load_products,
  CASE WHEN s.setup_hidden_at IS NOT NULL THEN NULL ELSE (
    EXISTS (SELECT 1 FROM price_types pt WHERE pt.store_id = s.id)  -- 시드가 없다 → 존재만으로 참
  ) END AS set_prices,
  CASE WHEN s.setup_hidden_at IS NOT NULL THEN NULL ELSE (
    EXISTS (SELECT 1 FROM payment_methods m                          -- 시드 3개에서 벗어났는가
             WHERE m.store_id = s.id
               AND (m.slug NOT IN ('efectivo','tarjeta-debito','mercadopago')
                 OR m.is_active = false))
  ) END AS check_payment_methods,
  CASE WHEN s.setup_hidden_at IS NOT NULL THEN NULL ELSE (
    EXISTS (SELECT 1 FROM branch_agents a
              JOIN branches b ON b.id = a.branch_id AND b.store_id = s.id   -- 테넌트 경계(H-2)
             WHERE a.branch_id = $2 AND a.last_seen_at IS NOT NULL)
  ) END AS connect_printer,
  CASE WHEN s.setup_hidden_at IS NOT NULL THEN NULL ELSE (
    EXISTS (SELECT 1 FROM sales sa                                   -- 매장 단위(M-1)
             WHERE sa.store_id = s.id
               AND sa.activity_type = $3
               AND sa.nullified_by_sale_id IS NULL)
  ) END AS first_sale
FROM stores s WHERE s.id = $1;
```

- [ ] **시각 비교식을 쓰지 않는다.** 시드 slug 3개는 `storeTemplate.service.ts:507,514,521` 에서
      **상수로 import** 한다 — SQL 에 문자열을 다시 적으면 시드가 바뀔 때 조용히 갈라진다
- [ ] `create_store`·`create_branch`·`open_box_terminal` 은 **항상 참**(쿼리 없음, SPEC D-6)
- [ ] `activity_type` 은 `SaleActivityType.SALE` 을 **파라미터로** 넘긴다(리터럴 금지)
- [ ] 완료 고정(D-3): `store_setup_steps.completed_at` 이 있으면 술어가 false 여도 완료
- [ ] 캐시: **`storeKey('setup', storeId, branchId)`** + `getOrLoad` (`get`/`set` 은 Phase 85 W8 에서 private 봉인 — M-2). TTL **10초**
- [ ] `branchId` 는 **반드시 `branches WHERE id=? AND store_id=?` 로 검증한 값만** 술어에 넣는다(H-2)
- [ ] `resolve()` 전체를 `try/catch` — 실패 시 예외를 던지지 않고 `null` 을 돌려준다(H-4)
