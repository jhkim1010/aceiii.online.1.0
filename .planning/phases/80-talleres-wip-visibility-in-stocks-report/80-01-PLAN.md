지점 분배는 DB 에 없는 값을 계산해 내는 것이므로(FINDINGS F1), 필드명과 메타데이터가

<constraints>
- **기존 응답 필드를 건드리지 않는다.** `/api/reports/*` 는 Flutter 앱도 쓴다(추가만).
- **cohort 단위로 계산한다** — 열린 envío 하나 = `(lote_id, etapa_id, pending_quantity)` 하나.
  로트당 "현재 공정" 하나를 뽑으면 분할 발송·rework 에서 조용히 틀린다(CODEX C2).
- `routing_path` 는 기존 `checkRoutingCanonical()` 과 **같은 조건**으로 검증한다. JSON 길이와
  `order` 만 믿지 않는다. 경로에 없는 etapa 는 그 cohort 만 `UNKNOWN`.
- **WIP CTE 는 표시 grain 당 1행으로 먼저 집계**하고 메인 쿼리에서는 `MAX()` 로 읽는다.
  그대로 JOIN 후 `SUM` 하면 stocks 원장 행 수만큼 곱해진다(CODEX C7).
- 제품 모집단은 **기존 `groupLeafIds` 와 동일**해야 한다. variante 뷰=leaf, CodigoMadre 뷰=family
  정규화 후 집계. `wip.product_id = p.id` 단순 조인 금지(CODEX C6).
- superadmin 전 매장 뷰에서 **매장 경계를 넘어 나누지 않는다** — 매장별로 나눈 뒤 합산.
- 집계 조건에 `pending_quantity > 0` 를 포함한다.
</constraints>

<tasks>
1. `wip-allocation.ts` (순수 함수) 를 만든다:
   - `allocateEqually(total: number, branchIds: number[]): Map<number, number>`
     `base = floor(total/N)`, `remainder = total % N`, **`branch_id ASC` 앞쪽 remainder 개에 +1**.
     `N === 0` 이면 빈 Map + 호출부가 `UNALLOCATABLE` 로 처리.
   - 렌더·DB 없이 검증되도록 둔다(합계 보존 테스트는 80-04).
2. WIP 집계 CTE 를 만든다. cohort → 제품 단위로 접으면서 다음을 산출:
   - `estimatedWipTotalQty = max(total_quantity − stocked_quantity, 0)`
   - `inWorkshopQty` = 열린 envío(`PENDING`/`PARTIAL`, `pending_quantity > 0`) 합
   - `unassignedInProcessQty = estimatedWipTotalQty − inWorkshopQty` (★ `no_iniciado` 라는 이름 금지 —
     실제로는 미착수·공정 사이 대기·재고 미반영·불량 판정 대기가 섞인다)
   - `pendingInventoryQty` = 최종 수령했으나 `inventory_status='PENDING'` 인 수량 (별도)
   - `estimatedReworkQuantity` = rework envío 분 (WIP 에 포함하되 **분리 반환**)
3. ETA 를 cohort 별로 판정해 제품 단위로 접는다:
   - 최종 공정 cohort → `estimatedReadyDate = due_date`, `etaBasis = FINAL_STAGE_DUE`
   - penúltima → 날짜를 주더라도 이름은 **다음 이정표**(`etaBasis = PENULTIMATE_STAGE_DUE`)
   - 그 외 / routing 비정상 → `UNKNOWN`
   - `due_date < 오늘` → `etaStatus = OVERDUE` + 원래 날짜 보존
   - 제품 단위: `etaKnownQty` / `etaUnknownQty` / `etaStatus: KNOWN|PARTIAL|UNKNOWN|OVERDUE`
     ★ 한 cohort 라도 모르면 **확정 날짜처럼 보이면 안 된다** → `PARTIAL`
4. 지점 분배: `branchId` 가 지정되면 `allocateEqually` 결과를 `estimatedBranchWipQty` 로.
   메타 동봉: `allocationMethod: 'EQUAL_ESTIMATE'` · `allocationBranchCount` · `allocationAsOf` ·
   `isEstimated: true`. **TOTAL 은 원본 합계**를 쓰고 분배값을 재합산하지 않는다.
   대상 지점 = 해당 store 의 **활성 지점**(Panel A 와 같은 정의).
5. 정렬 화이트리스트에 WIP 컬럼을 넣되 **권한 검사와 함께**(80-02 에서 연결).
</tasks>
