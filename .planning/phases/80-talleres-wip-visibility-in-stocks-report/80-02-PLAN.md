<objective>
WIP 정보를 **서버가 필드 단위로** 막는다.

Purpose: 이 화면의 기존 사용자는 `reporte-stocks` 권한으로 들어온다. 여기에 WIP 필드를 무조건
실으면 프론트에서 열을 숨겨도 **네트워크 응답에 그대로 보인다**. 반대로 엔드포인트 전체에 새
guard 를 걸면 기존 사용자가 기본 표까지 잃는다(CODEX C4). 그래서 "열 숨김" 이 아니라
"필드 부재" 로 만든다.
</objective>

<constraints>
- 기존 `@FunctionGuard('reporte-stocks','read')` 는 **그대로 둔다**(기본 표 접근권).
- 새 slug 는 시드에 남아 되돌리기 번거롭다 — 이름을 처음에 확정할 것.
- `getItems()` 와 `getItemsForExport()` 는 같은 구현을 공유한다 → **한 곳에서** 판정.
- 캐시를 쓰는 경로가 있으면 캐시 키에 권한 여부를 포함한다(권한자 응답이 비권한자에게 재사용되면 유출).
</constraints>

<tasks>
1. `functions.seed.ts` 에 항목 추가 — 예: `Reporte Stock WIP` /
   `'[Reportajes] Ver cantidades en producción y fecha estimada'` → slug 확인 후 고정.
2. 컨트롤러에서 **요청자의 WIP 권한 여부**를 판정해 서비스에 `includeWip: boolean` 로 넘긴다.
   (엔드포인트 자체를 막지 않는다.)
3. 서비스: `includeWip === false` 면
   - WIP CTE·조인 자체를 **생략**(불필요한 비용도 없앤다)
   - 응답 객체에서 WIP 필드를 **넣지 않는다**(null 도 아니고 키 자체가 없음)
   - `sortBy` 가 WIP 컬럼이면 **거부**(기본 정렬로 대체하지 말고 400 — 조용한 대체는 "왜 정렬이
     안 되지" 를 만든다)
4. export 경로(`getItemsForExport` → Excel/PDF)에도 같은 플래그를 전달하고 **컬럼 자체를 제외**.
5. 프론트 CASL 에 같은 slug 를 연결한다(열 렌더 여부는 80-03).
</tasks>

<verification>
- 권한 없는 사용자로 `/reports/stocks-cockpit/items` 직접 호출 → 응답 JSON 에 WIP 키 없음
- 권한 없는 사용자로 `sortBy=wip...` → 400
- 권한 없는 사용자의 PDF/Excel → WIP 컬럼 없음
- 권한 부여 후 즉시 노출(재로그인 불필요한지 확인 — 필요하면 문서화)
</verification>

- 기존 Stocks 사용자의 기본 표는 그대로
</success-criteria>
