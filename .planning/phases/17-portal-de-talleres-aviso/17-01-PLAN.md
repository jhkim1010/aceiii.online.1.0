   - vendor가 없으면 `UnauthorizedException('Vendedor inactivo')`
   - `return { vendors, phone: payload.vendorPhone }` — req.user에 할당

4. **vendor-auth.service.ts** — 로그인 서비스 (per D-03, D-04, D-06):
   - `vendorLogin(phone: string, pin: string)`:
     - `Vendor.findAll({ where: { phone, isActive: true }, include: [{ model: Store, attributes: ['id', 'name', 'logoUrl', 'aliasName'] }] })`
     - vendors가 비어있으면 `UnauthorizedException('Vendedor no encontrado')`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flutter app → API | Untrusted vendor input (phone, PIN) crosses to backend |
| Vendor JWT → user JWT | Two separate auth realms must not cross-access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Spoofing | vendor-auth login | mitigate | bcrypt PIN hash comparison, no plaintext PIN storage |
| T-17-02 | Elevation | vendor-jwt strategy | mitigate | payload.type === 'vendor' check prevents user JWT reuse on vendor endpoints |
| T-17-03 | Information Disclosure | vendor login error | mitigate | Generic error messages, no phone enumeration (same error for invalid phone/PIN) |
| T-17-04 | Tampering | vendor_notifications | accept | Notifications are read-only for vendors, write-only for backend triggers |
</threat_model>
