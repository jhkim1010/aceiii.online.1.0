<objective>
웹 표면의 기본 방어를 세운다. 보고서의 Medium 2건 + Next.js 버전이다.

**보안 헤더는 애플리케이션에도 프록시에도 없다.** 보고서는 "프록시에서 설정되는지 추가 검증
필요"라고 유보했는데, 운영 실측 결과 실제로 없다:

```
curl -sI https://ventago.coolsistema.com  →  HTTP/2 307  (보안 헤더 0건)
```

Purpose: CSP 가 없으면 XSS 한 건이 전체 세션 탈취로 번진다. 이 앱은 POS 라
세션 하나가 매장의 판매·재고 권한 전체를 의미한다.
</objective>

<constraints>
- **CSP 를 한 번에 엄격하게 걸지 마라.** 이 앱은 외부 리소스가 많다 — MinIO 이미지,
  PostHog, MercadoPago 결제 위젯, ApexCharts. 처음부터 `default-src 'self'` 로 조이면
  결제·차트·이미지가 통째로 죽는다.
  **`Content-Security-Policy-Report-Only` 로 먼저 관찰**하고 위반 목록을 확인한 뒤 강제로 전환한다.
- Next.js 업데이트는 **13.x 안에서 최소 13.5.9 이상**을 우선 검토한다.
  14/15 로 올리는 것은 Pages Router 호환성·빌드 파이프라인 영향이 커 별도 판단이다.
  CLAUDE.md 의 「npm workspaces 주의사항」(webpack alias, apexcharts 매핑)이 깨지기 쉽다.
- 이 프로젝트에는 `middleware.ts` 가 없다. 해당 CVE 의 직접 영향은 확인되지 않았다 —
  **업데이트 근거를 "지금 뚫려 있다"로 쓰지 마라.** 지원 버전 유지가 근거다.
</constraints>

<tasks>
1. `next.config.js` 에 `headers()` 를 추가한다:
   - `Strict-Transport-Security` (운영 HTTPS 확인 후)
   - `X-Frame-Options: DENY` 또는 CSP `frame-ancestors 'none'`
   - `Referrer-Policy: strict-origin-when-cross-origin`
   - `Permissions-Policy` — 카메라(바코드 스캔) 사용 여부를 먼저 확인하고 필요한 것만 허용
   - `Content-Security-Policy-Report-Only` — 초안
2. 개발·스테이징에서 브라우저 콘솔의 CSP 위반을 수집한다. 결제·차트·이미지 경로를 반드시 밟는다.
3. 위반 목록을 반영해 CSP 를 확정하고 `Report-Only` 를 해제한다.
   **위반이 남은 채로 강제 전환하지 마라.**
4. Next.js 를 13.5.x 최신 패치로 올린다. 빌드 + 주요 화면 회귀 확인.
5. API 오류 응답 표본을 훑어 내부 예외 메시지가 외부로 나가는 곳을 찾는다.
   외부에는 일반화된 코드만, 상세는 서버 로그로 보낸다.
</tasks>
