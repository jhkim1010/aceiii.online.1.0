<objective>
superadmin 관리자 앱이 **원문 비밀번호를 단말에 장기 보존**하는 것을 없앤다.

```dart
static const savedPass = 'admin_saved_pass';          // secure_storage.dart:10
await _storage.write(StorageKeys.savedPass, password); // auth_controller.dart:123
```

`logout()` 은 토큰만 지우고 자격증명은 남긴다(주석에 의도 명시 — 지문 재로그인용).
macOS 는 `useDataProtectionKeyChain: false` 라 강화 키체인 보호도 꺼져 있다.

**이건 superadmin 계정이다.** 전 매장에 대한 권한이다. 단말 하나가 털리면 범위가 전체다.
</objective>

<constraints>
- **`autonomous: false`** — 인증 흐름 변경이라 착수 전 확인. 잘못 건드리면 관리자가 앱에 못 들어간다.
- **지문 로그인을 없애는 것으로 해결하지 마라.** 그건 기능 제거이지 보안 개선이 아니다.
  사용자가 매번 비밀번호를 치게 만들면 더 약한 비밀번호를 쓰게 된다.
- `useDataProtectionKeyChain: false` 는 **의도적 우회다.** 주석에 이유가 있다 —
  비-sandbox macOS 빌드에서 entitlement 없이 쓰면 `errSecMissingEntitlement(-34018)` 로 실패한다.
  그냥 `true` 로 바꾸면 저장이 통째로 깨진다. **서명·entitlement 설정을 먼저 해결해야 한다.**
  그게 이번 범위에서 감당 안 되면 현 설정을 유지하되 저장 내용을 줄이는 쪽으로 간다.
- 서버 측에 refresh token 발급·회수 경로가 없으면 백엔드 작업이 동반된다. 먼저 확인할 것.
</constraints>

<tasks>
1. 서버에 refresh token 흐름이 있는지 확인한다. 없으면 백엔드 범위를 먼저 산정한다
   (발급·회전·회수·만료. 회수 경로 없는 refresh token 은 원문 비밀번호와 크게 다르지 않다).
2. 지문 재인증을 **refresh token 기반**으로 바꾼다. 저장 대상에서 원문 비밀번호를 제거한다.
3. 로그아웃 정책을 명시적으로 정한다 — 지금은 "토큰만 삭제, 자격증명 유지"가 주석에만 있다.
   사용자에게 보이는 동작으로 만들거나(예: "이 기기에서 로그아웃" vs "기기에서 잊기"),
   기본을 전체 삭제로 바꾼다. **암묵적으로 남기지 않는다.**
4. macOS keychain entitlement 를 해결할 수 있는지 조사한다.
   가능하면 `useDataProtectionKeyChain: true` 로 되돌린다. 불가능하면 그 사실과 이유를 기록한다.
5. 기존 저장분 마이그레이션 — 업데이트 시 `admin_saved_pass` 를 **삭제**한다.
   코드에서 쓰지 않게만 바꾸면 이미 깔린 단말에 원문이 계속 남는다.
</tasks>

<verification>
- 로그인 → 앱 종료 → 지문으로 재로그인 성공(기능 유지).
- 단말 저장소에 `admin_saved_pass` 키가 **없다**(기존 설치분도 업데이트 후 사라진다).
- 서버에서 refresh token 회수 시 해당 단말이 재로그인하지 못한다.
- 로그아웃 동작이 문서화된 대로다.
</verification>
