<objective>
**edge-agent 배포 차단 조건을 해소한다.** 지금 뚫려 있는 게 아니라, 이 상태로 배포하면 뚫린다.

`edge-agent` 는 아직 어디에도 배포되지 않았다(운영 컨테이너 없음, CI 빌드 워크플로 없음).
그래서 이 플랜은 사고 대응이 아니라 **출시 전에 반드시 통과해야 할 관문**이다.
Wave C 에서 예정돼 있던 HMAC 강화(`server.js:17` 주석)와 같은 자리다.

세 결함이 서로를 증폭한다 — 무인증 접근(C1)으로 미러를 통째로 받고, 거기에 bcrypt 해시가
들어 있고(H1), 신원은 검증되지 않은 토큰으로 정해진다(C2). 하나만 막으면 나머지가 남는다.
</objective>

<constraints>
- **`autonomous: false`** — 착수 전 사용자 확인. 오프라인 판매 흐름은 매장 영업에 직결되고,
  인증을 잘못 걸면 매장이 오프라인일 때 판매 자체가 막힌다. 설계 합의가 먼저다.
- **오프라인 동작이 목적이라는 점을 잊지 마라.** 클라우드가 끊긴 상태에서도 판매가 되어야 한다.
  "서버에 물어봐서 인증"은 이 요구를 깨뜨린다. edge 가 **자체적으로** 검증할 수 있어야 한다.
- 기존 오프라인 판매 E2E(`26ee432`, `7bda05f` 에서 검증됨)를 깨뜨리지 않는다.
- print-agent 가 edge print 게이트웨이로 failover 하는 경로(`/api/offline/print/*`)가 있다.
  인증을 걸면 그쪽도 같이 바뀌어야 한다 — 한쪽만 고치면 프린터가 죽는다.
</constraints>

<tasks>
1. **바인딩 제한** — `app.listen(cfg.port)` 에 host 를 준다. 기본값은 루프백,
   LAN 사용이 필요하면 설정으로 명시하게 한다(기본이 안전, 확장은 선택).
   CORS `*` 도 허용목록으로 좁힌다.
2. **인증 미들웨어** — 헬스체크를 제외한 전 라우트에 적용한다.
   오프라인에서도 검증 가능한 방식이어야 한다:
   - 방안 A: edge 등록 시 서버가 발급한 **공유 비밀로 HMAC** 서명 검증 (Wave C 예정안)
   - 방안 B: 서버 JWT 의 **공개키 검증**(RS256 전환 필요 — 서버 측 변경 동반)
   어느 쪽을 쓸지 **먼저 결정한다.** 추측으로 고르지 마라.
3. **신원 결정 경로 교정** — `decodeJwtPayload` 의 미검증 payload 를 신원으로 쓰지 않는다.
   검증을 통과한 세션에서만 `userId` 를 취한다. 요청 본문·헤더의 사용자 식별값은 신뢰하지 않는다.
4. **해시 미러 제거** — `mirror_rows` 의 `users` 에서 `password` 를 빼고 동기화한다.
   오프라인 로그인을 유지해야 한다면 해시를 그대로 두지 말고 대안을 설계한다
   (예: 단말 바인딩 PIN, 짧은 보존 기간, 접근통제). **여기는 설계 결정이 필요하다.**
5. **로그인 시도 제한** — 계정·IP 단위 rate limit + 연속 실패 시 지연/잠금.
   실패 로그에서 이메일을 마스킹한다(현재 `email=${email}` 원문 기록).
6. **미러 조회 라우트 보호** — `GET /api/offline/table/:key` 가 임의 테이블을 반환한다.
   허용목록 방식으로 좁히고 인증을 요구한다.
</tasks>

<verification>
- 기본 설정으로 기동 시 **다른 호스트에서 접근되지 않는다**(같은 LAN 의 다른 기기로 실측).
- 인증 헤더 없이 `/api/offline/table/users` 호출 → 401/403.
- 위조한(서명 없는) 토큰으로 `/api/offline/sales` 호출 → 거부.
- 미러에 `password` 필드가 존재하지 않는다.
- 오프라인 로그인 연속 실패 → 제한이 걸린다. 로그에 이메일 원문이 없다.
- **오프라인 판매 E2E 가 여전히 통과한다** — 클라우드 차단 상태에서 판매 생성 → outbox 적재
  → 복구 후 push 성공.
- print-agent edge failover 경로가 여전히 동작한다.
</verification>
