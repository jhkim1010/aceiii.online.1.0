<objective>
인증 복원 구간의 흰 화면 번쩍임을 없앤다. **차단 자체는 보안 요구사항이므로 유지한다.**

`AuthGuard.tsx:42` 가 인증 확인 전 `fallback` 을 렌더하는 것은 옳다 —
제거하면 보호 페이지가 순간 노출된다(71-FINDINGS F7). 바꿀 것은 fallback 의 **모양**뿐이다.

Purpose: 로그인 직후·새로고침 시 흰 화면 → 앱 화면으로 튀는 구간을 없앤다.
71-02 로 설정이 첫 페인트부터 적용되므로, 이제 대기 화면도 같은 테마 배경을 쓸 수 있다.
</objective>

<constraints>
- **보호 콘텐츠를 렌더하지 않는다는 성질을 절대 바꾸지 마라.** 이건 UX 개선이 아니라 보안 경계다.
  "잠깐 보였다 사라지는" 것도 노출이다.
- 사이드바처럼 보이는 가짜 UI 를 만들지 않는다. 인증 결과에 따라 사라질 구조를 미리 그리면
  오히려 변화가 커진다.
- 스피너는 **지연 표시**한다(예: 300ms 이후). 대부분의 인증 확인은 그보다 빨라
  스피너가 아예 나타나지 않는 것이 정상이다. 짧게 번쩍이는 스피너가 흰 화면보다 나을 것 없다.
</constraints>

<tasks>
1. 인증 대기 셸 컴포넌트를 만든다 — `minHeight: 100vh`, `bgcolor: 'background.default'`,
   중앙 정렬. MUI 테마 값을 쓰므로 다크/라이트가 자동으로 맞는다.
2. 스피너를 지연 표시로 감싼다. 지연 이전에는 배경만 있는 상태.
3. `_app.tsx` 가 `AuthGuard` 에 넘기는 `fallback` 을 이 셸로 교체한다.
   기존 `Spinner` 를 다른 곳에서도 쓰고 있으면 그 사용처는 건드리지 않는다.
4. `guestGuard` 경로도 같은 처리가 필요한지 확인한다 — 로그인 화면 진입에도 같은 번쩍임이 있으면
   동일하게 적용한다.
</tasks>

<verification>
- 다크 모드 상태에서 새로고침 → **흰 화면 구간이 없다**(배경이 계속 어둡다).
- 인증이 빠를 때 스피너가 보이지 않는다.
- 로그아웃 상태로 보호 URL 직접 진입 → 보호 콘텐츠가 한 프레임도 보이지 않고 로그인으로 이동한다.
  (이게 깨지면 즉시 되돌린다 — 보안 회귀다.)
