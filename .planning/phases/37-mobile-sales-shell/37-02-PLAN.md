<objective>
Build the Phase 37 backend read/write endpoints: `GET /mobile/catalog`, `GET /mobile/stock/:productId`,
`POST /mobile/sales`. All routed through `MobileScopeGuard` (Wave 1). The catalog/stock reads are cached
(D-04) to protect the PG pool; the sale path DELEGATES to `SuspendedSalesService.create` (D-13) — it creates
a suspended sale, never a confirmed `Sale`, so Caja/daily revenue are untouched and stock is only reserved
(`type:'suspend'`). Also wire the desktop arrival notification (UI-D4) by emitting the already-existing
`suspended-sale:changed` socket event and enhancing the desktop 보류 list with a toast + pending badge.

Purpose: A vendedor scans/searches, sees stock across their store's branches (STOCK-READ = all branches,
D-14), fills a matrix, and "Mandar a Caja" drops a suspended sale into the desktop queue. The desktop
operator restores + charges it (out of scope). Mobile NEVER touches Caja.

Output: MobileCatalogService, MobileStockService, MobileSalesService (thin — delegates), their controllers,
the create-sale DTO, MobileModule extension, the desktop notification enhancement, a pool-monitoring script,
and Jest specs (including a hard assertion that sales-create.service is NOT called).

CRITICAL REUSE MANDATES:
- `POST /mobile/sales` → `SuspendedSalesService.create(dto, userId)`. NEVER import or call salesCreateService.
- Always pass an explicit `branchId` (the vendedor's SELL branch). coolsistema has 2 branches → if branchId
  is null, `resolveBranchId`→null→`recordReservationMoves` silently SKIPS the reservation (Pitfall 3/6).
- `variantQuantities` keys are `${colorId}-${sizeId}` — identical format used by web + DTO + service. Do NOT reinvent.
- The `suspended-sale:changed` socket event + the desktop `useSuspendedSaleSocket` hook ALREADY exist. Reuse them.
</objective>
