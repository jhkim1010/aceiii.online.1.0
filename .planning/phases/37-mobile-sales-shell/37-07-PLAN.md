<objective>
Build the POS web side of Fichaje: a global Ctrl+V fullscreen QR overlay (for the caja secondary monitor,
auto-refreshing at store-TZ midnight), the `reportes/asistencia` monthly report page (per-seller worked hours +
open-session warning + admin edit modal via PATCH /attendance/:id), and a small admin panel to revoke a
revendedor's store authorization (DELETE /attendance/reseller-auth/:id).

Purpose: The caja desktop displays the daily QR (backend GET /attendance/qr, desktop-gated in 37-06) so sellers
scan it; managers review monthly hours and correct missed punches.

Output: 2 SWR hooks, the AttendanceQrOverlay + Ctrl+V wiring in UserLayout, the report page (code-split) + view
+ edit modal + reseller-auth revoke panel. All ESLint-clean.

CONSTRAINTS (project rules):
- ESLint blocks the build on warnings — newline-before-return, lines-around-comment, no-unused-vars.
- Use `apiConnector` (`.remove()` NOT `.delete()`); PATCH via `apiConnector.patch` (exists at api.service.ts:177 — do NOT use put).
- Report page MUST be `next/dynamic(() => import(...), { ssr: false })` (code-splitting rule).
- QR rendering uses `qrcode.react` (already a dependency); hotkeys use `react-hotkeys-hook` (already used in UserLayout).
- Reference data via SWR hooks (src/hooks/api/), 5-min dedup — but the QR hook must refresh at midnight, not dedup-stale.
</objective>
