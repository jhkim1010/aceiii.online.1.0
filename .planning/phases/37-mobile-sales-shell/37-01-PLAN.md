<objective>
Build the Phase 37 backend authentication + scope-enforcement layer: the `mobile_sessions`
table, the `MobileScopeGuard`, and `POST /mobile/auth/login` (PIN auth, UI-D3) / `GET /mobile/me`.
This is the security foundation — every later `/mobile/*` endpoint routes through `MobileScopeGuard`.

Purpose: Enforce scope 100% on the backend (D-02). A vendedor sees/sells only their own branch;
URL parameter tampering is impossible. Mobile sessions are separate from desktop `active_sessions`
(D-06) so a vendedor can run desktop POS and mobile simultaneously.

Output: 3 migrations (mobile_sessions, users.mobile_pin, vendedor user_branches backfill),
`MobileSession` model, `MobileScopeGuard`, `MobileAuthService`, `MobileAuthController`, `MobileModule`,
and Jest specs. The `mobile.access` function seed + `user_branches.mobile_terminal_id` column already
exist from the merged foundation slice — do NOT recreate them.

DECISION — scope is read from the DB (mobile_sessions), NOT from the JWT payload. The shared
`JwtStrategy.validate()` discards the payload and returns only DB `Users` (verified). Adding scope
claims to the JWT would NOT reach `req.user`, and editing the shared strategy would regress desktop.
Therefore MOBILE-A-03's `mobileSessionToken` is returned in the login response body and sent back on
every request via the `x-mobile-session-token` header (symmetric to the existing `x-session-token`
of SessionGuard). `MobileScopeGuard` looks the session up there. This is the authoritative mechanism.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile client → /mobile/auth/login | untrusted credentials + deviceFingerprint |
| mobile client → /mobile/* | untrusted `x-mobile-session-token` + query params (?branchId/?storeId) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-01 | Elevation of Privilege | MobileScopeGuard / ?branchId= tampering | mitigate | Guard cross-checks query branchId/storeId against session.scopeBranchIds/scopeStoreIds → 403 SCOPE_VIOLATION (criterion 4) |
| T-37-02 | Spoofing | mobile session token reuse across devices | mitigate | UNIQUE(user_id, device_fingerprint) + UNIQUE(active_session_token); re-login rotates token → old 401 MOBILE_SESSION_EXPIRED |
| T-37-03 | Denial of Service | mobile login killing desktop active_sessions | mitigate | mobile_sessions is a separate table; MobileAuthService NEVER calls SessionService.createSession (D-06) |
| T-37-04 | Tampering | SQL injection via scope IN() arrays | mitigate | Sequelize parameterized queries + INT[] typed columns; no raw string concatenation |
| T-37-05 | Information Disclosure | vendedor with no scope reading data | mitigate | login rejects empty scope 401 VENDEDOR_SCOPE_NOT_DEFINED before any token is issued |
| T-37-06 | Repudiation | PIN brute force | accept | beta = 2 known users; MVP has no lockout. Revisit if vendedor count grows (D-11). PIN is bcrypt-hashed. |
</threat_model>
