**영향 범위가 2026-05-21 진단보다 넓어졌다.** 당시엔 store 6 의 16행만이었으나 지금은 **store 6·9·10·11 에 걸쳐 30행 이상**이다. 즉 `Añiadir gasto` 는 ACE(9) 를 포함한 **여러 매장에서 동시에 발생 중**이다.

### 9-B. ★ 마이그레이션 파일의 전제가 낡았다 — 그대로 실행 금지

`26-05-reconcile-prod.sql` 헤더는 2026-05-21 PG10 진단 기준이며 다음을 전제한다:

- "store_id=6 가 16건" → **틀림.** 지금은 4개 매장 30행+
- "기존 expenses 데이터 0건" → **검증 필요.** 3개월 지났으므로 gasto 가 쌓였을 가능성이 크다
- 검증 쿼리의 `should equal 16` 하드코딩 → 이제 무의미

실행 시 **실패할 수 있는 지점 2곳**:

1. `26-01` 의 `CREATE UNIQUE INDEX uq_expense_cat_root_name (store_id, name) WHERE parent_id IS NULL` — 같은 매장에 **동명 루트 카테고리가 있으면 인덱스 생성이 실패**하고 트랜잭션 전체가 롤백된다. (store 9 에 `Agua Yihasu`/`Agua`, store 6 에 `general`/`Generales` 처럼 유사명이 보이나 완전 동일은 아직 미확인)
2. `26-03` 의 `FK fk_expenses_category` — `expenses.category_id` 가 **존재하지 않는 카테고리 id 를 가리키는 행이 하나라도 있으면 FK 추가 실패**.

### 9-C. 선행 점검 SQL (read-only, 승인 불필요)

```bash
ssh jhkim-server "sudo -u postgres psql -p 5434 -d ventago" <<'SQL'
-- A. 루트 동명 중복 (0행이어야 26-01 통과)
SELECT store_id, name, COUNT(*) FROM expense_categories
 WHERE parent_id IS NULL GROUP BY store_id, name HAVING COUNT(*) > 1;

-- B. 자식 동명 중복 (0행이어야 통과)
SELECT store_id, parent_id, name, COUNT(*) FROM expense_categories
 WHERE parent_id IS NOT NULL GROUP BY store_id, parent_id, name HAVING COUNT(*) > 1;

-- C. 백필 영향 규모
SELECT COUNT(*) AS total,
       COUNT(*) FILTER (WHERE path = '')            AS path_empty,
       COUNT(*) FILTER (WHERE parent_id IS NULL)     AS roots,
       COUNT(*) FILTER (WHERE parent_id IS NOT NULL) AS children
  FROM expense_categories;

-- D. orphan parent_id (있으면 백필 후에도 path 가 빈 채 남는다)
SELECT c.id, c.store_id, c.parent_id FROM expense_categories c
  LEFT JOIN expense_categories p ON p.id = c.parent_id
 WHERE c.parent_id IS NOT NULL AND p.id IS NULL;

-- E. expenses 현황 — '0건' 전제가 아직 유효한가
SELECT COUNT(*) AS rows_total,
       COUNT(*) FILTER (WHERE category_id IS NOT NULL)              AS with_category,
       COUNT(*) FILTER (WHERE expenses_subcategory_id IS NOT NULL)  AS with_old_subcat
  FROM expenses;

-- F. FK 위반 예정 행 (0이어야 26-03 통과)
SELECT COUNT(*) AS fk_violations FROM expenses e
  LEFT JOIN expense_categories c ON c.id = e.category_id
 WHERE e.category_id IS NOT NULL AND c.id IS NULL;

-- G. 컬럼 상태
SELECT column_name, is_nullable, data_type FROM information_schema.columns
 WHERE table_name = 'expenses' AND column_name IN ('category_id','expenses_subcategory_id');
SQL
```

**판단 기준:** A·B·D·F 가 전부 0행이면 `26-01 → 26-05 → 26-03 → 26-04` 를 그대로 적용해도 된다. 하나라도 걸리면 그 데이터를 먼저 정리해야 하므로 결과를 보고 판단한다.
