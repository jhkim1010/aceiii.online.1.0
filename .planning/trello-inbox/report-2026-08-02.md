## 1. ★ 최우선 — 재고 데이터가 실제로 망가지는 건

### 🔴 [Eliminar un ingreso](https://trello.com/c/LNBmJ2ZI) — 입고 삭제가 재고를 반복 차감 (08-01, still-open)

> "Al presionar Aceptar aparece error. Pero aun aparece el ingreso... en stock aparece negativo y lo sigue restando"

**증상 실재 — 원인 2개가 겹침.**

- `api-ventago/src/app/products/productStock.service.ts:859-940` `deleteStockTodayByParent`
  append-only 규약대로 음수 ADJUST 행을 INSERT 하지만, **"이미 상쇄됐는지"를 전혀 추적하지 않는다.** 호출할 때마다 같은 원본(`type=null`) 행을 다시 찾아 그 합계만큼 새 음수 행을 또 넣는다 → **멱등성 없음**.
- `productStock.service.ts:799-816` `getProductsWithStockAddedToday`
  목록 집계가 `where: { type: IS NULL, stock > 0 }` 뿐이라 **상쇄 ADJUST 행을 반영하지 않는다.** 삭제해도, 새로고침해도 입고 행이 사라지지 않는다.

두 결함이 합쳐져: 지워지지 않는 것처럼 보임 → 사용자가 반복 클릭 → 클릭할 때마다 `products.stock` 이 더 깎여 음수로 내려감.

프론트: `ventago-app/src/views/products/list/components/ProductsList.tsx:146-165` (`DELETE /products/stock-today/:id`).

**수정 방향**
1. `getProductsWithStockAddedToday` → `product_branch_id + operation_date` 기준 **SUM(stock)** (모든 type 포함) 으로 "오늘 순입고 > 0" 만 노출
2. `deleteStockTodayByParent` → 현재 순재고를 재계산해 **필요한 만큼만** 상쇄 (이미 0/음수면 no-op) = idempotent

> ⚠️ 이 카드는 이미 운영 데이터를 오염시켰을 가능성이 있습니다. 코드 수정 후 `stocks` 원장 기준으로 `products.stock` 캐시 드리프트 점검 SQL 을 돌리는 걸 권합니다 (조회는 승인 불필요).

## 3. 신규 미해결 (08-01 보고)

### 🔴 [Sucursal](https://trello.com/c/uyBUKfBM) — 지점 전환이 아예 안 됨

> "no hace el cambio, no muestra error y al cerrar sesion tampoco"

**원인 확정.** `BranchSwitchModal.tsx:113-125` 가 `POST /session/switch-terminal` 성공 후 `window.location.href` 로 하드 리로드 → `AuthContext.tsx:74-91` 의 `initAuth()` 가 `/auth/me` 재호출 → 그 응답의 `branchId` 는 `auth.service.ts:1012,1072` 에서 **`users.branch_id` (정적 소속 지점)** 을 반환한다. 그런데 `session.service.ts:668-807` `moveToTerminalAndCreateSession` 은 `active_sessions`/`terminal_devices` 만 갱신하고 **`users.branch_id` 는 건드리지 않는다.** → 전환 직후 이전 값으로 덮어써짐. 에러가 없는 이유는 API 자체는 200 이기 때문.

**수정 방향:** `/auth/me` 가 `active_sessions.branch_id` 를 `users.branch_id` 보다 **우선** 반환하도록. (세션이 진실, 사용자 레코드는 기본값)

### 🟡 [Agregar a 2 sucursales stock](https://trello.com/c/bklfCOX3) — 같은 날 2지점 추가 불가

"변경 없음" 오탐. `ProductParentList.tsx:119` 가 `GET /products/:id/inventory-by-date` 를 **branchId 없이** 호출해 전 지점 합산값을 `originalStocks` 에 넣고, `ProductsView.tsx:996-1002` 의 diff 가 `colorId+sizeId` 만으로 매칭한다(**branchId 없음**). 지점 A 에 10 넣은 뒤 지점 B 에 10 을 넣으면 `old(10) === new(10)` → "No hay cambios".

이미 고쳐진 안전 경로(`handleMadreSave`)가 있는데 `BasicDataCard.tsx:1090,1108` 의 저장 버튼이 구 경로 `handleEdit` 로 직행한다.
**수정 방향:** 저장 버튼을 `handleMadreSave` 로 일원화 (가장 작은 변경) 또는 diff 키에 `branchId` 포함.
