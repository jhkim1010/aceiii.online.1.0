## 4. 재현 정보 필요 (needs-repro)

### 🟡 `6a6b9b70` — Pasar a pdf (확대 110%/90% 에서 PDF 옵션이 안 보임)

증상: 노트북 화면 또는 브라우저 확대 110%·90% 에서 «PDF 로 넘기는» 옵션이 나타나지 않고, **70% 로 축소해야만 보임**.

**조사 결과 (코드 read-only):**

- 앱 전체에서 리포트용 PDF 버튼은 **한 곳뿐** — `ventago-app/src/views/reports-v2/ReportsTopbar.tsx:123-127` (`Tooltip title='Exportar PDF'`).
  메뉴 «Reportes» 는 `menuRegistry.ts:228` 에서 `directPath: '/reportes-v2'` 로 이 셸에 직접 진입하므로 신고 화면일 가능성이 높습니다.
- **레이아웃 가설 (증상과 일치):** Topbar 는 `height:56` 의 단일 flex row 이고 `flexWrap` 이 없습니다.
  - 좌측 제목 블록: `flexShrink: 0`
  - 우측 액션군(⭐ / Excel / **PDF** / Ejecutar): `flexShrink: 0`
  - 중앙 필터 슬롯: `flex: 1, minWidth: 0` — **컨테이너는 0 까지 줄지만 자식 필드는 `minWidth: 120` / `minWidth: 100` 고정**(`ReportsFilterFields.tsx:27,157`)이라 축소되지 않습니다.
  → 실효 폭이 좁아지면(확대 110% = 뷰포트 CSS 폭 감소) 필터 필드가 슬롯 밖으로 넘쳐 **우측 액션군 위를 덮습니다**. 70% 로 축소하면 폭이 넉넉해져 다시 보이는 동작과 정확히 일치합니다.
- **★ 더 중요한 발견:** 이 PDF 버튼은 아직 **동작하지 않는 placeholder** 입니다.

  ```ts
  // ReportsTopbar.tsx:26-29
  // PDF 는 Phase 6 훅에서 미지원 — placeholder
  const handlePdf = () => { alert('PDF export — próximamente') }
  ```

  즉 보이게 만들어도 `PDF export — próximamente` 경고창만 뜹니다. **이 카드는 레이아웃 버그가 아니라 「리포트 PDF 내보내기 미구현」 이라는 기능 요청일 수 있습니다.**

**착수 전 확인 요망 (택1):**
- (a) 스크린샷 화면이 `/reportes-v2` 셸이 맞습니까? → 맞다면 레이아웃 픽스(액션군 우선 배치 + 필터 슬롯 `overflow:hidden` / `flexWrap`)를 다음 실행에서 수행합니다. **단, PDF 기능 자체는 별도 구현 필요.**
- (b) 다른 화면(예: 재고 목록의 인쇄/내보내기)이라면 화면 경로를 알려주세요 — 현재 코드에 그 위치의 PDF 버튼은 존재하지 않습니다.
