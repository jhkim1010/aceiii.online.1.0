**최소 수정 방향** (로컬 세션에서):

1. `:155-162` **effect 를 둘로 분리** — 목록/리셋은 `open` 에만, 미마감 조회는 `[open, boxId]` 에만 반응:
   ```ts
   useEffect(() => { if (!open) return; fetchLists(); reset(defaultValues); setTerminalAlert(null); setBoxSuccessAlert(null) }, [open])
   useEffect(() => { if (!open) return; fetchUnclosedPreviousBalance() }, [open, boxId])
   ```
2. `:113-115` **이미 고른 값을 덮지 않게 방어**:
   ```ts
   setBoxId(prev => (prev && boxRes.some(b => b.id === prev) ? prev : boxRes[0].id))
   ```
   터미널 로딩도 그 결과 id 기준으로.
3. (선택) `fetchLists` deps 의 `occupiedTerminals`/`openedBoxesToday` 는 기본값 `= []` (`:33`) 때문에 부모가 prop 을 생략하면 매 렌더 새 배열 → 같은 고리를 다시 만든다. 모듈 스코프 상수 `const EMPTY: never[] = []` 로 빼는 편이 안전.

★ 이 카드에는 「useEffect 의존성이 사용자의 선택을 되돌리는 고리」 패턴이 그대로 들어 있다 — 스킬 3단계 규약에 추가해 뒀다.

## 8. Mac / 운영서버에서 실행할 명령

클라우드 세션이라 아래를 직접 못 돌렸습니다. Mac 에서 실행 후 결과를 주시면 판정을 확정하겠습니다.

### 8-1. Inicio de caja — 해당 지점의 Box 개수 확인

```bash
ssh jhkim-server "sudo -u postgres psql -p 5434 -d ventago -c \"
SELECT b.id, b.name, b.branch_id, br.name AS sucursal, b.status, b.is_deleted
FROM boxes b JOIN branches br ON br.id = b.branch_id
WHERE b.store_id = 9 ORDER BY b.branch_id, b.name;\""
```
`status` 가 active 가 아니거나 `is_deleted=true` 면 목록에서 빠집니다(`box.service.ts:10-11`). 2개 이상 정상 조회되면 **코드 회귀 확정**입니다.

### 8-2. Ventas suspendidas — `branch_id` NULL 행 확인 (백필 필요 여부)

```bash
ssh jhkim-server "sudo -u postgres psql -p 5434 -d ventago -c \"
SELECT store_id, COUNT(*) FILTER (WHERE branch_id IS NULL) AS sin_branch, COUNT(*) AS total
FROM ventas_suspendidas GROUP BY store_id ORDER BY store_id;\""
```
`sin_branch > 0` 이면 해당 보류 판매들이 **화면에서 영구히 사라진 상태**입니다 — 백필 SQL 이 필요합니다.

### 8-3. Añiadir gasto — 트리거 설치 여부 + NOT NULL 확인 (db-drift 확정)

```bash
ssh jhkim-server "sudo -u postgres psql -p 5434 -d ventago -c \"
SELECT tgname FROM pg_trigger
WHERE tgrelid = 'expense_categories'::regclass AND NOT tgisinternal;\""

ssh jhkim-server "sudo -u postgres psql -p 5434 -d ventago -c \"
SELECT column_name, is_nullable FROM information_schema.columns
WHERE table_name='expenses' AND column_name='expenses_subcategory_id';\""

ssh jhkim-server "sudo -u postgres psql -p 5434 -d ventago -c \"
SELECT COUNT(*) FILTER (WHERE path IS NULL OR path='') AS sin_path, COUNT(*) AS total
FROM expense_categories;\""
```
트리거가 0행이면 **신규 카테고리는 계속 `path=''`** 로 생깁니다. `is_nullable='NO'` 면 **gasto 저장이 23502 로 실패할 수 있습니다** — 이 경우 `ALTER TABLE expenses ALTER COLUMN expenses_subcategory_id DROP NOT NULL;` 승인이 필요합니다(영향 row 0 — 제약만 해제).
