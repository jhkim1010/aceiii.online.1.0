## 3. 수정 완료 (이번 실행)

### Agregar a 2 sucursales stock — `6a6e43fb` / [bklfCOX3](https://trello.com/c/bklfCOX3)

> "no deja agregar en un mismo dia a 2 sucursales distintas, el sistema detecta que no hay cambios para hacer"

**존재 검증:** 관련 파일에 이 결함을 다룬 최근 커밋이 없어 증상 현존을 확인한 뒤 착수했습니다.

**근본 원인 — 비교 기준선이 지점 단위가 아니라 전 지점 합산**

1. `ProductParentList.handleRowSelection` (L176)이 `GET /products/:id/inventory-by-date`를 **branchId 없이** 호출합니다. 이 엔드포인트는 `ProductBranch.findAll({ where: { productId } })`로 **모든 지점의 당일 입고를 합산**합니다 (`productStock.service.ts:1336-1362`).
2. 그 합산값으로 `setOriginalStocks`(L289)와 `setMode(todayHasEntries ? 'edit' : 'add')`(L292)가 정해집니다. → 지점 A에 오늘 입고가 있으면, 지점 B 작업이어도 무조건 `edit` 모드 + **지점 A 수량이 기준선**이 됩니다.
3. 사용자가 지점 B를 선택하면 `ProductsView`의 지점전환 effect(L517-596)가 **variants 그리드만** 다시 채우고 `originalStocks`/`mode`는 그대로 둡니다.
4. 결과: `handleEdit`(L1056-1069)이 지점 B 입력값을 **지점 A 기준선**과 비교 → 같은 수량이면 전부 skip → `diff.length === 0` → `toast('No hay cambios para actualizar')`(L1102). **신고 문구와 정확히 일치.**

**2차 결함 (기준선만 고치면 남는 "조용한 무저장")**

`correctTodayStocks`(`productStock.service.ts:554-675`)는 대상 `ProductBranch`를 `findAll`로만 찾고, 없으면 `continue`로 조용히 건너뛴 뒤 **성공 응답**을 냅니다. 상품이 그 지점에 처음 입고되는 경우 링크 행이 없으므로 "Cambios aplicados correctamente" 토스트만 뜨고 실제로는 아무것도 저장되지 않습니다. 같은 파일의 다른 경로들은 이미 `ProductBranch.findOrCreate`를 씁니다(L88, L338, L1622, L1694 — L1618 주석: "새로 추가된 지점(아직 ProductBranch 없음)도 처리하도록 findOrCreate"). correct-today만 예외적으로 누락된 것입니다.
또한 대상 지점을 정렬 없는 `pbs[0]`으로 골라 다지점 선택 시 **어느 지점이 정정될지 비결정적**이었습니다.
