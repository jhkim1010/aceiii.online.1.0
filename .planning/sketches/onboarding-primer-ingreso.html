A. 첫 로그인 = 가게 설명 (전체 화면, 약 5분)

메뉴를 보여주기 전에 대답하기 쉬운 질문으로 설정을 끝낸다. 사용자는 「설정」을 하는 게 아니라 자기 가게를 설명한다. (Square·Fudo 방식 — 대답이 실제로 기본값을 바꾼다)

단계 (1~7)

  • ① 업종 — ④의 분류 프리셋을 정한다. (메뉴는 안 바꾼다)
  • ② 결제수단 — 「Revisá tus medios de pago」 흡수.
  • ③ 판매원 신규 — Sellers 는 사용자와 별도 목록. 신규 매장은 1명만 시드돼 있다(운영 8곳 전부 1명, NOIX 13명 제외). 이름 + 「본인 사용자로 들어오나」(linkedUserId → POS 자동 선택) + PIN(선택). 「Vendo sólo yo」 한 번이면 끝.
  • ④ 분류 방식 신규 — 7개 use* 플래그를 의미와 예시로 켜고 끈다. 별칭(aliases, 예: Subcategoría→「Tipo」)도 여기서. 아래에 SKU 해부도가 실시간으로 바뀐다.
  • ⑤ 카테고리·타입·공급처 입력 신규 — 칩 입력. 공급처에 색 이름을 넣으면 경고.
  • ⑥ 첫 상품 — 여기서 만들지 않는다. 기존 Productos 화면 + 코치(장면 3)로 보낸다. Excel / Venta rápida 우회로.
  • ⑦ 프린터 — 「아니오」 기본. 하드웨어 연결은 첫 1분에 넣지 않는다(조사: 어느 경쟁사도 안 함).

왜 ④⑤가 필요한가 — 운영 실측 2026-09-27

  • 최근 가입 8곳 중 5곳(kim·Krencia·The Market·beula·CARAMELO)이 시드된 「General」 1개 + 제네릭 상품 1개에서 멈춰 있다.
  • 신규 매장은 7개 분류가 전부 ON(기본값)이다. 하나라도 비면 자동 SKU 가 멈춘다 — 그런데 무엇을 넣어야 하는지 아무도 말해 주지 않는다.
  • Cielo(22): 공급처에 BLANCO · NEGRO · TORNASOLADO · NONE — 색을 공급처로 넣었다. 뜻을 몰라서다.

원칙

  • 모든 단계 건너뛸 수 있다(Tiendanube 방식). 건너뛴 것은 가이드에 남는다.
  • 이미 있는 3개(매장·지점·카하)는 묻지도 세지도 않는다.
  • 매장 admin 에게만.

구현 메모

  • stores 에 업종 컬럼(expand, nullable). 위저드 완료/건너뜀 플래그는 setup-guide 상태에.
  • ④는 기존 store_configs.use*·aliases 를 그대로 쓴다 — 새 저장소 없음.

B. Guía de configuración — 내용만 새로

메뉴·착지점·기존 화면은 그대로. 바뀌는 것은 이미 있는 /guia-configuracion 페이지의 내용뿐이다. 체크리스트 대신 큰 버튼 하나(Shopify: 한 번에 한 단계·버튼 하나).

가이드로 들어오는 길 (화면을 안 바꾸는 것만)

  • 첫 로그인: 위저드(A)가 기존 화면 위에 전체 화면으로 뜬다. 닫으면 원래 화면.
  • 떠 있는 「Guía」 버튼(오른쪽 아래, 장면 3·4): 모든 화면 위에 진행률과 다음 할 일. 누르면 이 페이지. 설정이 끝나면 사라진다. (Toast 의 설정 아이콘, Shopify 의 서랍과 같은 역할)
  • 기존 메뉴의 「Guía de configuración」 항목은 그대로 — 배지만 붙는다.

내용

  • 4구역 13항목: Cobrar(업종·결제·판매원) · Productos(분류 방식·카테고리/타입·공급처·첫 상품) · Vender(시험 판매·첫 카하 마감) · Crecer(라벨·AFIP·이익). 「매장·지점·카하 생성」은 빠진다(사용자가 한 일이 아님).
  • 완료 판정은 실제 데이터로: 카테고리·공급처 수 > 시드, 판매원 > 1 또는 「혼자 판다」, 상품(제네릭 제외) ≥ 1, 판매 ≥ 1, 마감 ≥ 1.
  • 각 항목의 「Empezar」 = 해당 기존 화면으로 이동 + 코치 켜기.

그대로 두는 것

  • 진행률·자동 중단(≥70%+7일)·「No aplica」·「Más tarde」 서버 규칙.

C-1. 코치: 기존 Productos 화면에서 SKU 만들기

사용자 지적 그대로 — 코드는 이 화면에서 만들어지므로 여기서 가르친다. 위저드는 재료(분류)를 준비하고, 코치는 그 재료로 코드가 조립되는 순간을 보여 준다.

화면은 손대지 않는다. 코치는 세 가지만 얹는다: 위의 안내 띠(해부도 포함) · 대상 칸 강조 · 말풍선. (목업의 폼은 실제 BasicDataCard 를 단순화한 그림)

7단계

  • ①②③ 카테고리·타입·공급처 — 고를 때마다 안내 띠의 해부도 칸이 켜진다. 셋이 다 차야 코드가 나온다는 것을 눈으로 본다(지금은 코드가 말없이 비어 있다).
  • ④ 코드 — 「직접 쓰지 않는다. 자체 바코드가 있으면 Automático 해제 후 스캔」.
  • ⑤ 이름·가격 ⑥ 탈레×색 — 칸마다 변형 코드(기본 + 색 + 탈레) ⑦ 저장 → 라벨 인쇄 제안.
  • 해부도의 숫자는 코치가 매장 설정(use*·자릿수·prefix)과 선택값에서 읽어 그린다 — 화면 코드는 그대로.
  • 자동으로 뜨지 않는다. 가이드의 「Empezar」로만 켜진다(NN/g). 「Salir」 언제든.

별건 — 가이드와 무관하지만 발견한 것

  • SKU 는 분류의 전역 DB id(235 …)로 조립된다(sku-assembler.ts). 신규 매장 자릿수 2 인데 id 가 3자리라 넘친다. 실측 Cielo: 25372357501251189(17자리).
