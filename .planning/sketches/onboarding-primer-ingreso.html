Consulta a CODEX (2026-09-27)

  • Orden: fase 1 Productos → Ventas → Impresoras; fase 2 venta guiada → cierre. Un paso destacado por vez; «hecho» se detecta del estado real y lo ya configurado se saltea solo.
  • Obligatorio para vender: un producto vendible, un medio de pago, caja abierta. Impresora: saltable si no imprime. «Omitir» explica la consecuencia y queda pendiente a la vista.
  • No hacer una venta real y anularla: deja contrapartidas en stock, anulaciones en reportes, auditoría, numeración y posible AFIP. En su lugar, modo práctica con la interfaz real, sin escribir nada, y luego la primera venta real con confirmación explícita.
  • Chequeo previo: silencioso si todo está bien; los vendedores sin permiso ven explicaciones, no enlaces que fallan; preferencias por tienda y rol; «Reintentar» contra falsas alarmas.

조사 요약

14개 제품 + NN/g 연구. 우리 상황에 가장 가까운 것은 Fudo(아르헨티나·셀프 가입·2~5분 환영 폼이 설정을 바꿈·메뉴 입력 무료 대행).

이 조사로 바뀐 것

  • 코치(C)는 자동으로 띄우지 않는다 — 가이드의 「Empezar」를 눌렀을 때만. (NN/g)
  • 프린터는 위저드에서 「예/아니오」만. 연결은 나중.
  • 떠 있는 「Guía」 버튼은 설정이 끝나면 사라진다.
  • 메뉴 재구성(D)은 뺐다 — 가이드는 시스템을 바꾸지 않는다. 대신 떠 있는 「Guía」 버튼.

1. 첫 로그인 — 업종 → 추천 카탈로그 → 계획

설정은 실제 화면 위의 코치에서 한다 — 단, 빈 목록부터 채우게 하지 않고 업종에 맞는 카탈로그를 먼저 만들어 준다(사용자 지시 2026-09-27). 위저드는 세 장:

  • 업종 → 추천 카탈로그 자동 생성(다음 카드): 카테고리·서브카테고리·탈레·색·시즌과 켤 목록을 업종 템플릿으로 만든다. 사용자는 ✕ 로 빼고 칸에 써서 더한 뒤 「Crear mi catálogo」.
  • 추천 카탈로그 — 위 규칙.
  • 계획 — 1 준비(Productos → Ventas → Impresoras) · 2 학습(연습 판매 → 첫 실제 판매 → 마감·대조). 순서는 사용자 지시 그대로.

추천 카탈로그 — 규칙

  • 매장 자신의 행만 만든다(categories·subcategories·colors·sizes·seasons·store_configs.use*). 공용 테이블(global_categories 38개)은 건드리지 않는다 — 그건 기존 매장 이름을 모은 것이라 BEBIDA/BEBIDAS 같은 중복도 있다.
  • 공급처는 만들지 않는다(추측 불가).
  • 가격 레벨도 만든다 — 기준은 이름 「PRECIO 1」 그대로(설명에 Mayorista 등), 나머지는 + 인상·반올림. 의류 도매 기준+소매 40% · 액세서리 +60% · 키오스크 1개 · 가스트로 Delivery +10% · 철물 Mostrador +25%. 수치는 초안.
  • 켤 목록도 업종이 정한다: 키오스크 = Categoría·Subcategoría·Proveedor 만, 가스트로 = Categoría·Subcategoría 만(사이즈·색 OFF → 빈 켜진 목록이 SKU 를 막는 문제가 처음부터 없다).
  • 액세서리·피어싱: 기존 목록에 별칭을 붙여 쓴다 — Talle→Medida(0.8~1.6 mm · 6~12 mm), Color→Terminación, Origen→Material(Titanio · Acero quirúrgico · Plata 925 · Bijou). 별칭 기능(EditModuleAlias)은 이미 있다 — 새 컬럼 없음. 실측 Cielo 가 「PIERCING DE TITANIO」를 카테고리로, 색을 공급처로 넣었던 바로 그 업종이다: 재질은 목록, 색은 Terminación 에.
  • 코드 방식 안내도 업종별: 키오스크 = 제조사 바코드(EAN) 스캔(Automático 해제), 철물 = 바코드가 있으면 스캔, 의류·액세서리 = 자동.
  • 「Empezar de cero」 = 지금처럼 General 1개. 매장 생성 직후 한 번만, 상품이 0개일 때만 실행. 이미 이름이 같은 행이 있으면 건너뛴다(멱등).
  • 템플릿 내용(업종별 목록)은 운영 매장 실제 카테고리로 다듬을 수 있다 — 지금 값은 목업용 초안.

지금의 환영 모달을 대체한다

  • 현 OnboardingDialog 는 「Venta Rápida」 스위치를 켜라고 안내하는데, POS 에 그 스위치가 없다(코드 확인). 첫 안내가 없는 기능을 찾게 만든다.

구현 메모

  • stores 업종 컬럼(expand, nullable) + 위저드 완료/건너뜀 플래그. 매장 admin 에게만.

2. 가이드 페이지 — 준비 → 학습

기존 /guia-configuracion 페이지의 내용만 바꾼다. 메뉴·착지점·다른 화면은 그대로.

구성 (사용자 지시 순서)

  • 1 준비: 📦 Productos(목록 → 첫 상품) · 💳 Ventas(결제수단 · 판매원) · 🖨 Impresoras(선택).
  • 2 학습: 🎯 연습 판매 · 🛒 첫 실제 판매(판매 전 점검 포함) · 🔒 마감·대조. Productos·Ventas 가 끝나야 열린다(Impresoras 는 선택이라 조건 아님).
  • 맨 위 큰 버튼은 항상 다음 한 단계. 각 「Empezar」 = 그 기존 화면으로 이동 + 코치 켜기.

완료 판정 — 실제 데이터로 (CODEX)

  • 목록: 켜진 목록마다 「General」 외 1개 이상 · 첫 상품: 제네릭 외 상품 ≥ 1
  • 결제수단: 활성 ≥ 1 그리고 가이드에서 「확인함」(시드 3개가 이미 활성이라 데이터만으론 「봤다」를 알 수 없다)
  • 판매원: 시드 외 ≥ 1 또는 「혼자 판다」 · 프린터: 에이전트 Conectado + 터미널 기본 comandera + 테스트 인쇄 성공 · 첫 판매 ≥ 1 · 대조(arqueo) ≥ 1
  • 이미 설정된 매장은 해당 단계를 자동으로 건너뛴다.

그대로 두는 것

  • 「No aplica」·「Más tarde」·자동 중단(≥70%+7일) 서버 규칙.

C-0. 코치: 분류 목록부터 채우기 (SKU 이전)

사용자 지적 — 상품은 목록에서 골라 만들어지므로, 목록이 SKU 보다 먼저다. 이제 목록은 추천 카탈로그로 이미 차 있고, 이 코치는 검토·보완(빠진 것 추가, 안 쓰는 목록 끄기, 공급처 입력)을 가르친다. 이 코치는 실제로 계속 쓰게 될 Configuración › Productos 화면에서 가르친다. 화면은 그대로이고 안내 띠·강조·말풍선만 얹는다.

순서 (9단계)

  • ① 지도: 「상품 = Categoría → Subcategoría + Proveedor + Color + Talle」. 이 화면의 카드들이 그 목록이라는 것.
  • ② Activo: 안 쓰는 목록(예: Temporada·Origen)은 체크 해제 → 상품 입력 때 안 묻고 코드에도 안 들어간다. 지금은 7개가 전부 켜진 채 시작한다 — 비어 있는 켜진 칸이 SKU 를 멈춘다.
  • ③④ Categorías: Nueva → 이름 → Guardar. 「General」 은 이미 있다(그대로 둬도 된다).
  • ⑤ Subcategorías: 모달이 Categoría 를 먼저 묻는다 — 그래서 카테고리가 먼저다.
  • ⑥ Proveedores: 「파는 사람, 색 아님」 (Cielo 실측).
  • ⑦ Colores·Tallas: 이미 채워져 있다 — 확인·추가만.
  • ⑧ Parámetros: 「Prefijo para SKU = 25」 — 모든 코드의 첫 숫자.
  • ⑨ → 상품 코치(장면 4)로.

「Dígitos」는 설명하지 않는다

  • 코드 안 자릿수 설정인데, 지금은 전역 id 가 들어가 설정대로 안 나온다(장면 4 별건). 고쳐지기 전엔 「건드리지 않아도 된다」고만.

위저드와의 관계

  • 위저드 ④(분류 방식)는 무엇을 켤지 결정만, 입력은 이 화면에서 한다 — 나중에 다시 올 곳을 처음부터 익힌다. 위저드 ⑤가 이 코치로 연결된다.
  • 가이드 「Productos」 구역의 「Categorías y tipos」「Proveedores」 → 이 코치.

  • 켜진 목록마다 「General」 외 1개 이상 — 실제 데이터로.

C-1. 코치: 기존 Productos 화면에서 SKU 만들기

사용자 지적 그대로 — 코드는 이 화면에서 만들어지므로 여기서 가르친다. 위저드는 재료(분류)를 준비하고, 코치는 그 재료로 코드가 조립되는 순간을 보여 준다.

화면은 손대지 않는다. 코치는 세 가지만 얹는다: 위의 안내 띠(해부도 포함) · 대상 칸 강조 · 말풍선. (목업의 폼은 실제 BasicDataCard 를 단순화한 그림)

7단계

  • ①②③ 카테고리·타입·공급처 — 고를 때마다 안내 띠의 해부도 칸이 켜진다. 셋이 다 차야 코드가 나온다는 것을 눈으로 본다(지금은 코드가 말없이 비어 있다).
  • ④ 코드 — 「직접 쓰지 않는다. 자체 바코드가 있으면 Automático 해제 후 스캔」.
  • ⑤ 이름·가격 ⑥ 탈레×색 — 칸마다 변형 코드(기본 + 색 + 탈레) ⑦ 저장 → 라벨 인쇄 제안.
  • 해부도의 숫자는 코치가 매장 설정(use*·자릿수·prefix)과 선택값에서 읽어 그린다 — 화면 코드는 그대로.
  • 자동으로 뜨지 않는다. 가이드의 「Empezar」로만 켜진다(NN/g). 「Salir」 언제든.

별건 — 가이드와 무관하지만 발견한 것

  • SKU 는 분류의 전역 DB id(235 …)로 조립된다(sku-assembler.ts). 신규 매장 자릿수 2 인데 id 가 3자리라 넘친다. 실측 Cielo: 25372357501251189(17자리).
  • 매장별 번호 store_entity_id(1, 2, 3…)가 이미 있다. 목업의 25 01 01 01 07 은 그걸 쓴다고 가정한 그림이다 — 지금 실제로는 이보다 길게 나온다. 고칠지는 따로 정할 일(기존 SKU 와 형식이 섞인다).

▶ 말풍선의 버튼으로 단계를 넘겨 보세요. 6단계에선 격자 칸을 눌러 볼 수 있습니다.

5. 판매 전 점검 — Nueva venta 위에 뜬다

막는 것 / 알려만 주는 것 (CODEX)

  • 막음: 카하 닫힘 · 활성 결제수단 0 · 팔 수 있는 상품 0.

누구에게 · 언제

  • 다 준비된 매장에는 안 뜬다 — 조용히 검사하고 빠진 게 있을 때만.
  • 「Vista vendedor」: 관리자 권한이 없으면 설정 링크 대신 「encargado 에게 요청」 문구. 열리지 않는 링크를 주지 않는다.

  • 이것은 가이드가 POS 진입 때 띄우는 오버레이다. POS 자체의 검사 로직은 건드리지 않는다.

4. 사용법 ① — 연습 판매 (진짜 화면)

「말만 한다」는 지적 → 실제 Nueva venta 화면 그대로(코드에서 라벨·배치를 옮겼다) 위에서 한 단계씩 누른다.

왜 「연습 모드」인가 — CODEX 권고

  • 실제 판매 후 취소는 흔적이 남는다: stocks 원장 보정 행, 보고서의 취소, 감사 로그, 전표 번호, AFIP 자동 발급 매장이면 전표까지.
  • 그래서 연습은 저장하지 않는다: 서버 쓰기·인쇄·AFIP·소켓 전부 차단, 상단 띠로 상태를 계속 보인다. 끝나면 「첫 실제 판매」로 넘어가며 명시적 확인(매장·카하·금액)을 받는다.
  • 위험: 연습 화면이 실제 화면과 어긋나는 것. 연습은 별도 복제가 아니라 같은 컴포넌트를 「쓰기 차단」 상태로 띄우는 방식이어야 한다 — 구현 난이도가 가장 큰 부분.

8단계

  • ① 카하: 보통 자동으로 열린다. 「Inicia tu caja」가 보이면 → Selecciona Caja y Terminal · Monto inicial
  • ② Vendedor (F7) ③ Buscar Producto(이름) ④ Buscar SKU(스캐너) ⑤ PAGO: F9 = 전액 현금, Alt+2~4 = 그 줄 수단으로 전액
  • ⑥ 나눠 내기: 두 줄에 금액 → 「✓ Completo」 ⑦ Generar Venta (F2) ⑧ 결과 미리보기(티켓 그림만)

6. 사용법 ② — 마감과 대조(arqueo)

코드 확인 결과, 마감(「Cerrar Caja」)에는 현금 입력칸이 없다 — 확인창만 뜬다. 센 현금과 차이는 /caja 의 「Arquear」에서 입력한다. 신규 고객이 「닫았는데 어디서 세지?」에서 막히는 지점이라 둘을 한 흐름으로 가르친다.

6단계

  • ① Resumen de Caja 숫자 읽기(Saldo final = 서랍에 있어야 할 돈)
  • ② Cerrar Caja → 「Confirmar cierre de caja」 — 되돌릴 수 없다는 경고
  • ③ Cajas pendientes de arqueo → Arquear ④ 「Efectivo contado en la caja」 입력 → 「Diferencia contra el libro」 ⑤ Motivo ⑥ Confirmar arqueo

카하 규칙과의 관계

  • 돈은 서랍 단위로만 모인다 — 대조도 서랍·구간 단위(box_settlements). 코치 문구가 「사람별」 로 오해하게 쓰지 않는다.
