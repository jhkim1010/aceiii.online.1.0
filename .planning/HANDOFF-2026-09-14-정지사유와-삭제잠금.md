## 1. ★★★ 가장 중요 — 검증 게이트가 두 군데 뚫려 있었다

**이것부터 읽어야 한다.** 이 세션 전반의 커밋 상당수가 검증 없이 지나갔다.

### ① NODE_OPTIONS 가 node 를 죽여 훅 두 개가 침묵했다
`--require` preload 임시파일이 사라지면 **모든 node 실행이 즉사**한다. 두 훅은
첫 줄에서 `node -e` 로 입력 JSON 을 파싱하고 실패를 `2>/dev/null` 로 삼킨다 →
`CMD` 가 비고 → **커밋 게이트도 CODEX 자동 검토도 아무 말 없이 통과**.
유일한 흔적은 `.auto-codex.heads` 가 2026-09-10 에 멈춘 것뿐이었다.
→ `node-sano.sh` 로 **실제로 돌려 보고** 고친다. 실패하면 **소리를 낸다.**

### ② `git add X && git commit` 은 게이트를 통째로 뚫는다
훅은 **PreToolUse** 라 명령 실행 **전**에 돈다 → 같은 명령 안의 `git add` 결과가
index 에 없다 → `staged` 가 비어 **tsc·eslint·jest 가 하나도 안 돌고** 통과.
**실증**: 일부러 실패하는 spec 을 그 형태로 커밋했더니 막히지 않았다(`0100d26`).
`git add` 를 따로 하니 정상적으로 막혔다.
→ 같은 명령에 `add`/`stage` 가 있으면 **거절**한다. 시험 4건 + 오탐 대조군.

★ **습관을 그렇게 들일 것**: `git add` 는 **항상 커밋과 별개의 Bash 호출**로.
★ 게이트가 돌았는지 확인하려면 `/tmp/vbc-api-jest.log` 의 **mtime** 을 본다.

## 6. 이번에 배운 것

1. **「같은 사실을 두 곳이 소유한다」를 다섯 번 만났다** — 매장 관리자 판정(3곳) ·
   정지 사유(추론 2곳) · purge 잠금(서버/프론트) · 집계 창(서버/프론트) ·
   연장 판정(함수/SQL). **지적 하나를 받으면 그 형태를 전수로 세라**가 반복 확인됐다.
2. **반쯤 고친 것은 고친 것이 아니다.** 정지 필터를 일괄 UPDATE 에만 걸고 관리자·
   매장 행을 빠뜨렸는데, 그 상태로 「고쳤다」고 적었다. CODEX 가 P1 으로 잡았다.
3. **동어반복 검사를 썼다.** 「두 판정이 같다」를 재면서 한쪽이 다른 쪽을 부르게
   해 놨다 — 언제나 참이다. 진짜 위험은 **소비자가 그 함수를 안 쓰는 것**이었고
   실제로 그랬다.
4. **소스 문자열 검사는 돌연변이로 재야 한다.** purge 잠금 검사가 조건만 바꿔도
   통과했다 — 호출 토큰으로 바꾸니 잡혔다.
5. **「닿지 않는다」와 「막혀 있다」는 다르다.** 다매장 직원의 `trial_ends_at` 이
   전부 NULL 이라 P1 이 지금 데이터로는 안 터진다 — 그래도 고쳤다.
6. **화면이 숫자의 뜻을 말해야 한다.** 앱 현황이 「접속 중」이 아니라 「서버와
   대화한 앱」임을 화면에 적었다. 누적 22 vs 실사용 1 — 22배 과대평가가 가능하다.
