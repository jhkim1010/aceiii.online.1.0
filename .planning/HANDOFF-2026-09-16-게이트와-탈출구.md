## 2. ★★★ push 를 막는 것 — 게이트의 탈출구가 아직 탈출구가 아니다

### 무엇을 만들었나

`libroIva()` 가 `FROM afip_vouchers` 라서, **AFIP 에는 있는데 우리 DB 에 없는 전표**가
IVA Digital 파일에서 통째로 빠진다. 실측(2026-09-15, 읽기 전용 SOAP 조회):

| 전표 | AFIP 마지막 | 우리 max | AFIP 에만 있는 번호 |
|---|---|---|---|
| Factura A(1) | 80 | 80 | **78** (2026-08-24, $1) |
| Factura B(6) | **126** | **124** | **117·118·119·120**($1 씩) · **125·126**(2026-09-08 각 **$40,000**) |

7건 모두 우리 판매와 날짜·금액이 안 맞는다 = **cool-invoice 가 같은 번호열을 소비**했다
(채번 키는 인증서가 아니라 `CUIT + PtoVta + CbteTipo`). 9월분을 그대로 뽑으면
**$80,000 이 빠진 신고서**가 나간다.

⤷ 게이트(제출 전 AFIP 대조 → 409/503) + 외부 발급 원장(등록하면 파일에 **합류**).

### 세 바퀴 동안 고친 것 (전부 돌연변이로 고정)

1차 CODEX: 판정 두 축 분리 · `db_adelante` 추가 · 409/503 구분 · (PV×종류) 연역 ·
Excel 제외 · CUIT 박제 · **원장은 면제표가 아니라 신고 원장**.

2차 CODEX(P1 3건):
- **게이트와 파일의 범위가 갈렸다** — 게이트는 `cuit`, 파일은 `store_id`. 남의 매장
  행으로 게이트가 열리고 내 파일엔 그 전표가 빠진다. **이 기능이 막으려던 사고 그 자체.**
  ★ 그 결함을 **내 시험이 못 박고 있었다**(`expect(where.storeId).toBeUndefined()`).
- **발행자 0건을 「검증 성공」으로** 처리 → 감시 대상 부재다.
- **우리 전표를 외부로 중복 등록** 가능 → `UNION ALL` 이라 두 번 신고된다.

3차 CODEX — **막다른 게이트**: 게이트만 내보내고 등록 경로를 닫았는데,
**store 6 은 이미 결번 상태**라 IVA Digital 을 **영구히 못 뽑는** 상태가 된다.
내가 "테이블이 0행이라 종전과 같다"고 적은 것이 틀렸다 — 게이트를 막는 것은 원장이
아니라 `afip_vouchers` 의 결번이고 그건 이미 있었다.
⤷ 탈출구를 **함께** 내기로 하고(사용자 결정 «가»), 열기 전에 P1·P2 넷을 해결:
  **세액**(AFIP 원본값 + Campo 9 불변식 강제) · **소유권**(남의 매장 행 탈취 차단) ·
  **환경**(`entorno` 박제, homo 행이 운영 신고서에 못 섞임) · **P1-B**(외부 원장도 세기).

### ★★★ 4차 CODEX — 아직 안 고쳤다. **여기서 멈췄다** (`632c6780` 검토)

보고서: `.team/reviews/auto-api-ventago-632c6780.md`

| | 지적 |
|---|---|
| **P1** | **비과세·면세·기타세금이 있는 정상 전표는 영구히 해소 불가.** `ImpTotConc`/`ImpOpEx`/`ImpTrib` 가 있으면 `ImpTotal ≠ ImpNeto + ImpIVA` 가 **정상**인데, 지금 코드는 그것을 `incompleto` 로 만든다. 신고서 모델에 그 금액 필드도 없다. ⤷ **탈출구가 여전히 탈출구가 아니다** |
| **P1** | 게이트가 검사하는 종류는 `tiposDeEmisor()` 가 연역한 고정 목록인데, **등록 API 는 임의의 `cbteTipo` 를 받고 보고서는 전부 포함**한다. 목록 밖 종류가 하나 등록되면 그 종류의 다른 결번은 **검사 없이** 파일이 나간다 |
| **P1** | 중복 검사가 **TOCTOU** — `afip_vouchers` 확인 → AFIP HTTP 조회 → INSERT 사이에 같은 번호가 저장되면 두 원장에 남아 중복 신고 |
| **P2** | 마이그레이션이 유일 인덱스를 **DROP 먼저** 한다. 실행기가 트랜잭션으로 안 감싸면 실패 시 **유일 제약이 없는 상태**로 남는다 (운영은 `--single-transaction` 으로 적용해 안전했다) |

★ 첫 번째가 가장 무겁다. **$1 시험 전표 5건은 아마 통과하겠지만, 실제 $40,000 두 건이
  비과세·기타세금을 포함하면 등록해도 `incompleto` 로 남아 계속 막힌다.**
  ⤷ 다음 세션 첫 일: **그 7건을 `FECompConsultar` 로 조회해 `ImpNeto`·`ImpIVA`·
    `ImpTotConc`·`ImpOpEx`·`ImpTrib` 를 실제로 확인**할 것. 그 값이 「탈출구를
    지금 형태로 열어도 되는가」를 정한다. 도구는 이미 있다:
    `scripts/afip-probe-lectura.js` 옆에 만든 조회 스크립트(§6).

## 5. 환경에 대해 반드시 알아야 할 것

★★ **dev API 는 `localhost:5432/ventago` 를 쓰지 않는다.**
```
dev API (.env) → 127.0.0.1:15432 / ventago_staging   ← 여기
「로컬 DB」     → 127.0.0.1:5432  / ventago          ← 운영과 스키마 동일
```
스테이징은 레거시 이관본이라 마이그레이션이 **뒤처져 있다**. 이번에 2개를 적용해
로컬과 컬럼 단위로 맞췄다. 로그인이 `column Users.suspended_reason does not exist`
로 죽으면 그 이야기다 — **코드 문제가 아니다.**

★ **dev 서버가 도는 동안 프론트 운영 빌드(`npm run build`)를 돌리지 말 것.**
  `next build` 와 `next dev` 가 같은 `.next/` 를 써서 dev 서버가 자기 청크를 못 찾는다
  (`Cannot find module './chunks/vendor-chunks/@mui.js'`). 이번에 실제로 깨뜨렸고,
  `.next` 삭제 + dev 재시작으로 복구했다.

★ **`eslint --fix` 주의.** `productStock.service.ts` 의 **필요한 타입 단언 3개를
  지웠다**(`as Array<{...}>`). tsc 가 잡았다. 이 저장소의 알려진 함정이다.

★ **`perl -0pi` 로 한글 파일을 편집하면 이중 인코딩될 수 있다.**
  `Wide character in print` 경고가 나오면 그 파일은 깨진 것이다. 복구:
  `iconv -f UTF-8 -t ISO-8859-1`. 이번에 `reportes-arca.service.ts` 가 그렇게 깨졌고
  그렇게 되돌렸다(한글 57줄·줄 수 307 완전 복원).

★ **macOS `git` 은 Xcode shim 이다.** Xcode 가 26.6→27.0 으로 올라가면서 라이선스
  동의가 무효가 돼 세션 도중 git·python3 가 전부 멈췄다. `sudo xcodebuild -license accept`.

## 7. 이번에 배운 것

1. **막는 장치는 푸는 길과 함께 낸다.** 세 번 다 여기서 걸렸고, 세 번째는
   「0행이니 무해하다」는 내 오판이었다 — 막는 조건은 원장이 아니라 **기존 데이터**였다.
2. **내 시험이 결함을 못 박고 있을 수 있다.** `expect(where.storeId).toBeUndefined()`
   가 정확히 그랬다. 틀린 결정을 고정한 시험은 회귀를 막는 게 아니라 결함을 보존한다.
3. **돌연변이가 안 죽으면 치환이 적용됐는지부터 본다.** 이번에 두 번, 살아남은 줄
   알았던 돌연변이가 사실은 **적용되지 않은 것**이었다(`[^)]*` 가 `@Query('mes')` 의
   괄호에서 끊김 · `\$S` 이스케이프로 엉뚱한 파일).
4. **「로컬」이 하나가 아니다.** dev API 가 보는 DB 를 확인하지 않고 다른 DB 를
   근거로 안내했다. 접속 문자열을 먼저 읽을 것.
5. **커밋 게이트가 두 번 나를 막았다** — 새 파일만 lint 하고 수정한 기존 파일을
   안 봤다. 손으로 돌리는 검증에 의존하지 말라는 규칙이 실제로 작동했다.
