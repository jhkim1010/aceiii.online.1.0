## 2. ★★ CODEX P1 — gerente 가 남의 지점 잔액을 바꿀 수 있었다

`gerente` 는 **지점 제한 역할**인데 실사 경로가 `storeId` 만 봤다. A 지점 gerente 가
같은 매장 B 지점 금고 id 로 `POST /:id/arqueo {countedAmount: 999999}` 를 보내면
**보정 원장을 만들고 B 지점 잔액을 바꿀 수 있었다.** 읽기 누출이 아니라 **쓰기**다.

→ `asegurarAlcanceDeSucursal()` 하나로 **6개 경로**에 건다:
  · POST `:id/arqueo` (잠근 직후·아무것도 만들기 전에 거절)
  · GET `:id/arqueo/ultimo` · `:id/arqueos`
  · GET `branch/:branchId` (**만들기 전에** 거절 — get**OrCreate** 다)
  · GET `:id/balance` · `:id/operations`  ← 사용자 승인 후 확장

★★ `getOrCreateByBranchId` **본문은 한 글자도 안 바꿨다.** 그 함수는 카하 개시·마감과
  box-operation 이 부르는 **시스템 경로**이기도 하다. 거기에 호출자 판정을 끼우면
  `user_branches` 가 비고 `users.branch_id` 가 낡은 계정에서 **카하 마감이 막힌다.**
  판정은 HTTP 경계(컨트롤러)에서만 건다.

### 실제 영향 — 사실상 0
운영에서 지점 제한 사용자는 **7명**(gerente 2 · vendedor 5). vendedor 는 `/balance` 가

## 6. ★ Caja Fuerte 일별 원장 — 설계 확정, 구현 미착수

**목업**: https://claude.ai/code/artifact/84e8d333-521c-4075-9712-780efade3f40
(coolsistema 실제 원장 71건 · 56일. 날짜별 등식 전부 검산 후 사용)

### 사용자가 요구한 것 (그대로 옮김)
1. 「몇일 몇시 얼마로 시작 → 얼마 들어옴 → 그래서 얼마」 형태의 **날짜별 서술**
2. **카하를 이름으로** — `cash_register_id` 는 매일 바뀌는 **세션 id** 라
   같은 서랍이 257·295·299 로 보인다. 사람에겐 `Caja 1`/`JuanaCaja` 가 맞는 단위
3. 누계는 **마지막으로 금고를 0으로 비운 날 이후**만. 전 기간 누계는 의미 없다
   (사용자는 마지막으로 비운 날을 기억한다)
4. 지금 0이면 **그 이전 0부터의 누계**를 보이고 「그래서 지금 0원」이라고 말할 것
5. 하루를 넘으면 **「며칠부터 며칠까지 누계 얼마」**를 한 문장으로
6. `Salió del local` 은 **몇일 몇시 누가** 가져갔는지 기록

### 설계 결정
- **구간(ciclo)** = 잔액이 0이 된 지점이 경계. 지금 0이 아니면 「마지막 0 이후~현재」
  (`EN CURSO`), 지금 0이면 「그 이전 0 이후~비운 시점」(`CICLO CERRADO`)
- ★ **표시는 서랍 이름, 짝 판정은 세션 id.** 이름으로 개시금↔마감을 이으면
  **같은 서랍의 다른 날이 잘못 묶인다**(서랍 1개인 지점은 전부 한 덩어리가 된다)
- 「0」이라는 숫자만 두면 **「아직 없다」와 「방금 전부 꺼냈다」가 같은 픽셀** →
  총계 라벨을 `Debería haber ahora` ↔ `Quedó en` 으로 바꾸고 이유를 문장으로
- 실측 참고: coolsistema 는 0이 **6회** 있었고, 유출 6건 **전부 `jungho kim`**

### 구현에 필요한 것 (미착수)
1. **카하 이름** — `/operations` 응답에 `cash_registers → boxes.name` 조인 추가.
   지금 `CajaFuerteOperationsTable.etiquetaMovimiento()` 가 세션 번호를 찍는다
2. **유출자** — `/balance` 의 `desglose` 에 `admin_retiro` 목록(일시·사용자·사유·금액)
3. **구간 누계** — ★ 가장 큰 변경. `getBalance` 가 지금 **전 기간**을 센다.
   구간 기준으로 바꾸면 **화면 숫자가 전부 달라지고**, 오늘 넣은 `calcularDescuadre`
   자기검증도 구간 기준으로 같이 옮겨야 한다
4. **일별 접기** — `/daily` 를 출처별 분해 + 시작 잔액까지 주도록 확장.
   FullTable(AG Grid)이 그룹 행을 지원하지 않아 표 컴포넌트 손질 필요

## 8. 이번에 배운 것

1. **「끝났다」고 말하기 전에 세어 볼 것.** 사용자가 「caja fuerte 다 끝났나」고 묻기
   전까지 P2 #1·#5 가 남은 줄 몰랐다. 끝났다고 **보고한 적은 없지만** 끝난 것처럼
   들리게 보고했다.
2. **내 근거가 틀렸는데 결론이 맞을 수 있다.** 금액 센타보화는 할 가치가 있었지만
   내가 제시한 이유 셋 중 셋이 틀렸다. 결론이 살아남았다고 근거를 검증 안 하면
   다음에 같은 근거로 틀린 결론을 낸다.
3. **대조군이 헛통과하는 것을 두 번 겪었다.** 「구분된다」를 계산으로 확인했다고
   믿었는데 spec 에 넣은 값이 달랐다. **실제로 돌려 보기 전까지는 모른다.**
4. **돌연변이가 컴파일을 깨면 `Tests: 0` 이 나오고 통과처럼 보인다.**
5. **내가 만든 검증 장치를 내가 새로 만든 화면에 안 붙였다.** 목업의 잔액 카드에서
   `Otros retiros −1` 을 빠뜨려 식이 안 맞았는데, 같은 날 구현한 자기검증을
   목업에 넣지 않아 조용히 지나갔다. 사용자가 눈으로 잡았다.
6. **조회에서도 같은 실수를 한다.** 코드에 「필터가 걸려도 잔액은 전체 원장 기준」이라고
   적어 놓고, 내 SQL 조회에서 날짜로 거른 뒤 누적해 **음수 잔액**을 뽑았다.
