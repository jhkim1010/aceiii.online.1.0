# PLAN — CUIT 를 치고 Tab 하면 이름·주소가 채워진다 (DB 우선 → ARCA 폴백)

사용자 요구 (2026-09-25):
> 「venta 부분에서 새 고객 cuit을 적고 탭을 누른 순간… ARCA 로 접근해서 그 사람의
>  이름, 주소 등을 가져오게」 →
> 「먼저는 내 데이터 베이스 속에서 자료를 찾게 하고. 없을 때 사용하도록」
> 「11글자의 숫자를 넣고 tab 을 할 때 그 때만」

---

## 0. ★★ 짓기 전에 잰 것 — 이 숫자들이 설계를 정한다

### 0-a. 고객은 **`clients.document`** 로 식별된다 — `cuit` 컬럼은 **없다**

```
information_schema: 'cuit|documento|dni' 로 잡히는 컬럼 16개 중
고객 테이블은 **하나도 없다**. clients 의 식별자는 `document`(varchar) 뿐이다.
```
⤷ 새 컬럼을 만들지 않는다. **`document` 가 CUIT 이 사는 자리**다.

### 0-b. 그 안에 실제로 무엇이 들어 있나 (운영, store 전체)

| `document` 숫자 길이 | 건수 | 그중 주소 있음 |
|---|---|---|
| **11 (CUIT)** | **546** | **545** |
| 8 (DNI) | 26 | 2 |
| 6 | 24 | 1 |
| 12 | 3 | 3 |
| 기타(7·9) | 4 | 1 |
| **합계** | **604** | |

`global_clients`: **4,296행, 전부 document 보유.**

★★★ **이 표가 「DB 우선」을 정당화한다.** 11자리인 546건 중 **545건이 이미 주소를 갖고
  있다.** 즉 기존 고객은 ARCA 를 부를 필요가 **거의 없다**. ARCA 는 **진짜 새 손님**에게만
  쓰인다 — 사용자가 말한 그대로다.

★ 그리고 `document` 에는 11자리가 아닌 것이 **58건** 있다(DNI·짧은 번호). 그래서 발동
  조건을 「11자리」로 거는 것은 **기존 데이터를 깨지 않는다** — 그 58건은 지금처럼
  손으로 입력하는 흐름 그대로다.

### 0-c. ARCA 쪽은 **이미 만들어져 있다**

`api-ventago/src/app/afip/padron-a5.service.ts` (2026-08-10) —
`ws_sr_constancia_inscripcion`(Padrón A5).
```
GET /afip/padron/:cuit   @Auth(admin, superadmin)
→ { found, persona: { razonSocial, nombre, apellido, domicilio{...} } }
```
**새로 만들 것이 아니라 배선할 것이다.**

## 1. ★★★ 시작 전 반드시 해소해야 하는 것 — 코드가 아니다

**AFIP 포털 → Administrador de Relaciones 에서 인증서 별칭 `CNCOOLSISTEMA2024` 에
`ws_sr_constancia_inscripcion` 위임.**

위임 전에는 **WSAA 가 티켓 자체를 주지 않는다.** 코드를 다 붙여도 한 줄도 동작하지 않는다.

확인 방법(확정적):
```
GET /afip/padron/diagnose      (superadmin)
→ ticketObtained / ticketError
```
운영 인증서 폴더(`/app/certificates/coolsistema`) 실측: `CNCOOLSISTEMA2024` · `cert` ·
`key` · `.lastTokens` · `token/` — **이 서비스의 흔적 없음 → 아직 위임 안 된 것으로 보인다.**

⤷ **이 단계가 끝나기 전에는 3~5 를 시작하지 않는다.** 시작하면 「실행된 적 없는 코드」가 된다.

---

## 2. ★★ 양보할 수 없는 제약 (실측 근거 있음)

### ① 인증서를 공유한다 — **청구서 발행과 같은 인증서**
Padrón 호출에 쓰는 인증서는 **wsfe(CAE 발급)와 같은 것**이다. 그 폴더의 `.lastTokens` 는
「캐시」로 보이지만 사실 **잠금**이고, 잘못 다루면 **최대 12시간 발급 불가**가 된다.
⤷ **캐시는 선택이 아니라 필수.** 같은 CUIT 은 한 번만 묻는다.

### ② POS 를 멈추면 안 된다
AFIP SOAP 은 느릴 때가 있다. Tab 에 동기로 물리면 계산원이 그 자리에서 기다린다.
⤷ **짧은 타임아웃 + 실패는 조용히.** 못 가져와도 판매는 그대로 진행된다.

### ③ 인증서 없는 매장이 다수다
운영 인증서 폴더에 있는 것은 `coolsistema` 와 homo 하나뿐. NOIX 등은 **애초에 못 부른다**.
⤷ 기능이 **그냥 안 뜬다**. 오류를 띄우지 않는다.

### ④ 프라이버시는 **쟁점이 아니다** (2026-09-25 정정)
ARCA 는 아무 CUIT 이나 로그인 없이 보는 **Constancia de Inscripción** 공개 페이지를
운영한다. 「계산원이 남의 상호·주소를 본다」는 공개된 것을 보는 것이고, 막아도 보호가
안 된다. 처음에 이것을 위험으로 적었던 것은 **틀렸다.**
⤷ 남는 것은 ①②③ 뿐이고, 그중 **①이 제일 크다**(발행이 멈춘다).

## 3. 조회 순서 — 한 곳에서 정한다

```
11자리 + 검증숫자 통과 + Tab + 값이 바뀜
   │
   ├─ 1) clients        (이 매장, document = CUIT)        ← 546건 중 545건이 주소 보유
   ├─ 2) global_clients (전 매장 공용)                     ← 4,296건
   └─ 3) ARCA Padrón A5 (1·2 에 없을 때만)                 ← 진짜 새 손님
```

★★ **판정은 `.ts` 한 곳에** 둔다(`resolver-cuit.ts`). 이 저장소 jest 는 `.tsx` 를
  import 하지 못하므로, 화면 안에 둔 판정은 **영원히 검증되지 않는다.**

★ **`global_clients` 는 읽기만 한다.** 절대 쓰지 않는다(상시 규칙).

★ 응답에 **출처**를 같이 싣는다(`origen: 'cliente' | 'global' | 'arca'`). 화면이
  「ARCA 에서 가져옴」을 표시하려면 필요하고, 나중에 「ARCA 를 몇 번 불렀나」를
  세는 유일한 근거가 된다.

## 4. 발동 조건 (사용자 지시 + 하나 추가)

| 조건 | 왜 |
|---|---|
| 정확히 **11자리 숫자** | 사용자 지시. DNI(8자리) 흐름을 안 건드린다 |
| **검증숫자(dígito verificador) 통과** | 오타가 ARCA 까지 가지 않는다. 호출 수를 더 줄인다 |
| **Tab(onBlur)** — 타이핑 중엔 안 부름 | 사용자 지시 |
| **값이 직전과 다를 때만** | 같은 칸을 두 번 나가도 두 번 안 부른다 |
| 이미 이름이 채워져 있으면 **덮지 않음** | 사람이 고친 것을 기계가 되돌리면 안 된다 |

## 6. 하지 않기로 한 것

- **`cuit` 컬럼 신설 금지.** `document` 가 그 자리다. 새 컬럼은 두 개의 진실을 만든다.
- **타이핑 중 조회 금지.** 11자리에 닿기까지 10번을 부르게 된다.
- **실패 시 판매 차단 금지.** ARCA 가 죽어도 장사는 된다.
- **감사 로그·분당 제한을 프라이버시 이유로 넣지 않는다** (§2-④). ①을 위한 캐시는 넣는다.
