## 2. 전제가 틀렸던 것 — 핸드오프 항목 ①

**「PM2 4워커 + socket.io Redis 어댑터 없음」은 사실이 아니었다.**
어댑터는 `api-ventago/src/common/socket/redis-io.adapter.ts` 에 이미 구현·배선돼 있고
(`main.ts:78-92`), 운영 4워커 전부 `redisAdapter:"on"` 이었다.

진짜 공백은 **둘**이었다:

1. `adapterStatus.redisAdapter` 가 **부팅 시 1회만** 설정된다 → 부팅 후 Redis 가 죽으면
   워커 간 emit 이 유실되는 동안에도 health 가 `"on"` 을 찍는다.
   **인쇄 명령이 사라지는데 계기판은 초록불이다.**
2. `ventago-health-watch.sh` 가 **`redisAdapter` 를 아예 안 봤다** (HTTP 200 만 봤다).

⤷ **항목이 맞아도 근거·범위가 틀릴 수 있다.** 실측 먼저.

## 5. 이번에 배운 것 (다음 사람이 같은 실수를 안 하도록)

1. **돌연변이가 컴파일되는지 확인할 것 — 반대 방향으로도.**
   `if (false && x)` 로 만든 돌연변이가 «죽었다»고 나왔는데, 실제로는 **TS 오류**였다.
   진짜 돌연변이(블록 삭제)로 다시 하니 **생존**했다 — `attachSaleId` 를 지키는 검사가
   아예 없었다. 컴파일 오류는 검증이 아니다.

2. **시험 하네스가 운영과 다른 서식을 내면 검사가 헛통과한다.**
   가짜 health 서버가 `json.dumps` 기본값(콜론 뒤 공백)을 냈고, 내 sed 는 압축 JSON 만
   알아서 **아무것도 못 보고** 「이상 없음」을 냈다. 대조군(정상)까지 실패해서 잡혔다.
   → 파서를 공백에 견디게 고쳤다. **운영 서식을 흉내내는 것이 하네스의 일이다.**

3. **「없다」와 「깨졌다」를 같이 처리하면 더 나빠질 수 있다.**
   날짜 파싱 실패를 전부 `now` 로 덮으니 «Invalid Date» 는 사라졌지만
   **그럴듯하지만 틀린 날짜**가 남았다. 아무도 신고하지 않는 오류가 더 비싸다.

4. **재생(replay)은 「아무것도 안 하기」가 아니다.**
   멱등 재생에서 인쇄와 QR 인텐트를 건너뛰게 만들었더니, 커밋 직후 죽은 경우에
   **주방이 주문을 영영 모르고 · 손님이 스캔할 QR 이 없는 주문**이 남았다.
   → 신규와 재생이 **같은 코드**를 지나게 하고, 중복은 `printJobId` 원장에 맡겼다.

5. **CODEX 는 `codex exec` 로 프롬프트만 주면 멈출 수 있다.**
   1차 자문(코드 없이 설계 질문)은 50분간 0바이트였다. **diff 를 함께 넘긴** 2차는
   ~25분에 결과가 나왔다. 서브모듈이 있으므로 `--working` 대신 diff 를 직접 만들어 넘긴다.
