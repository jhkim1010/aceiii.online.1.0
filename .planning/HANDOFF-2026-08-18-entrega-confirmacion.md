## Phase 82 마무리 — 도착일과 클릭 시각을 가르다

CODEX 가 미배포 코드에서 **Blocker 4건**을 잡았고 전부 수용:

- ★ **UTC 정오 기준은 UTC+12 이상에서 다음 날이 된다** (리포의 테스트가 Kiritimati 를
  쓴다). → `store-day.util.ts` 로 **매장 현지 정오**를 만든다.
- ★ `new Date('2026-02-31')` 은 **3월 3일로 굴러간다.** 정규식만으로는 없는 날짜가
  통과한다 → 재구성 후 대조하는 엄격 파싱.
- ★ 도착일을 비우면 조용히 클릭 시각으로 돌아가 **기능이 무력화**된다 → 필수(400) + 버튼 비활성.
- 프론트 `toISOString()` 은 UTC 라 아르헨티나 21시 이후 **내일** 날짜를 채워 서버가 거부했다.

그 외 수용: id 중복 제거 · 이미 delivered 는 실패가 아니라 no-op ·
내부 예외 문구 비노출 · 상한 100→50 · 역할을 단건 deliver 와 같은 집합으로(+envioManager).

**검증 규칙**은 매장 달력 날짜로만 하고(미래/발송일 이전), **시각은 구간 안으로 당긴다**
(현지 정오 → now → shippedAt). 안 그러면 오늘 오전 확인과 같은 날 배달이 거부된다.

## Phase 83 — 고객 배달 확인 링크 (W1+W2 배포)

### 스키마
`delivered_on`(도착일·KPI 근거) · `delivered_confirmed_by`(customer|staff) ·
`delivered_confirmed_at`(클릭 시각) · `delivery_dispute_at/note/resolved_at/by` ·
`confirm_token`(+만료, 부분 UNIQUE). CHECK 로 토큰↔만료 쌍을 강제.
기존 행 `delivered_on` 은 **리포트가 계산하던 값과 정확히 같게** 채워 숫자가 안 움직인다.

### CODEX Blocker 2건 (배포 전 수정)
1. ★ **토큰이 모든 HTTP 로그에 평문으로 남았다.** 이 토큰은 식별자가 아니라 **권한**이라
   로그 열람 권한이 곧 주문 조작 권한이 된다.
   → 토큰을 **URL 에서 body 로** 옮겼다(전부 POST). `sanitizeUrlForLog` 는 이중 방어로 남김.
   부수 효과 하나가 이롭다: **링크 미리보기 봇이 GET 으로 주문을 열어보지 못한다.**
2. ★ **un-ship 후에도 기존 링크가 살아 있었다** — 아직 안 보낸 주문에 고객이 분쟁을
   등록하고 화면은 `en_transito` 라고 거짓말했다.
   → 토큰 해석에 `shippedAt != null && status in (SHIPPED, DELIVERED)` 를 요구.
   토큰 자체는 여전히 안 지운다(재발송하면 같은 링크가 다시 살아야 한다).

### 설계에서 뺀 것 / 더한 것
- ★ 원안의 *"직원 확인 → 그것에 고객이 OK"* 마지막 단계는 **뺐다**: 고객이 첫 번째를
  안 눌러 대행하는 건데 결과를 다시 고객 OK 에 걸면 주문이 계속 열린 채 남는다. 침묵=동의.
- ★ **자동 확인 금지** — 레거시 폴백(`mirrorSaleId == null`)이 매출·외상을 만든다.
  공개 확인도 그 주문은 거부하고 직원에게 넘긴다(변이 테스트로 가드 확인).
- ★ **분쟁 해소 경로**를 더했다(CODEX). 없으면 한 번 올라온 분쟁이 영원히 목록에 남아
  결국 아무도 안 본다. 신고 기록 자체는 지우지 않는다 — 반복 패턴을 봐야 하므로.
- ★ **retiro 증거 승격**: 인계 시 이미 entregado 인 건에 고객이 QR 을 누르면
  상태·원장은 그대로 두고 `deliveredConfirmedBy` 만 staff→customer.
  이걸 no-op 로 돌려보내면 **가장 확실한 확인이 기록되지 않는다.**

### KPI 를 delivered_on 으로 전환
소요일 평균·P90·운송사별·발송→배달 구간·전 구간 여정을 전부 **도착일 기준**으로 바꿨다.

## 작업 방식 — 이번에 걸린 것

- ★ **미배포 워킹트리가 운영 장애다.** 프론트만 배포된 상태로 밤을 넘겼다.
  세션 시작 시 `git status` 를 먼저 본다 — 남은 변경이 "아직 안 한 일" 이 아니라
  "이미 깨진 것" 일 수 있다.
- ★ **모델에 컬럼을 더하면 마이그레이션 전에는 push 할 수 없다.** Sequelize 가 SELECT 에
  넣으므로 스키마가 없으면 그 테이블 조회가 전부 500 이 된다. 순서: 마이그레이션 → push.
- ★ **로그에 남는 값이 권한이면 그건 유출이다.** URL 은 우리 로그·nginx·Referer 로
  퍼진다. 자격증명 성격의 값은 처음부터 body 로 받는다.
- ★ 정적 모델(`Store.findByPk`)을 서비스에서 부르면 **유닛 테스트가 DI 없이 죽는다.**
  주입된 `sequelize.query` 를 쓰고, 설정값 조회는 **트랜잭션 밖**에서 한다
  (tx 안의 실패는 그 트랜잭션 전체를 중단시킨다).
- ★ **테스트가 새 의도와 충돌하면 기대값을 고친다.** "재확인은 아무것도 저장하지 않는다"
  가 증거 승격을 막고 있었다 — 단언을 "원장·상태 무변경" 으로 정정.
