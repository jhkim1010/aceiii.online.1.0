## 왜 빠졌나 — 한 줄

기준선이 **`store_id` 컬럼**을 소유권 권위로 썼다. 관계로만 매장에 닿는 테이블은
`regen-store-backup-inventory.sh:29` (`col.column_name = 'store_id'`) 와
`store-backup-coverage.spec.ts:154` (`/\bstore_id\b/.test(body)`) **둘 다** 통과한다.
감시가 두 겹인데 **두 겹이 같은 맹점을 공유**했다.

새 기준(= `stores` + `store_id` 보유 테이블에서 출발한 FK 도달 폐포)으로 바꾸면
테넌트 테이블은 **180개**가 되고, 그중 **42개가 미선언**으로 드러난다.

## ⑥ 별개 문제 — FK 가 없어서 그래프가 거짓말하는 테이블 (4)

관계 도달성으로 바꿔도 **FK 제약이 없으면 안 잡힌다.** 실측:

| 테이블 | 행 | 상태 |
|---|---:|---|
| `talleres_deliveries` | 0 | **FK 0개** — `subcon_order_id` 가 있는데 제약이 없다 |
| `talleres_payments` | 0 | **FK 0개** |
| `talleres_material_issues` | 0 | **FK 0개** — `product_id`·`subcon_order_id` 보유 |
| `talleres_defects` | 0 | **FK 0개** |

앞의 둘은 백업 대상으로 **이미 선언돼 있다**(사람이 손으로 넣었다). 뒤의 둘은 아니다.
→ **FK 를 추가해 그래프가 사실을 말하게 한다.** 네 테이블 모두 0행이라 잠금 위험이 없다.
  (안 하면 새 기준선이 이들을 "전역" 으로 오분류한다.)
