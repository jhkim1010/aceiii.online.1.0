## 1. 판매가 통째로 막히던 500 ✅ (운영 장애)

**증상**: `POST /sales` → 500 `current transaction is aborted, commands ignored until end of transaction block`

**그건 증상이었다.** 앱 로그에는 원본 오류가 **없었다.** PostgreSQL 로그에만 있었다:
```
ERROR: stock no puede registrarse en un codigo madre:
       product_id=364 tiene 50 variantes activas (product_branch_id=601).
```

**원인**: 변형(색·talle)을 고르지 않은 **códigos madre 줄**이 장바구니에 남은 채 판매가
확정되면 `applyStockLedger` 가 그 **부모** ProductBranch 에 원장을 쓰려다
`trg_stocks_leaf_only` 에 막힌다. 트랜잭션이 죽고 이후 문장이 전부 aborted 가 되며
**원인이 덮인다**(이 파일 F-11 주석이 이미 경고하던 형태).

**왜 "판매 자체가 안 되는" 것처럼 보였나**: 카트가 유지되므로 그 줄이 남아 있는 한
**모든 판매 시도가 실패**한다. 실제로 그 줄이 없는 판매는 같은 시각대에 201 로 성사됐다.
두 번 재현됐고 제품이 달랐다 — 364 `[POLO] 2270 KRENCIA`(변형 50) / 264 `CAMISA TRAVELL`(변형 16).

**수정**: 읽기·검증만 하는 단계에서 조기 차단 + 상품명 안내로 **400**.
- 판정은 트리거와 **똑같은 정의** — `is_parent` 플래그가 아니라 **자식 수**
  (`parent_id` = 이 상품 AND 같은 store AND `status <> 'deactivated'`). 트리거도 플래그를 안 본다.
  플래그에 기대면 데이터가 어긋났을 때 가드는 통과시키고 트리거는 막는 갈라짐이 생긴다.
  자식 0 인 단품은 트리거가 허용하므로 여기서도 막지 않는다.
- **조용히 skip 하지 않는다** — 재고 차감 없이 판매가 성사되면 원래 버그보다 나쁘다.
- 품목 수와 무관하게 1쿼리. 던지는 시점에 아직 INSERT 가 없어 부분 저장이 없다.

`api 3915ae4` (#671 SUCCESS, dist 에 문자열 존재 확인)

**남은 것**: 프론트가 변형 수량 0인 마드레 줄을 F2 에서 막아야 한다.

## 2. 재고 매트릭스가 제품 선택 시 500 ✅ (운영 장애)

`GET /reports/stocks-cockpit/matrix` → 500 `table name "br" specified more than once`

Phase 73 리팩터(`7a8fd82`)가 `BRANCH_JOIN`(= `JOIN branches br`)을 넣으면서 **그 전부터 있던
`LEFT JOIN branches br` 을 안 지웠다.** 같은 SELECT 에 같은 별칭 두 번 → PG 거부.

중복된 LEFT JOIN 제거. `BRANCH_JOIN` 이 남는 게 맞다 — `is_active` + `store_id` 를 강제하는
단일 출처이고 2026-08-08 에 의도적으로 도입됐다.

**왜 기존 테스트가 못 잡았나**: `reportsStocksCockpit.matrix.spec.ts` 는 `sequelize.query` 를
mock 한다. SQL 이 실행되지 않으므로 **문법·별칭 오류는 DB 만 안다.**
→ **생성된 SQL 문자열에서 별칭 중복을 검사**하는 회귀 테스트 추가(getMatrix + getItems).

검사기를 처음엔 단순 정규식으로 썼더니 `d` 를 중복으로 잡았다 — 서로 다른 스칼라 서브쿼리
안이라 유효한 SQL 인데 **거짓 양성**이었다. 괄호 블록을 접어 바깥 스코프만 보도록 고쳤고,
서브쿼리 재사용이 위반이 아님을 테스트로 고정했다.

검증: 뮤테이션(중복 JOIN 복원) → 해당 테스트만 사멸. **수정된 SQL 을 운영 DB 에 읽기 전용으로
직접 실행**해 정상 동작·두 지점 행 확인(productId=281).
