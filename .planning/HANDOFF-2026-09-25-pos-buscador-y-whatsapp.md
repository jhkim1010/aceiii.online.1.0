## 2. 한 것 — POS 상품 검색 두 건

### 2-a. 목록 가격이 **청구 가격과 달랐다** (사용자 보고)

사용자: NOIX 에서 한 상품이 검색 목록에 **가격 없이** 나온다. 「물론 선택하면 가격은
다 잘 나와.」 ← 이 한 문장이 진단 전체였다: **목록과 선택이 서로 다른 규칙**을 썼다.

`ProductsInputs.tsx` 의 `renderOption` 이 `option.prices?.[0]?.amount` 를 썼다.
거기서 결함이 **둘** 나왔다:

| | 무엇 | 실측 |
|---|---|---|
| ① | `prices` 행이 없으면 **빈칸**. 기준가(PRECIO 1)는 행 없이 `products.price` 에만 사는 경우가 많다(`BasicDataCard` 가 `increaseValue!==0` 만 행으로 만든다) | NOIX **15/174** |
| ② | `prices[0]` 은 「첫 행」이지 PRECIO 1 이 아니다 → **틀린 가격을 보여준다** | 전체 **19건** (coolsistema 16 · ACE 2 · **NOIX 1**) |

②의 NOIX 사례: `2515014-V [SHORT POLLERA] MICROFIBRA` — 목록 **PRECIO 5 $4.500** /
실제 **$5.000**. coolsistema 는 **$19.400 vs $50.000** 이었다.

★★ ②가 ①보다 위험하다. 빈칸은 눈에 띄어 보고가 들어오지만(이번이 그랬다),
  틀린 숫자는 **멀쩡해 보여서 판매원이 손님에게 말해 버린다.**

★ **정직하게 남길 것**: 「첫 행」을 `id` 순으로 재었다. API 가 `prices` 를 가져올 때
  **명시적 정렬이 없어서** 배열 순서가 항상 id 순이라는 보장은 없다. 「틀릴 수 있었다」는
  확실하고, 「그 19건이 매번 그렇게 보였다」는 단정할 수 없다.

**고친 방식**: 규칙을 더한 게 아니라 **두 번째 규칙을 지웠다.** 목록이 판매와 같은
`pickDefaultPriceType` + `resolveAmountFor` 를 쓴다.

### 2-b. 검색 결과가 정렬돼 있지 않았다 (사용자 요청)

원인: 카탈로그가 `productStock.service.ts:1709` 의 `order: [['id','DESC']]` — **등록
역순**으로 온다. 이름과 무관해 무작위로 보인다.

★ **서버 `ORDER BY` 를 안 바꿨다.** 두 가지 때문:
  · 그 쿼리엔 `pageSize=1000` 상한이 있다. `id DESC` 에서 잘리는 건 **오래된 것**,
    `name ASC` 면 **알파벳 뒤쪽** — 사라지는 상품의 집합이 달라진다. 오늘은 어느 매장도
    상한에 안 닿지만(최대 400 미만), 닿는 날 **조용히** 그리고 「그 상품을 못 판다」로 바뀐다.
  · 목록은 카탈로그 + 검색결과(`serverMatches`)를 **섞는다**. `ORDER BY` 는 앞 절반만
    정렬한다. 그래서 **섞은 뒤** 클라이언트에서 정렬한다(시험이 그 순서를 고정).

`orden-catalogo.ts` 가 고정하는 것: 원본 불변 · `numeric`(TOP 2 < TOP 10) ·
악센트/대소문자 무시 · **이름 없으면 맨 뒤**(맨 위 빈 줄은 「깨졌다」로 읽힌다) ·
SKU 로 안정 정렬(렌더마다 줄이 바뀌면 누르려던 줄이 움직인다).

## 3. ★★ 이 세션에서 배운 것

### ① 「선택하면 잘 나온다」는 **두 규칙이 있다**는 신호다

사용자의 그 한마디가 원인을 바로 가리켰다. 같은 질문에 답이 두 개 있으면, 눈에 덜 띄는
쪽이 틀린 채로 오래 산다. ⤷ **같은 값을 두 곳에서 계산하면 반드시 갈라진다.**

### ② 소스 문자열 검사는 **제 주석에 걸린다** — 오늘만 세 번

「`prices[0]` 이 없어야 한다」 검사가 그 문구를 인용한 **내 주석**에 걸렸다. 같은 일이
`width: 186` 에서도, 「Efectivo (Alt+1)」에서도 났다.
⤷ **소스 문자열 검사를 쓸 때는 처음부터 `sinComentarios` + 양방향 대조군**을 넣을 것.
  (지우면 코드가 남는가 / 주석은 정말 지워지는가 — 둘 다 재야 한다.)

### ③ 배포 확인을 **상수명·함수명으로 하면 안 된다**

minify 가 지운다. 0건이 「미배포」가 아니라 **검사가 틀린 것**이다.
그리고 `grep -c` 는 0 을 출력하고 exit 1 을 내므로 `|| echo 0` 이 0 을 덧붙여
**거짓 통과**를 만든다. 빌드는 번호가 아니라 **커밋 SHA** 로 찾을 것.
