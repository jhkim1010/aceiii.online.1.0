## 1. Caja Fuerte — 앞 핸드오프 §6 의 4가지 전부 완료

| # | 내용 | 어떻게 |
|---|---|---|
| 1 | 카하 **이름** | `/operations` 에 `cajas`(세션 id → `boxes.name`). storeId 로 조인. 모르면 「caja no identificada」 |
| 2 | **유출자** | `/balance` 에 `salidas[]` — 일시·사용자·사유·금액. 합계와 **같은 범위** |
| 3 | **구간(ciclo) 누계** | 순수 함수 `ciclo.ts`. 마지막으로 0 이 된 뒤부터 |
| 4 | **일별** | `/daily` 에 `saldoInicial`·`saldoFinal`·출처별 분해. 새 패널 `CajaFuerteDiario` |

### ★★ 구간 전환이 쉬웠던 이유 — 불변식이 살아남는다
경계에서 잔액이 **0** 이었으므로 **구간의 순합 = 현재 잔액**이다. 그래서
`cierreCaja + otrosIngresos − aperturaCaja − salidaExterna − otrosRetiros = balance`
가 그대로 성립하고, 화면의 자기검증(`descuadre.ts`)을 **한 줄도 안 건드렸다.**

### ★★★ 사용자가 잡은 것 둘 (내가 빠뜨렸다)
1. **누계 금액이 없었다.** 요구 5번은 「며칠부터 며칠까지 **누계 얼마**」인데
   날짜만 넣어 문장의 절반이 빠져 있었다.
2. **「비운 날」이 틀렸다.** `ciclo.desde` 는 **구간의 첫 이동**이지 0 이 된 시각이
   아니다. HELGUERA 는 10/09 22:13 에 비우고 11/09 00:00 에 첫 마감이 들어왔는데
   「11/09 에 비웠다」로 읽혔다. → `vaciadoEn` 을 따로 낸다.

### 실측 검산 (운영, 읽기 전용)
- `/daily` 누적 사슬: coolsistema(caja 5) 09-02 가 **788,000 에서 시작**하고
  날짜별 `saldoInicial = 전날 saldoFinal` 이 전부 이어진다(창 밖까지 누적한 결과).
- HELGUERA(caja 7): 마지막 0 이 27번째 행 → 구간은 **1건**, 135,000.
  화면 문장: `Desde que se vació el 10/09/2026 10:13 p. m. · hasta 11/09/2026 12:00 a. m. · entraron $135.000`
- 그래서 화면 숫자가 **전부 바뀐다**(2.618.698 → 135.000). 잔액은 그대로.

### 시험 유효성 — 돌연변이 6개 전부 죽는다
구간 자르기 제거 / 센타보 반올림 제거 / `cerrado` 고정 / `huboCeroPrevio` 고정 /
0 경계를 마지막 것으로 / `salidas` 뒤집기 제거.

★ **처음엔 하나가 살아남았다.** 픽스처로 고른 `0.1+0.2−0.3` 이 double 로 곱해
  더해도 **정확히 0** 이라 구분이 안 됐다. `1.1+2.2−3.3`(5.68e-14)로 바꿔야 했다.

★ 기존 `caja-fuerte-desglose.spec.ts` 는 구간 전환 뒤에도 **한 줄도 안 고치고
  통과했다** — 그 픽스처들이 0 을 한 번도 안 지나 두 구현이 구분되지 않는다.
  그래서 `caja-fuerte-ciclo-balance.spec.ts` 를 따로 만들었다.

## 2. ★★★ 레거시 임포트 — 경로가 **둘**이고 뒤쪽은 부를 수가 없었다

| 경로 | 담당 | HTTP |
|---|---|---|
| **한 방** `runImport(sqlText)` | 카탈로그 · **todocodigos** · **codigos** · 고객 · 판매원 | `POST /legacy-import/upload` |
| **스트리밍** staging + 매퍼 | **ventas** · 결제 · facturas · **gastos** · 재고 · 카하개시금 | ★ **없었다** |

매퍼 6종은 모듈에 provider 로만 있고 **부르는 컨트롤러·잡이 없었다.** 돌리는 것은
itest 뿐이었다 — 즉 화면의 「legacy importación」으로는 **판매·비용·팩투라가
한 건도 안 들어왔다.**

→ 사용자 승인(2026-09-11) 후 `ImportRunnerService` + 엔드포인트 둘을 만들었다:
  · `GET  /legacy-import/sesiones/:id/sucursales` — ACE sucursal 의 **근거**(추천 없음)
  · `POST /legacy-import/sesiones/:id/importar` — `{grupo, branchMap}`

★ 실행 가능 묶음: **③ 판매 · ④ 팩투라 · ⑥ 비용**.
  **②(재고)와 ⑤(외상·온라인)는 거절한다** — 재고는 코드↔ProductBranch 지도가
  없고 ⑤ 는 매퍼 자체가 없다. **빈 성공을 내지 않는다.**

★★ 돌연변이 4개 중 **둘이 처음에 살아남았다** — 가짜 DB 가 표 이름만 보고 답해서
  질의에서 `AND store_id = $n` 을 **지워도 검사가 안 죽었다**(매장 격리가
  사라졌는데 「7개 통과」). 가짜가 **SQL 을 해석**하게 고쳐야 했다.

## 3. ★★ 찾아낸 결함 — 부모 없는 살아 있는 상품이 사라진다

`buildCodeImportBatch` 가 `borrado=t` 를 부모·자식 **각각에서** 건너뛴다.
그래서 「부모는 지워졌는데 자식은 살아 있는」 조합이 샜다:

- 자식은 batch 에 들어가지만 `parentSku` 가 가리키는 부모가 없어 **조용히 skip**
- `errors[]` 에도 안 남고 `variants.skipped` 안에 섞여 **숫자로도 안 보였다**
- 이관 후 그 상품은 **POS 에서 팔 수 없다**(목록 where 에서 빠지면 끝)

실측: noix `26_185_2599012`(판매 이력 **22줄**) · charo4 **209건**.

### 고친 방식 — 몇 명이 그 부모를 가리키는가로 갈린다
| 경우 | 처리 | 오류 코드 |
|---|---|---|
| `todocodigos` 에 SKU 가 **지워진 채로** 있음 | 되살린다(원본이 정확) | `PARENT_REVIVED` |
| 행이 없고 자식이 **하나** | 자식을 **단품**으로 올린다 | `VARIANT_PROMOTED` |
| 행이 없고 자식이 **둘 이상** | 부모를 만들어 **묶음 보존** | `PARENT_SYNTHESIZED` |

★★★ 단품 처리가 이 모양인 이유. 색·사이즈를 안 쓰는 매장은 ACE 의 todocodigo 와
  codigo 가 **같은 코드로 1:1** 이고, 임포트는 그 둘을 **상품 하나**(자식 0)로
  합친다 — noix 141개, charo4 19,911개가 그 모양이다. 고아만 「없는 부모 SKU +
  자식」 쌍으로 만들면 같은 매장에 **두 모양이 섞이고 원본에 없는 상품이 생긴다.**
  ★ 자식 0 인 단품은 팔린다 — `madre-guard.ts` 판정이 「활성 자식 수」다.

★ 처음엔 자식을 `variants` 에서 **뺐다가 가격이 통째로 빠졌다**(precios=0).
  `ParentRowDto` 에는 `price` 하나뿐이고 **5슬롯은 variant 에만** 있다.
  지금은 자식을 남기고 `parentSku` 를 자기 자신으로 돌린다 → 구조가 완전히 같다.

    **진짜 천장이 아니다.** 진짜 천장은 **파싱 후 객체 크기**다.

    그 컨테이너의 Node heap 은 **4,144MB** 인데 이 파일 하나가 5.2GB 를 쓴다.
    즉 상한 65MB 는 **지금 이미 안전하지 않다**(가정이 아니라 실측이다).

`catalogo-una-vez.itest.ts` 가 `process.memoryUsage()` 를 직접 찍는다 —

## 8. 이번에 배운 것

1. **대조군이 통과하는 것을 세 번 겪었다.** 돌연변이 픽스처(`0.1+0.2−0.3`),
   가짜 DB 의 SQL 무시, `join` 이 0건 조인. 셋 다 **「통과」가 「지켜짐」이
   아니었다.** 통과를 보면 먼저 「이게 구분을 하긴 하나」를 물을 것.
2. **사용자가 내 구현의 빠진 절반을 잡았다.** 「며칠부터 며칠까지」만 보고
   「누계 얼마」를 흘렸다. 요구를 **문장째로** 옮겨 적고 하나씩 지울 것.
3. **비슷한 이름의 두 값을 섞었다.** `desde`(구간 첫 이동)와 `vaciadoEn`(비운 시각).
   하루가 밀리면 사용자의 검산이 통째로 안 된다.
4. **「기능이 있다」와 「부를 수 있다」는 다르다.** 매퍼 6종이 완성돼 있고 itest 도
   있었는데 **엔드포인트가 없어 아무도 쓸 수 없었다.** 모듈에 등록돼 있다는 것은
   배선의 증거가 아니다.
5. **OOM 을 「재실행 탓」으로 단정할 뻔했다.** 두 번 중 한 번은 populated 상태에서도
   통과해 가설이 틀렸다. 추측 대신 `process.memoryUsage()` 로 쟀다.
