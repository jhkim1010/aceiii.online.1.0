왜 길고, 왜 아마추어처럼 보이는가

진단

"정보가 많아서"가 아닙니다. 담긴 정보는 적고 포장이 큽니다.

구조 결함 — 카드가 이중으로 겹쳐 있다

  • SaleDetailPanel 이 각 블록을 <Card><CardContent> 로 감싸는데, 자식 컴포넌트도 각자 <Card> 를 렌더합니다 — 7개 중 5개가 그렇습니다. 결과는 테두리 2겹 · 패딩 2겹 · 그림자 2겹. 이게 가장 큰 원인이고, 취향 문제가 아니라 고쳐야 할 버그입니다.
  • 장식용 아바타 5개. 40~56px 원형 아이콘이 정보를 전혀 나르지 않습니다. 헤더 패딩까지 합치면 약 360px — 화면 하나에 가까운 높이를 장식이 먹습니다.
  • 총액이 두 번 나옵니다. SaleHeader 의 금액과 SaleSummary 의 TOTAL 이 같은 값입니다.
  • SaleHeader 는 전체 페이지용 hero 입니다 (p:4, 아바타 56px, h4+h3). 좁은 패널에 그대로 넣으니 "Venta #158" 이 페이지 제목처럼 커집니다.
  • 5열 표를 440px 패널에 넣었습니다 → 가로 스크롤바가 생깁니다. 좁은 칸에서 표는 거의 항상 집니다.
  • 값 하나에 줄 하나. "4 productos" · "15 unidades" 가 각각 한 줄 + Chip.
  • createdAt / updatedAt 이 카드 하나를 통째로 씁니다.

제안이 지키는 규칙

핵심

자주 묻는 것은 스크롤 없이

  • 상세를 열 때 확인하는 건 대개 번호 · 시각 · 상태 · 총액 · 결제수단 다섯입니다. sticky 머리말에 고정해 상품이 많아도 항상 보이게 합니다.
  • 총액은 한 번만.

좁은 칸에서는 표 대신 리스트

  • 5열 표는 440px 에서 반드시 가로 스크롤을 만듭니다. 왼쪽 이름/SKU, 오른쪽 금액을 우측 정렬 mono 로 두면 구분선 없이 눈이 정렬됩니다.
  • 색×사이즈는 표 대신 인라인 알약. 1색×4사이즈에 표 하나는 과합니다.

접어도 값은 보이게

  • Cliente / Pago / Entrega / Datos 는 접되 접힌 줄에 값을 같이 씁니다. 열어야만 알 수 있으면 접는 의미가 없습니다.
  • 내부 ID·생성/수정 시각은 「Datos」 안으로.

장식 제거, 위계는 크기와 여백으로

  • 아바타 원형 5개 전부 삭제. 구역 제목은 작은 대문자 라벨로 충분합니다.
  • 카드 중첩 대신 구분선. 좁은 패널에서 카드 안의 카드는 테두리만 두꺼워집니다.
  • 금액·ID·시각은 mono + tabular figures — 자릿수가 세로로 맞습니다.
