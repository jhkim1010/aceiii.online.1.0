Prioridad backend: DTO.provinceId → client.province_id → null. De esta forma un cliente registrado (ej. "Pedro González, Itapúa") llena la venta automáticamente, pero una venta anónima también queda localizada.

sales-create.service.ts (resolve)

// provincia 우선순위: DTO → cliente registrado → null
let resolvedProvinceId = createSaleDto.provinceId ?? null
if (!resolvedProvinceId && clientId && clientId !== 5) {
  const cli = await Client.findByPk(clientId, {
    attributes: ['provinceId']
  })
  resolvedProvinceId = cli?.provinceId ?? null
}

const sale = await saleModel.create({
  clientId,
  sellerId: sellerId || userId,
  provinceId: resolvedProvinceId,  // ← NUEVO
  totalAmount,
  ...
})

v_sale_item_dim (view)

-- unify: venta > cliente
COALESCE(s.province_id, cl.province_id) AS province_id,
COALESCE(prov_s.name, prov_c.name)      AS province_name
FROM sales s
LEFT JOIN clients cl   ON cl.id = s.client_id
LEFT JOIN provinces prov_s ON prov_s.id = s.province_id
LEFT JOIN provinces prov_c ON prov_c.id = cl.province_id
Un cambio en la view hace que el dashboard Provincia funcione sin tocar los 3 servicios que ya lo usan (breakdown('province'), turnover, pivot).
