로그에서 column "province_id" does not exist, column "linked_user_id" does not exist 에러가 반복 발생. 모델에 정의된 컬럼이 실제 DB에 없음.

sales-create.service.ts:116, 137

🔌 PostgreSQL 커넥션 풀

Critical Pool 설정 완전 부재

database.module.ts에 pool 관련 설정이 전혀 없음. Sequelize 기본값(min: 0, max: 5)만 사용 중. 동시 요청이 5개를 초과하면 대기열이 생기고, idle 커넥션도 즉시 반환되어 매번 재생성 비용 발생.

api-ventago/src/database/database.module.ts
pool: { min: 5, max: 20, idle: 10000, acquire: 30000, evict: 1000 } 설정 추가

Low 트랜잭션 명시적 롤백 부재

일부 서비스에서 sequelize.transaction() 자동 관리에 의존. 명시적 try/catch/rollback 패턴이 아닌 곳이 있음.

cashRegister.service.ts, public-purchase.service.ts
명시적 try/catch/finally 롤백 패턴 적용

api-ventago/src/common/middleware/http-logger.middleware.ts:19

api-ventago/src/common/socket/websocket.service.ts:71-81
disconnect 시 빈 Set 제거 로직 추가

Medium Cron에서 전체 Store 로드

store.cron.ts에서 매일 findAll()로 전체 매장 데이터를 제한 없이 메모리 적재.

⚡ Sequelize 쿼리 최적화

Critical N+1 쿼리 — 상품 조회

findFiltered()에서 페이지네이션된 상품 조회 후, 각 상품마다 getProductSubcategories() 개별 호출. 20개 상품 페이지당 최소 20개 추가 쿼리 발생.

api-ventago/src/app/products/products.service.ts:279-287
include에 Subcategories 통합하여 1회 쿼리로 해결

Critical N+1 쿼리 — Variants 생성

createVariantsBatch()에서 중첩 루프: variants × branches, 각각에서 Color/Size findByPk() + ProductBranch 조회/생성. 10 variants × 3 branches = 60+ 쿼리.

api-ventago/src/app/products/productStock.service.ts:77-165
Color/Size를 Map으로 사전 로드, bulkCreate 활용

High 과도한 Eager Loading

상품 관련 모든 조회(findAll, findFiltered, findOne)에서 동일한 8개 include 적용. 목록 조회에서도 Stocks, Discounts, Variants 재귀 등 불필요한 데이터까지 로드.

api-ventago/src/app/products/products.service.ts:223-241

대부분의 findAll/findOne에서 attributes를 지정하지 않아 불필요한 컬럼(description, imageUrl 등)까지 전부 조회.

products.service.ts, sales.service.ts, stocks.service.ts 전반
필요한 attributes만 명시적으로 지정

Medium Pagination 미적용

판매 내역, 클라이언트 목록 등 일부 findAll()에서 limit/offset 없이 전체 데이터 조회.
