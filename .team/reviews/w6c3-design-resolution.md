## E1 — 순서는 제약이지 의미가 아니다

> "소유권은 선언이 정하고 **삽입 순서는 DB 제약에서 계산**해야 한다."

맞다. 내가 "매니페스트가 권위" 를 **모든 것**에 적용하려 했는데, 순서는 의미 판정이 아니라
FK 라는 **사실**이다. 152개를 손으로 적으면 스키마가 바뀔 때마다 낡고, 낡은 줄도 모른다.
→ 카탈로그로 위상 정렬 + **순환 묶음과 해소 전략만** 선언 + 스키마/FK 집합이
   매니페스트와 다르면 거부 + 같은 레벨은 고정 정렬로 재현성 확보.

## E3 — NULL 은 정상값이라 "안 채웠다" 를 못 구분한다

내 계획의 구멍을 정확히 짚었다. 순환 컬럼을 NULL 로 넣고 나중에 UPDATE 하는데,
**UPDATE 를 빠뜨려도 NULL 은 FK 검사를 통과**한다. 그래서 DEFERRED 값마다
`원본이 NULL 이었는지` · `원본 FK 값` · `재매핑 대상 ID` · `해결 여부` 를 **원장으로 남기고**,
커밋 전에 `원본 non-NULL 인데 미해결` 0건을 확인해야 한다.
순환 컬럼이 NOT NULL 이면 이 방식 자체가 불가능하므로 DEFERRABLE FK 또는 스테이징이 필요하다.

## E4 — 공통 원인 실패 ★ 이번 자문의 핵심

> "백업과 복원 검증이 같은 SQL 을 공유하면 **`COALESCE` 우선순위가 틀릴 때 둘이 나란히
>  틀린 결과를 정상으로 판정**한다."

오늘 내가 `OR` → `COALESCE` 로 바꾼 그 우선순위가 바로 그 지점이다. 근거가 하나면
반증할 수단이 없다. → **검증은 백업 SQL 재실행이 아니라, 복원된 행에서 목적지 매장까지
관계 폐쇄를 역방향으로 증명**한다.

### 이 지적으로 **지금 바로 만든 것**

`api-ventago/scripts/check-tenant-ownership.sh` —
**DB 카탈로그(FK)에서만** 소유 관계를 유도한다. TypeScript 선언을 읽지 않는다.
`store_id` 가 없는 테이블의 각 행이 부모를 타고 닿는 **서로 다른 매장 수**를 세어,
0개(고아)와 2개 이상(**한 행이 두 매장에 걸침**)을 보고한다.

★ **첫 실행에서 내가 손으로 못 찾은 것을 하나 더 잡았다:**

| 테이블 | 고아 | 모호 | 내용 |
|---|---:|---:|---|
| `venta_suspendida_items` | 3 | **2** | 매장 3 보류판매 ← 매장 8 상품 (2026-03-31) |
| `qr_print_log` | 0 | **1** | 매장 6 지점에서 **매장 8 상품** 라벨 출력 (2026-07-16) ← **새로 발견** |
| `role_function_actions` | 96 | 0 | 전역 역할 — 정상 |
| `payment_methods_options` | 9 | 0 | 전역 결제수단 — 정상 |
| `user_roles` | 1 | 0 | 사용자·역할 둘 다 전역 |

모호 3건에서 **종료코드 1** 로 실패한다. 고아는 전역 데이터일 수 있어 실패시키지 않는다.

★ `stores` 자신은 제외했다 — 루트라 소유자가 없는 것이 정상인데, 빼지 않으면 매번
  "고아 11" 이 뜨고 곧 아무도 결과를 안 본다. **거짓 경보를 방치하면 진짜 경보도 묻힌다.**

## E6 — 자격증명 테이블 통째 건너뛰기는 과하다

비밀이 아닌 설정과 자식 관계까지 유실된다. → 비밀은 분리하고 복제 시
**비활성 "재인증 필요" 행**을 만든다.

## codex 가 짚은 가장 큰 누락

> "복원 세션의 **목적지 `storeId` 를 서버가 확정**하고, 입력 파일의 매장 ID 로
>  대체할 수 없게 해야 한다."

W6-C0 에서 "파일의 주장을 믿지 말라" 를 배웠는데, **목적지 매장에도 같은 원칙**이
적용된다는 것을 못 봤다. 엔진 구현 시 첫 줄에 넣는다.

## 남은 것 — W6-C3 은 이 세션에서 끝나지 않는다

codex 의 설계를 그대로 지으면 다음이 필요하다:
- 카탈로그 위상 정렬 + 순환 해소 전략 선언
- DEFERRED 값 원장 + 커밋 전 4종 검사
- 역방향 소유 증명 검증기 (**← 이번에 절반 완성: 감사 스크립트**)
- 모드별 실행기 2개 + 입력 스키마 검증
- 매장별 advisory lock + 복원 중 쓰기 차단
- `IN_PLACE_RECOVERY` 는 "T 이후 사실이 참조했는가" 로 경계 — 참조된 것은 안 되돌린다

복원은 **W6-C0 로 잠겨 있으므로 서두를 이유가 없다.** 잠금이 풀리는 조건은
`store-restore-contract.ts` 에 적혀 있고, 위 항목이 다 되기 전에는 풀리지 않는다.
