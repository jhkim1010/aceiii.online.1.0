## P1 — untracked 파일 누락 → 해소 (재작성)

지적 그대로 실재하는 결함이었다. `git diff HEAD` 는 추적 중인 파일만 보여주므로 아직 `git add` 하지 않은
신규 엔드포인트·마이그레이션이 검토에서 통째로 빠지고, **신규 파일만 있으면 "검토할 변경이 없습니다" 로
정상 종료해 검토를 우회**한다. 지적의 위험 서술이 정확하다.

재작성본은 `codex review --uncommitted` 를 쓴다 — CLI 문서상 "staged, unstaged, and untracked" 를 모두 포함한다.
자체 diff 생성을 없앴으므로 이 결함은 구조적으로 사라졌다.

## P1 — 따옴표 없는 비밀번호 → 수정함

재작성본은 diff 를 프롬프트에 싣지 않으므로(codex 가 저장소를 직접 읽는다) **리댁션은 더 이상 통제 수단이 아니다.**
남은 건 "저장소에 평문이 있다"는 경고 한 줄인데, 그 정규식이 따옴표를 요구해 YAML 형식(`password: secret123`)을
못 잡는 건 지적대로였다. 경고가 조용히 통과하면 경고가 없느니만 못하다.

수정: 따옴표 유무 모두 매칭 + `passwd`/`pwd` 변형 포함.
```
(password|passwd|pwd)[[:space:]]*[:=][[:space:]]*['"]?[^'"[:space:]<][^'"[:space:]]{5,}
```

**다만 범위를 분명히 해둔다.** 이건 경고이지 차단이 아니다. `codex review` 는 저장소 파일을 직접 읽으므로
스크립트가 무엇을 보내는지 통제하지 못한다. 실제 통제는 두 가지뿐이다 — AGENTS.md 의 금지 규칙(모델 지시),
그리고 **태스크 004(평문 제거) + 005(회전)**. 리댁션 정규식을 아무리 다듬어도 저장소에 값이 남아 있는 한 근본 해결이 아니다.

## P2 — ARG_MAX → 해소 (재작성)

타당한 지적이다. 27KB diff 로 시험했을 때는 통과했지만 `ARG_MAX` 는 환경 의존이고, 스크립트가 명시적으로
"수십 KB diff" 를 상정하고 있었으니 시간 문제였다. 재작성본은 짧은 지시문만 넘기고 diff 는 codex 가 직접 만든다.
